# Prepare a Solr contribution

Locate the current `pr-formula.md` and, for a comment, `comment-formula.md` on the fork's coordination-ui branch. Pin the board revision and read applicable workspace instructions. Current user direction and authorization govern; a stale copied formula does not override them. If the board is unavailable, use [the drafting guide](references/drafting-guide.md) to make a clearly provisional local draft and identify what was not refreshed.

Assemble the actual issue context, outbound diff, implemented behavior, genuine remaining design choice and exact-head receipt. Draft from those facts. Use the repository's existing template and formula; do not infer proof from a green badge or test-file names. If evidence is missing, say so and prepare the required handoff rather than inventing a result.

Keep the concrete problem and resulting behavior prominent, with concise proof and named limits. Only include a choice when there is a live defensible alternative; state context, recommendation and the deciding considerations. A straightforward scope boundary does not need a manufactured question. Keep disclosure and responsibility wording truthful: do not claim Nick reviewed a draft unless he did.

Before offering an existing fix, refresh the PR discussion/head, determine whether it was incorporated and check ancestry of the proposed commands. A merged PR requires a follow-up against current main; commands for the closed contributor branch may be obsolete. Prepare the local draft first. Publish only under current explicit or applicable standing authorization, preserving any draft-review hold, then separately verify stored text and record its URL/head/proof.
