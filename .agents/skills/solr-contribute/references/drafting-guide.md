# Drafting from evidence

Canonical formulas live at `https://github.com/nick-boss-tech/solr/blob/coordination-ui/pr-formula.md` and `comment-formula.md` on the same branch. They evolve; fetch one snapshot and record its SHA. Detailed workspace rules govern disclosure, draft status, headings, collapsible verification and publication. Do not preserve historical authority statements when current user/workspace instructions supersede them.

For a description, express the concrete current symptom, what the patch does, executed proof, a real choice when present, and limits. Scale length to the change. The formula uses level-two Markdown section headings and a bold opening claim per section, with evidence beneath rather than repeated claims. Proof numbers and seeds come from actual receipts/logs; link code at immutable pre-change or tested revisions as appropriate. Retain the current formula's AI disclosure and responsibility statement.

A tested-fix offer leads with the behavior and pinned original-to-tested diff, gives only material proof and limits, and provides verified ordinary fetch/merge commands when the live contributor ancestry supports them. Avoid another offer when the fix was already taken. Optional adjacent improvements are a bounded offer, not an implied demand before an advisory rollout.

Useful draft inputs: issue/PR URL, repository/head/base, observed symptom and trigger, outbound files, behavioral change, proof results and locators, compatibility, actual choices and remaining limits. These are inputs to prose, not a requirement to force a long checklist into every public comment.

The first-level skill does not copy the full evolving formula or edit live PR descriptions automatically. If asked to edit a body, read live text first, prepare the exact local replacement, use the workspace's authorized write path and separately read it back.
