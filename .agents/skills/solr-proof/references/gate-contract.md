# Gate contract

A handoff names ticket/PR, purpose/phase, contributor or main base, fork branch, full verified pushed SHA, outbound files, claiming capabilities, clean checkout requirements and execution host's receipt path. Include deterministic commands, tasks/classes/methods, random seeds where applicable, expected outcomes and fresh evidence requirements. Mention dependencies and known environment conditions only when relevant.

Separate the required positive proof, any original/mutation negative leg, formatting/module/root checks required by the actual job, and final branch identity/cleanliness. Use JUnit XML where generated; stdlib unittest instead needs its full log and explicit counts. No fabricated XML or pass count.

Failure rules distinguish expected negative results from positive failures. Investigate executed failures before retry; record setup interruption and repair separately. Never weaken required checks or silently reinterpret them. An authorized scoped repair is committed and pushed with the correct identity, and its new head receives an add-only superseding record. Receipt authorship belongs to the host that executed the gate.

Receipt assessment records required leg, input SHA, observed outcome, proof locator and any missing piece. A receipt can be accepted only for the head and legs it actually covers. When the PR/main moved, reconcile before offering pull-in instructions or declaring readiness.

The workspace's current AGENTS.md, START-HERE.md and named job govern exact host/tooling requirements. This skill grants no authority to run an unassigned build, alter another contributor's branch, schedule a job or publish a comment.
