## JIRA context
Grant Ingersoll: the 6.5 `ant package` tarball did not contain the Learning To Rank examples (`config.json`, the model
loading python script, ...). The audit note said "ant build, obsolete".

## What the code shows on main
The Ant build is gone but the gap moved to Gradle. `gradle/solr/packaging.gradle` `assemblePackaging` (used for every
`:solr:modules:*` project) copies only `README.md`, the module jar and its runtime libs into the module's packaging
dir, which the root `solr/packaging` assembles under `modules/<name>/`. `solr/modules/ltr/example/` (README, `config.json`,
`exampleFeatures.json`, `libsvm_formatter.py`, `train_and_upload_demo_model.py`, `user_queries.txt`) is never copied, yet
its README tells users to run `cd modules/ltr/example` (a distribution-relative path). The ref guide points to git
instead, which fits the gap. `ltr` is the only module with an `example` directory today.

## Change
`assemblePackaging` also copies an optional `example` directory of the module into `example` of its packaging dir
(`from("example", { into "example" })`; a module without one is unaffected). BATS test in `test_modules.bats` checks the
LTR files are present under `${SOLR_TIP}/modules/ltr/example`.

## Guessed / verify first
- A source directory that does not exist is silently ignored by a Gradle `Sync` `from`; if the build complains, guard it
  with `file("example").exists()`.
- `solr/modules/ltr/example/solrclient` is generated by `copyPythonClientToExample` (README step); it is included only if
  that task already ran. Packaging does not depend on it, which may be wanted or not.
- License/jar checks (`jar-checks.gradle`, `validateSourcePatterns`) were not consulted for new files in the distribution.
- A `liblinear` symlink or other local files under `example/` would be packaged too; check `.gitignore` behaviour.
