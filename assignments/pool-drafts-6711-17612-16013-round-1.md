The branch also passed the changelog parse, tidy, the Error Prone compile and the core module check at the head.
- Choice material (material/replication-backup-round-1-answers.md): persistence is opt-in as implemented (`persist=true` on the request), or persistence could be the default. ## Item 3: SOLR-16013, SolrCloud

Draft file: pr-drafts/solrcloud/SOLR-16013.md. Source: receipts/SOLR-16013.md.

- Branch solr-16013-submit, gated head 966bb4c4eb449853994594b8474ccf24eec59d87. Merge-base 14c7aac0d151402b00259e2fb9bf5eed7049ec5d (the receipt's proof leg uses this commit).
- What the change does, per the receipt. The change description must cover both parts. First, the close-ordering change: ZkController.close() submits the overseer close as one task and waits on it before closing the state reader and the ZooKeeper client, so the overseer finishes closing before the session ends and the election nodes are released. The wait survives interrupts: an interrupted shutdown thread keeps waiting for the overseer close. Second, the interrupt-restore fix at the current head: the remembered interrupt is restored only at the end of the close sequence, after zkStateReader.close(), zkClient.close() and the close thread pool shutdown, so the session-ending closes never run on an interrupted thread, and the caller still gets its interrupt status back when close() returns. The test, OverseerCloseOrderingTest, pins the guarantee with a Mockito overseer whose close blocks on a latch.
- Changelog fragment on the branch: changelog/unreleased/SOLR-16013.yml. Its title as it stands: "Stopping a node now waits for its Overseer to finish before releasing the Overseer leader node, so a newly elected Overseer cannot process the same queue items concurrently."
- Proof, from the receipt only: OverseerCloseOrderingTest passes 2 of 2 at the head in two runs with different method orders (verification runs on 2026-10-12). Without the production change (production at the merge-base, branch test kept), both tests fail, with the two premise messages only: the ZooKeeper client closed before the overseer finished closing, in one test after the shutdown thread was interrupted. The full check at the head (changelog parse, tidy, Error Prone compile, the proof above, the focused tests and the core module check) passed on 2026-10-12. The receipt also records honest history the draft's Proof may state plainly: an earlier head failed this test in a run where the interrupt method ran first (the ordering method found no node running the overseer), the investigation traced that failure to the branch itself, and the interrupt-restore fix at the current head is what settles it.
