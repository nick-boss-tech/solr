## 2. What the change does

Taken from `git diff c3cdf7b46e8 0d5916186797` and the hunks at the tip. **[verified: diff]**

- `solr/core/src/java/org/apache/solr/spelling/SolrSpellChecker.java`: the class now `implements Closeable` (line 49) with a no-op `close()` (lines 83-87).
- `solr/core/src/java/org/apache/solr/spelling/AbstractLuceneSpellChecker.java`: a new `close()` (lines 225-231) closes the Lucene `SpellChecker`, then, in a `finally`, the `index` Directory.
- `solr/core/src/java/org/apache/solr/spelling/IndexBasedSpellChecker.java`: a `sourceDir` field (line 48). `initSourceReader()` (lines 61-77) keeps the `FSDirectory` it opens and, after installing a new reader, closes the previous reader and directory (lines 74-75). A new `close()` (lines 79-87) closes the reader and the directory. The `build` path (lines 90-110) is unchanged.
- `solr/core/src/java/org/apache/solr/handler/component/SpellCheckComponent.java`: at the end of `inform`, inside `if (initParams != null)`, a `CloseHook.postClose` (lines 737-743) calls `IOUtils.closeQuietly` on every checker in `spellCheckers`.
- `changelog/unreleased/SOLR-1877-close-spellcheckers.yml`: type `fixed`, author Nick Shanin, link to SOLR-1877.
- `solr/core/src/test/org/apache/solr/spelling/IndexBasedSpellCheckerTest.java`: `testSourceReaderClosedOnReloadAndClose` (lines 314-349). It asserts reference counts only: the first source reader is 1 after init, is 0 after reload, the new reader is 1, and the second reader is 0 after close.

Behavior change: source readers and their directories are now released on reload and on core close. Before this branch, neither class had a close method on `upstream/main`, so the source reader and the spell index directory were never released **[verified: code]**. The new reload-time close is also what creates the race in section 5, item 1.

Suggester-backed checkers are not affected by the new hook in practice. `Suggester` extends `SolrSpellChecker` (`solr/core/src/java/org/apache/solr/spelling/suggest/Suggester.java:51`) and inherits the no-op close. `SolrSuggester` already closes a `Closeable` lookup in its own `preClose` hook (`suggest/SolrSuggester.java:117-128`). The changelog title says spell checkers are now closed; that is accurate for the Lucene-based checkers only **[verified: code]**.

The test distinguishes the old behavior: the old code never closes the first reader, so the `assertEquals(0, ...)` after reload would fail. It does not exercise the `IOException` catch (`IndexBasedSpellChecker.java:70-73`), and it does not overlap a reload with a read **[verified: diff]**.

Commit `6b356990292` has a doubled subject prefix (`SOLR-1877: SOLR-1877: close spell checkers ...`). Cosmetic; fix at squash.

## 5. Blockers

Line references are at the live tip `0d5916186797`.

1. **Reader race (High; confirmed by reading the code, not run).** `IndexBasedSpellChecker.java:74-75` closes the previous source reader and directory immediately after the new one is installed. Two readers of `this.reader` are not protected:
   - A search request gets the source reader from `determineReader` (`IndexBasedSpellChecker.java:116`), which `AbstractLuceneSpellChecker.getSuggestions` uses at line 136. The same method then calls `reader.docFreq(term)` (`AbstractLuceneSpellChecker.java:151`) and passes the reader to `suggestSimilar` (line 159). A request that took the old reader before the swap would make those calls on a closed reader.
   - `build` reads `this.reader` at `IndexBasedSpellChecker.java:97` and indexes it through `HighFrequencyDictionary` (line 101) and `indexDictionary` (line 109).
   Reload is reached from the `spellcheck.reload` request (`SpellCheckComponent.java:124`) and from the first-searcher listener (`SpellCheckComponent.java:813`). Nothing in the branch serializes these paths or reference-counts the reader. The branch's own handoff named this window in `SOLR-1877-TESTING.md` (at `15f5e04baab`). Before this branch the old reader was never closed, so the race is new.
2. **Gate owed.** No receipt is visible (section 3). The focused proof and the fail-before check are not on record at this tip.
3. **Limit: the source-open IOException path is untested** (lines 70-73, the catch in `initSourceReader`). Name it in any draft.
4. **Changelog wording (nit).** "Spell checkers are now closed when the core closes" reads broader than the code for Suggester-backed checkers (section 2). Name the Lucene-based checkers or leave a Limit.
5. **Commit subject (nit).** `6b356990292` doubled prefix. Reword at squash.
