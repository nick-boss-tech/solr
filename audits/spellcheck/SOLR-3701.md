## 2. What the change does

Taken from `git diff cabedd1d968 aabd678dec7` and the tip. **[verified: diff]**

- `solr/core/src/java/org/apache/solr/spelling/SpellingQueryConverter.java`: `PATTERN` (lines 87-88) gains a repeated suffix, an apostrophe (ASCII or U+2019) followed by letters, after the word body `[\p{L}_\-0-9]+`. A comment on line 86 explains it. An apostrophe, ASCII or U+2019, followed by one or more letters now stays inside the token.
- Old behavior, read from the regex: the first character class `[^^.:(\s]` does not exclude the apostrophe, so an apostrophe can start the next match. `pandora's` therefore splits into `pandora` and `'s`, and the collation rebuilds it as `pandora's's`. That reading fits the output reported in the ticket. **[hypothesis for the tokens; verified against the regex text only]**
- New behavior: `pandora's` is one token. This is the case the test checks.
- `solr/core/src/test/org/apache/solr/spelling/SpellingQueryConverterTest.java`: `testApostropheStaysInWord` (lines 75-87). It converts `pandora's star`, asserts two tokens, checks the first token text and offsets (0 to 9), the second token text, and offset correctness.
- `changelog/unreleased/SOLR-3701-spellcheck-apostrophe.yml`: type `fixed`, author Nick Shanin. Title: "SpellingQueryConverter keeps a word with an apostrophe (pandora's) as one token, so collations no longer come out as pandora's's."

Breadth, which the changelog does not name: the new suffix applies to any letters, apostrophe, letters run, not only to possessive `'s`. Contractions (`don't`) and French elisions (`l'homme`) also become one token under the new pattern. Read from the regex; not tested. This is owner decision 1.
