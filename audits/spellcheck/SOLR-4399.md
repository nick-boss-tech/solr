## 2. What the change does

Taken from `git diff 97d973814336 de6cc6b27ed` and the tip. **[verified: diff]**

- `solr/core/src/java/org/apache/solr/spelling/FileBasedSpellChecker.java`: `init` (lines 61-74) now throws `SolrException` with `SERVER_ERROR` when `sourceLocation` is null (lines 63-71). The message reads: "FileBasedSpellChecker '<name>' requires the 'sourceLocation' parameter naming the dictionary file". The check runs after `super.init`, which sets `sourceLocation` from the `sourceLocation` key (`AbstractLuceneSpellChecker.java:89`; the constant `LOCATION` is at line 53).
- Before this branch, `init` succeeded with no source location. The failure came later, in `build`, as an NPE from `getLines(null)` (`FileBasedSpellChecker.java:115` on the tip; the same call is at line 105 on `upstream/main`).

- `solr/core/src/test/org/apache/solr/spelling/FileBasedSpellCheckerTest.java`: `testMissingSourceLocationIsRejected` (lines 70-81). It builds a checker with a dictionary name `nolocation`, no source location, and a field, calls `init`, and expects a `SolrException` whose message contains "sourceLocation" and "nolocation". It covers init-time rejection only.
- `changelog/unreleased/SOLR-4399-filebased-spellchecker-location.yml`: type `fixed`, author Nick Shanin. Title: "A FileBasedSpellChecker configured without sourceLocation now fails at startup with a message naming the missing parameter instead of throwing a NullPointerException on spellcheck.build."

Behavior change: a `FileBasedSpellChecker` with no `sourceLocation` now fails when the core loads, not when `spellcheck.build` runs. A configuration that has a persisted index and no source file and that never rebuilds would load before this change and fail after it (section 5, item 1).
