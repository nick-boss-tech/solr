## 2. What the change does

**[verified: diff]** **[verified: code]**

- **Shard path (`SpellCheckComponent.java:160-161`).** `extendedResults` becomes `shardRequest || params.getBool(SPELLCHECK_EXTENDED_RESULTS, false)`. A shard now always computes and returns frequency data: `origFreq`, the `{word, freq}` form of each suggestion, and `correctlySpelled` (line 223). Before, a shard sent that data only when the user asked for extended results.
- **Coordinator merge.** `finishStage` collects the shard suggestions and their alternative frequencies (`collectShardSuggestions`, which sums frequencies per suggestion) and passes them to `SolrSpellChecker.mergeSuggestions`. The merge sorts with `new SuggestWordQueue(numSug)` (`SolrSpellChecker.java:118`), the default comparator. It does not read the configured `comparatorClass`. `DirectSolrSpellChecker.mergeSuggestions` (`DirectSolrSpellChecker.java:249-280`) runs its own checks and then calls `super.mergeSuggestions` (line 280), so it also uses the default queue.
- **User-facing output is unchanged in format.** The coordinator still builds its response with `toNamedList(false, result, origQuery, extendedResults)` (line 447), where `extendedResults` is the user's own parameter. Frequency fields and `correctlySpelled` appear only when the user asked for them. What changes is the ranking input when the user did not ask: candidates that tie on score now get a non-zero frequency to sort on.
- **Tests.** Two added queries in the existing `test()` (lines 160-169) compare control with distributed output without extended results. A new `testShardMergeRanksTiesByFrequency` (lines 417-457) indexes four terms at edit distance 1 from `zxrnt` with document counts 2, 5, 8, 11 (`zarnt`, `zernt`, `zirnt`, `zornt`), builds the IndexBased and Direct dictionaries, and compares distributed with control. The query does not request extended results and uses the default dictionary. All candidates have equal score, so only frequency can order them.
- **Side effect.** Every distributed spellcheck request now asks each shard for frequency data, whether or not the user asked. The cost is not measured here.
- **Changelog** (`type: fixed`, author Nick Shanin): says merged results are ranked by frequency when extended results are not requested. See blocker 2.
