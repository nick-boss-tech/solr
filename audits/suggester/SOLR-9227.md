## 1. What the change does

When a suggester has a `storeDir`, `SolrSuggester.build` stores the lookup after building it. The base code called `lookup.store(...)` and, on a false return, logged `Store Lookup build failed` at ERROR with no suggester name. The branch changes that block (tip `SolrSuggester.java:183-199`):

- An `IOException` from the store call is rethrown as a new `IOException` whose message names the suggester and the absolute store-file path, with the original kept as the cause (lines 186-191).
- A false return logs a WARN that names the suggester, the lookup class, and the target path, and says the lookup "may persist elsewhere, e.g. in its own index" (lines 192-199).
- The `lookup.build` call before it (lines 172-181) is unchanged, so build failures propagate as before. **[verified: code]**

The changelog fragment (type `changed`) says the suggester and store file are now named, and that the context-free error is gone for lookups that persist themselves.

Test: `testLookupThatDoesNotStoreIsLoggedWithSuggesterName` (test file lines 111-130). It builds `suggest_blended_infix_suggester`, asserts that `SolrSuggester` logged no ERROR, and asserts one WARN containing the suggester name. It distinguishes the old behavior (the old ERROR would fail the `assertNull`). It does not exercise the `IOException` branch. **[verified: diff]**
