## 1. What the change does

Adds an opt-in suggester option that chooses the tokenizer for `suggest.cfq` context filter queries. Before, `SolrSuggester.init` hard-wired `StandardTokenizerFactory`, so a context value such as `c#x` was split into `c` and `x` at query time and matched the wrong contexts.

- The option is `contextFilterQueryTokenizer`. The default is `standard`, kept as a constant (`SolrSuggester.java:82-84`). Existing configurations keep the old tokenizer.
- Init reads the option and calls `TokenizerFactory.forName(name, new HashMap<>())` (lines 119-127). An unknown name fails at core init. The factory is created with no arguments, as the ref guide says.
- A context filter parse failure now throws `IllegalArgumentException("Failed to parse context filter query: " + contextFilter, e)` with the cause kept (lines 283-285). The old message dropped the cause.
- Fixture: suggester `suggest_blended_infix_keyword_cfq` with `keyword`, in the XML at lines 64-79.
- Fixture rows: test lines 107-130 add docs id 10 (cat `special context entry`, context `c#x`) and id 11 (cat `special plain entry`, context `c`).
- Tests: `testContextFilterWithSpecialCharactersAndKeywordTokenizer` (136-153), `testBadContextFilterQueryTokenizerFailsAtInit` (155-172), `testUnparseableContextFilterQueryReportsQueryAndCause` (174-194).
- Documentation: `suggester.adoc` lines 933-943, describing the option and its limits.

Not in the review, and found in this audit:

- **Overstated doc claim.** The ref guide (lines 934-937) and the changelog say `keyword` "keeps the whole filter value as a single term" and lets "context values containing special characters match exactly". The code does not do that. `parseContextFilterQuery` passes the whole string to `StandardQueryParser` (lines 277-278) before the analyzer sees it. The parser splits on whitespace and reads Lucene query syntax first. So `ctx 1` still becomes two terms, and a value with `:` is read as a field query. The keyword tokenizer keeps each parser term whole. `c#x` works because `#` is not query syntax. **[verified: code]**, the parser behavior from reading; not run.
- **SPI resolution.** `TokenizerFactory.forName` resolves names through Lucene's SPI, not through the core's resource loader (line 122). Whether a tokenizer shipped in a core `lib/` directory resolves was not checked.
