On current main, DocBasedVersionConstraintsProcessorFactory still requires the version field to be stored, so a long field that has docValues and useDocValuesAsStored, but is not stored, is rejected at startup. The single check that does this is in that processor, and we did not find the same check anywhere else. We have not yet tested whether the processor reads such a field correctly, so a fix would come with a test that covers it. We are leaving this open until that is done.
