On current main, SolrJ builds query parameters with the form encoding of URLEncoder: a space becomes "+" and a literal "+" becomes "%2B". We could not reproduce a space sent as "%20". Your example, a local-params query with a leading "+", is encoded as "%2B" and is decoded by the server as a plus sign. If you still see a failure with a current release, please attach the request as SolrJ sends it and the server response.
