We re-read this ticket against the Solr source at fork commit 498a09aea97. The leader's processGetVersions still reads the fingerprint and the recent versions in two steps without a shared snapshot, so the window the ticket describes is present. PeerSync bounds its own fingerprint comparison to the leader's max version, which reduces the effect but does not make the two reads atomic. We have not run a reproduction, and the fix is a design choice, so this ticket stays open.
