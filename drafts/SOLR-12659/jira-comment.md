We checked this ticket against the current code. The HttpClient-based createMethod named here has been removed from main, but the same behavior remains in the current JDK-based client: when a stream is attached, the request body is the stream and every other parameter is still placed on the URL, so long parameter sets can exceed the URL limit. The clean fix (sending the parameters in the body with the stream) needs multipart or a request-format change, which is a design decision, so we are leaving the ticket open for it.
