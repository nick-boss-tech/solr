We checked this ticket against the current code. A corrupt index on a running replica does not change the replica's published state to Down, and nothing triggers recovery from it; the map that was meant to record tragic replica events is never filled. Whether a corrupt checksum should mark the replica Down, and which errors should count, is a design decision for the maintainers, so we are leaving the ticket open. A run that corrupts a replica's segment and records the cluster status and write results at the current head would confirm the behavior.
