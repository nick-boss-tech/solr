We checked this ticket against the current code. When a response writer fails part way through, the javabin writer has already written part of the stream to the response, and the error is then sent as a new response. Whether a Java client reads that as a corrupt result or as an error is not settled, and the ticket's design question (a restart marker or a fail-fast marshal) is still open. We have not reproduced the bad read on the current code, so we are leaving the ticket open.
