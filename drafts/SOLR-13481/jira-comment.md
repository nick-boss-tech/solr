We checked this ticket against the current code. The class LBHttpSolrClient was replaced by LBSolrClient and LBJettySolrClient, and those still try the next live server when a request fails with a connection, timeout, or retryable HTTP error. A failure that is not classified as retryable, such as an unexpected runtime exception, still ends the attempt instead of trying another server. We have not reproduced that case on the current code, so we are leaving the ticket open.
