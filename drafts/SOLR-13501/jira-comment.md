We checked this ticket against the current code. The class ConcurrentUpdateHttp2SolrClient is no longer in the Java code: it was renamed to ConcurrentUpdateBaseSolrClient, with ConcurrentUpdateJettySolrClient as its implementation (SOLR-18005). The update path still uses this concurrent client, and the distributed update processor does not use the Http2 client directly. Whether the rename is enough, or the update path should drop the concurrent client as this ticket proposes, has not been decided, and the 2019 comments ask for benchmarks first. We are leaving the ticket open for that decision.
