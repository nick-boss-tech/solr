This is fixed on current main. A delete by id that carries routing information is now forwarded from the leader to replicas with its version, so the replica no longer drops the version and goes into recovery for that reason. The change is in the 2021 commit for SOLR-8889, which fixed deleteById with routing information. We are closing this ticket as fixed. If you still see replicas go into recovery after a routed delete on a current build, please open a new ticket with the log.
