We reviewed this ticket against the current code. When a schema update is handled by one node, that node reloads the core before it returns. Other nodes in the cluster reload when they see the change through ZooKeeper, so a request sent to one of them just after the update can still use the old schema for a short time. We have not yet run that sequence on a current build. We are leaving the ticket open for that run and for a decision on whether the update should wait for the other nodes. A useful next step is the number of nodes, the update request, and the first query that returned the old schema.
