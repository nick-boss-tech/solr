We reviewed this ticket against the current code. The Solr security listener still adds its internode headers to any outgoing request from a client created by the same provider or handler, unless the authentication plugin says it handled that request. The ticket's case (an audit client sending to an external Solr with Kerberos) is still possible on current main. A fix needs a decision on how the interceptors are registered: per client, or with a rule for destinations outside the cluster. We are leaving the ticket open for that decision. Meanwhile, a client built with a dedicated HTTP client avoids the headers.
