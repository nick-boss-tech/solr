We reviewed this ticket against the current code. In current Solr, the _root_ field is populated for every document when the schema defines it, so updates and deletes by id look at _root_ when the schema allows it. Documents indexed before that change do not carry a _root_ value, so an update does not replace them. Re-indexing the documents after the upgrade is the reliable way to clear the duplicates. We are leaving the ticket open for a decision on whether Solr should add a fallback lookup on the id field for older documents.
