On current main a delete-by-query runs its query while holding the update lock in the direct update handler, so an index change can wait behind it. Whether the wait comes from that lock or from the Lucene merge it waits on is still open, and it is tracked in LUCENE-7049. We have not timed a delete-by-query against a delete-by-id during a large optimize on current main, so we are keeping this issue open until that run is done. If you have current timings, please attach them.
