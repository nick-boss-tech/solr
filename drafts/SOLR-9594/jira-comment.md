On current main, a one-shard query that lands on an inactive replica is not short-circuited to the local core, so that node becomes the aggregator for a distributed search. The short-circuit check in the shard handler requires the local replica to be active. The fix version on this issue does not match a change in the code we can find, so we are keeping this open. The open question is whether such a request should be forwarded to an active replica or sent with distrib=false. Please say which you prefer.
