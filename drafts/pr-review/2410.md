## Proposed comments

1. Rebase needed. The files this PR changes are gone from apache/main at `c8ab71430f`: `solr/solrj/src/java/org/apache/solr/client/solrj/impl/Http2SolrClient.java` and `HttpSolrClientBuilderBase.java` no longer exist, and a read-only three-way merge conflicts on both. The HTTP/2 client now lives in `solr/solrj-jetty/src/java/org/apache/solr/client/solrj/jetty/HttpJettySolrClient.java`. The same behavior is at lines 279 and 289 there (`setMaxConnectionsPerDestination(builder.getMaxConnectionsPerHost())` and a hardcoded `setMaxConnectionsPerDestination(4)`). Could the change be re-based onto that class?
2. Which limit is the divisor? The new code divides by `http2client.getMaxConcurrentPushedStreams()`. In the Jetty HTTP/2 client that is the limit on server-pushed streams. Requests a client sends are governed by `getMaxLocalStreams()`. Please confirm which one was meant, and say in the PR body which value the division assumes. The result differs for some builder values (for example, a per-host value of 64 gives 2 connections with the pushed-stream limit and 1 with the local-stream limit, given the defaults of 32 and 1024 that are assumed here and not verified).
3. Default behavior change. When the builder does not set `maxConnectionsPerHost`, HTTP/2 used to be capped at 4 connections per destination. This PR removes that cap, so the default becomes the Jetty default. The CHANGES entry says so, but this is a user-visible change for upgrades. Could the upgrade note be stated explicitly, and could a maintainer confirm it is intended?
4. Tests. The PR adds no test. A test should assert the per-destination limit for both transports (HTTP/1.1 and HTTP/2) with a set value and with the default, so the divisor in comment 2 is pinned.
