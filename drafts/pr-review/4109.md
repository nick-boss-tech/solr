# PR review draft: apache/solr #4109 (SOLR-18101)

Status: PROPOSED. Nothing is posted. Reviewer host: vm4. Head branch `SOLR-18101-SolrjCommitApi` (dsmiley/solr), PR base as in the snapshot. Outcome: NEEDS-CHANGES (tests for the new public API).

## Summary of the change

Adds a fluent commit API to SolrJ update requests (`commit()`, `softCommit()`, `commitWithin(int, TimeUnit)`, `commitFlushOnly()`, `commitAsync()`) on `AbstractUpdateRequest`, with Javadoc on each. It marks the `UpdateRequest.add(doc, overwrite)` and `add(doc, commitWithin, overwrite)` overloads `@Deprecated` in favor of setting `overwrite` once per request. It moves the `ACTION` enum within `AbstractUpdateRequest` (it is not removed) and adds a Javadoc block on the delete methods.

## Proposed comments

1. Tests. The PR changes only `AbstractUpdateRequest.java` and `UpdateRequest.java` and adds no tests. The fluent methods set `UpdateParams` values (`commit`, `softCommit`, `openSearcher`, `waitSearcher`, `commitWithin`), and each combination should be pinned, for example that `commitAsync()` sets `waitSearcher=false` and that `commitWithin(1, SECONDS)` sends 1000. A test on `UpdateRequest` parameters would be enough.
2. The `ACTION` enum moved. The patch shows the enum removed from the top of the file and re-added further down. That is a move, not a removal, so existing callers (`setAction(ACTION...)` at `RecoveryStrategy`, `CollectionHandlingUtils`, `SolrCmdDistributor`, and tests) still compile. Could the PR body say that explicitly, so a reviewer does not have to check it?
3. Formatting. The patch has two blank lines in a row after `commitAsync()`. Spotless should flag this, so please run `spotlessApply`.
4. Deprecations. The new `@Deprecated` tags on the `add` overloads state the replacement in Javadoc. The `TODO eliminate overwrite` comment is fine as a note, but a `@Deprecated(since = ...)` would match the other deprecations in this codebase.
5. Scope. The PR adds several public methods in one change. It may help to list them in the PR body with the param each one sets, so that the review can check the list against the code.
6. Rebase. The PR base is older than current main. Check the `UpdateRequest` changes after a rebase.
