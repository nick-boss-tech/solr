# PR review draft: apache/solr #4324 (SOLR-18207)

Status: PROPOSED. Nothing is posted. Reviewer host: vm4. Head branch `SOLR-18207_avoid_duplicate_vector_storage` (iamsanjay/solr), PR base as in the snapshot. Outcome: NEEDS-CHANGES (round-trip and interaction tests for the document fetch path).

## Summary of the change

Adds an option `useVectorValuesAsStored` to `DenseVectorField`, so a dense vector field can be returned from the KNN vector values in the index instead of a second stored copy. It changes `SolrDocumentFetcher` (+136/-5) to read the vector from the KNN values when the option is on. It adds a schema file `schema-densevector-derived-stored.xml` (+54), a bad-schema file for multivalued use (+22), tests in `DenseVectorFieldTest` (+69), and a reference-guide section (+19).

## Proposed comments

1. Round-trip for both encodings. The returned values must equal the indexed input. Please add a test for `vectorEncoding` `FLOAT32` and `BYTE` that indexes a vector, fetches it by id with the option on, and checks the values are exactly the input. For `BYTE`, the derived value must come back as the same signed bytes, not as floats.
2. Interaction with `stored`. If a field sets both `stored=true` and `useVectorValuesAsStored=true`, the PR should say which one is used, and the schema check should reject or define the combination. Could a test pin the choice?
3. Hot path. `SolrDocumentFetcher` is used on every document fetch in Solr, so a change there affects all fields, not only dense vectors. The PR should show that a document with no dense vector field is fetched the same way as before (the existing fetch tests cover this, but the PR should name them).
4. Deleted and missing docs. The KNN values are per segment. A test with a deleted document, and with a document that has no vector value, should check that the fetch returns no field instead of an error.
5. Multivalued. The bad-schema file covers the multivalued case. Please confirm that the reference-guide text says the option is for single-valued fields only.
6. Reference guide. The added section says what the option saves in storage; it would help to say what it costs at fetch time, since the value is read from the vector index.
