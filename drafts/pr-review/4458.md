# PR review draft: apache/solr #4458 (SOLR-18251)

Status: PROPOSED. Nothing is posted. Reviewer host: vm4. Head branch `docvalues-skip-list` (iamsanjay/solr), PR base as in the snapshot. Outcome: READY-WITH-NOTES.

## Summary of the change

Adds a `skipList` schema property for numeric and point fields. When it is set, the field is written with a Lucene DocValues skip index: `FieldProperties` gets the bit `DOC_VALUES_SKIP_LIST` (bit 20, after `UNINVERTIBLE` at bit 19) and the name `skipList`, `SchemaField.hasDocValuesSkipList()` reads it, and `docValuesSkipIndexType()` (a stub returning `NONE` at base) now returns the skip index type. `FieldType.checkSchemaField` rejects `skipList` without `docValues`, or on a type other than numeric or sorted numeric. `PointField.createFields` uses `NumericDocValuesField.indexedField(...)` when the skip list is on. Tests: `TestSchemaField`, `TestCodecSupport`, `TestFieldResource`, `BadIndexSchemaTest` with a new bad schema file.

## Proposed comments

1. Bit alignment is correct. `propertyNames` has 20 entries at base, which map to bits 0 to 19, and the PR adds `skipList` as the 21st entry, which maps to bit 20 (`0b100000000000000000000`). Please keep the two lists in step in any later change; a reader might not see the link.
2. Schema API output changes for every field. `getNamedPropertyValues` now adds `skipList` to every field's property map, so `/schema` responses gain a `skipList: false` entry on all fields. `TestFieldResource` changed for this. Is that the intended API output? If it is, the changelog should say so, because clients that compare full property maps will see new keys.
3. Codec support. `NumericDocValuesField.indexedField` needs the Lucene codec to support the skip index. The PR tests cover `schema_codec.xml` and `schema_postingsformat.xml`. Could the PR say which default codec supports the skip index, and what happens on an index written with `skipList` and read by an older codec, so an upgrade does not fail at read time?
4. Error code. `checkSchemaField` throws `ErrorCode.SERVER_ERROR` for an invalid `skipList` combination. Schema validation errors are usually client input problems; `BAD_REQUEST` may be the better code, if other schema checks in the file use it. Please check the neighbouring checks in `FieldType` and match them.
5. Documentation. The new schema property needs a line in the schema documentation (the field properties list) and the changelog should name it. Neither is in the diff.
6. Stub replacement. `SchemaField.docValuesSkipIndexType()` returned `NONE` at base. The PR changes it to return the real type. A reviewer should confirm no other caller depended on the stub.
