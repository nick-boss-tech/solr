# PR review draft: apache/solr #4475

Status: PROPOSED. Nothing is posted. Reviewer host: vm4. Head branch `handling_empty_queries_in_FiltersQParser` (renatoh/solr), PR base `c851aae5c8`. Outcome: NEEDS-CHANGES.

## Summary of the change

Makes an empty query clause (for example a stopword) count toward the minimum-should-match calculation when `mm.autoRelax` is false. It adds a `createFieldQuery` override in `SolrQueryParserBase` that returns `MatchNoDocsQuery` where the analyzer produces nothing, changes `SolrPluginUtils.setMinShouldMatch` to skip those clauses under autoRelax, and changes `BoolQParserPlugin` to read `mm` and `mm.autoRelax` from local params only. `FiltersQParser` gets a small local-variable refactor. Tests: `TestMmBoolQParserPlugin` (+35), `SolrPluginUtilsTest` (+107/-77), and a field in the test schema.

## Proposed comments

1. Request-level `mm` is no longer read by `!bool`. `BoolQParserPlugin` previously used `SolrParams.wrapDefaults(localParams, params)` and `params.getBool(MM_AUTORELAX)`. The PR uses only `localParams`, so `mm` or `mm.autoRelax` set as request parameters stop applying to `{!bool}`. Is that intended? If it is, the PR body should say so and a test should pin it. If not, the wrap should stay.
2. Broad effect of the `createFieldQuery` override. `SolrQueryParserBase` is the base for every Solr query parser that uses the Lucene parser, not just `!bool`. An empty analysis result now becomes `MatchNoDocsQuery` instead of `null` for all of them. Could the PR show which parsers change (for example lucene, edismax, and the join parsers) and add a test for at least one of them with a stopword?
3. `setMinShouldMatch` semantics. Skipping `MatchNoDocsQuery` clauses only under `mmAutoRelax` changes the count for every caller of `SolrPluginUtils.setMinShouldMatch`. The `mm` documentation should say how an empty clause is counted in each mode, and the PR should point to it.
4. `SolrPluginUtilsTest` rewrites 107 lines and removes 77. A reviewer needs to see that each old assertion still holds, or that the change is intended. A list of the changed assertions with the reason for each would help.
5. `FiltersQParser` is a refactor with no behavior change (a local variable is extracted). It could go in its own commit so the logic review is not mixed with it.
6. Rebase. The PR base `c851aae5c8` is older than current main at `c8ab71430f`, and the `BoolQParserPlugin` lines the PR shows as "before" do not match the current file. A rebase is needed before this is checked against the current code.
