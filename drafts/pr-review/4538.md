# PR review draft: apache/solr #4538 (SOLR-17559)

Status: PROPOSED. Nothing is posted. Reviewer host: vm4. Head branch `SOLR-17559` (dsmiley/solr), PR base `28ac2a5744`. Outcome: NEEDS-CHANGES.

## Summary of the change

Makes the SolrJ cluster model class `DocCollection` more immutable: it renames the slice maps to `slicesByName` and `activeSlicesByName`, adds a cached `activeSlices` collection, makes `replicaMap` final and built up front, and annotates the class `@Immutable` (jcip). The PR also edits `.github/labeler.yml`.

## Proposed comments

1. Unrelated edit. `.github/labeler.yml` changes the docs and cloud labeling globs (`help/**`, `README.md` removal, `**/org/apache/**/cloud/**`). Nothing in SOLR-17559 needs that. Could it go in its own PR, or be removed from this one?
2. `@Immutable` needs a check. The class still has a non-final `perReplicaStatesRef` (`AtomicReference`) field in the base version, and the PR does not show whether that changed. An `@Immutable` class should have only final state, or the annotation overstates the guarantee. Could the PR say how the lazy `perReplicaStatesRef` is handled, or drop the annotation for this class?
3. Public surface. The patch adds `public Map<String, Object> getProperties()` to `DocCollection`. It may be a move from another class, but it looks new in this diff. Could the PR body say whether it is a new public method, and if so why it is needed for immutability?
4. Tests. No tests are added or changed. `DocCollection` is central to cloud state, so a refactor like this needs the existing SolrJ cloud and collection tests to run. A focused gate would be the `DocCollection`-related tests in `solr/solrj` and the cloud tests in `solr/core` that read collection state, on the rebased branch.
5. Rebase. The PR base `28ac2a5744` is older than current main. `net.jcip` is a `compileOnly` dependency of `solr/solrj` at apache/main `c8ab71430f`, so the annotation compiles there. A rebase is still needed to check `DocCollection` against any changes since the base.
6. Changelog. The PR says it is not changelog-worthy. That fits an internal refactor, so no entry is needed unless the public `getProperties` addition is user-visible.
