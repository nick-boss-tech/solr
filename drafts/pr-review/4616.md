# PR review draft: apache/solr #4616 (SOLR-17841)

Status: PROPOSED. Nothing is posted. Reviewer host: vm4. Head branch `multi-threaded-search-performance` (arup-chauhan/solr), PR base as in the snapshot. Outcome: READY-WITH-NOTES.

## Summary of the change

Adds a `multiThreaded` JMH parameter to the existing `ExitableDirectoryReaderSearch` benchmark (`false` by default, `true` as an option), and sets `CommonParams.MULTI_THREADED` on the request params when it is on. One file, +20/-3.

## Proposed comments

1. Import order. `org.apache.solr.common.params.CommonParams` is added between the `client.solrj.request` imports, so the list is out of order. Spotless will reorder it; please run `spotlessApply`.
2. The parameter is defined. `CommonParams.MULTI_THREADED = "multiThreaded"` exists at base (`solr/solrj/src/java/org/apache/solr/common/params/CommonParams.java` line 160), so the benchmark compiles against current main.
3. Benchmark run. A benchmark change should show that it runs and that both values produce a result. A short JMH run with each `multiThreaded` value, and the output lines, would show that. The PR says it is for baseline comparison, so it would also help to put the numbers from one run in the PR body, labeled with the machine.
4. Default. The `@Param` default is `false` and the value list is `{"false","true"}`, so both values run by default. If the intent is only to compare, the PR could say which value the baseline uses.
5. Scope. This only changes the benchmark module, so it does not affect shipped code or the test suites.
