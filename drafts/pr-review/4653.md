# PR review draft: apache/solr #4653 (SOLR-18315)

Status: PROPOSED. Nothing is posted. Reviewer host: vm4. Head branch `solr-18315-utf-conversion` (psalagnac/solr), PR base as in the snapshot. Outcome: NEEDS-CHANGES (wire compatibility proof, public API removals, benchmark numbers).

## Summary of the change

Replaces the custom UTF-16 to UTF-8 conversion (`ByteUtils`, 230 lines, removed) with the standard Java charset APIs. `ByteArrayUtf8CharSequence` now stores the string and encodes it with `getBytes(UTF_8)`, `JavaBinCodec` uses a `CharsetEncoder`, and `Utils.toUTF8(CharArr)` uses `UTF_8.encode`. It also drops the `noggit` `CharArr` use in those classes, removes the `stringProvider` field, and changes the benchmark `RequestWriters` parameter from `binary` to `javabin`. The PR is 8 files, +105/-313.

## Proposed comments

1. Wire compatibility needs a proof. The JavaBin codec writes these bytes to other Solr nodes and clients, so the new encoder must produce the same bytes as the old one for every string. The Java charset encoder and the old custom routine differ on unpaired surrogates (the standard encoder substitutes a replacement byte, the old routine may not). Could the PR add a test that encodes many random Unicode strings, including lone high and low surrogates and supplementary characters, with the old and the new code, and asserts equal bytes? Without it, a rolling upgrade could change what older nodes read.
2. Public API removals. `ByteUtils` is a public class in `org.apache.solr.common.util` in SolrJ, and the public field `ByteArrayUtf8CharSequence.stringProvider` is removed. Both are breaking for code outside Solr. The changelog should use `type: removed` and name them, or the removal should be deprecated first.
3. Benchmark numbers. The title is an optimization. Please put before and after JMH numbers in the PR body (same machine, same benchmark, the `RequestWriters` benchmark with both `xml` and `javabin`), since a change to the wire encoder should show a measured gain, not only a cleaner call.
4. Memory. `ByteArrayUtf8CharSequence` now holds both the `String` and the byte array, and the constructor allocates the bytes eagerly. A reviewer should check the memory effect on large response batches, since this class is used for every field value.
5. Test scope. `TestJavaBinCodec` and `TestJavaBinResponseWriter` change. Could the PR name the cases they now cover (surrogates, empty strings, very long strings), so the review can check that they are the ones that matter for the wire format?
6. Changelog type. `type: other` does not fit a change that removes public classes; see comment 2.
7. Rebase. The PR base is older than current main. Check `JavaBinCodec` and `Utils` after a rebase, since both are busy files.
