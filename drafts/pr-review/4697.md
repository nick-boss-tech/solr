# PR review draft: apache/solr #4697 (SOLR-18330)

Status: PROPOSED. Nothing is posted. Reviewer host: vm4. Head branch `SOLR-18330-TLOG-RTG-shortCircuit` (dsmiley/solr), PR base as in the snapshot. Outcome: READY-WITH-NOTES.

## Summary of the change

Lets a real-time get (RTG) request that lands on a TLOG shard leader be answered locally, without an extra HTTP hop. It renames the replica filter from "NRT only" to "RTG capable" (`onlyNrt` becomes `onlyRtg` in `CloudReplicaSource`, and `HttpShardHandler.ONLY_NRT_REPLICAS` becomes `ONLY_RTG_REPLICAS`, with the same string value `distribOnlyRealtime`). It adds a trace test with a single-shard TLOG collection and a span JSON file, and a changelog entry (`type: changed`).

## Proposed comments

1. Filter logic. The old rule kept NRT replicas, plus TLOG replicas that are the shard leader. The new rule is `NRT || isShardLeader`, so any shard leader passes. PULL replicas cannot become leaders in SolrCloud, so the result should be the same, but the PR body should say so, or keep the explicit `Replica.Type.TLOG` check so the filter reads the same as before.
2. Public constant rename. `HttpShardHandler.ONLY_NRT_REPLICAS` is a public constant in `solr/core`. Renaming it breaks any plugin code that refers to the old name, even though the string value is unchanged. Could the old name be kept as a deprecated alias for one release, or the rename noted in the changelog?
3. Trace test. `TestDistributedTracing` gets a new case that checks the expected span JSON for `/get` on the TLOG collection. Could the test also assert that no outbound HTTP span is created for the local hop, so the optimization itself is checked and not only the span list?
4. Javadoc. The new `onlyRtg` Builder method has a one-line Javadoc, which is good. The `HttpShardHandler` Javadoc now says "replicas that serve the latest data", which is clearer than the old text.
5. Changelog. `type: changed` fits. The title starts with "Optimization:", which reads oddly next to the other entries; a plain description of the behavior would do.
