# PR review draft: apache/solr #4874 (SOLR-18417)

Status: PROPOSED. Nothing is posted. Reviewer host: vm4. Head branch `SOLR-18417-remove-prh-code-2` (gerlowskija/solr), PR base as in the snapshot. Outcome: NEEDS-OWNER (a removal that breaks public SolrJ API and solr.PingRequestHandler configs).

## Summary of the change

Removes `PingRequestHandler` and the code around it: the server class and its tests, the `SolrPing` and `SolrPingResponse` SolrJ classes, the `ping` methods on `SolrClient`, several `CommonParams` constants, the `/admin/ping` entries in the implicit handler list and in test `solrconfig` files, the admin UI's ping pieces, and the reference-guide page `ping.adoc` with its example test. It adds a changelog entry (`SOLR-18417-remove-pingrequesthandler.yml`, 7 lines).

## Proposed comments

1. Owner decision on the removal. This takes out public SolrJ types (`SolrPing`, `SolrPingResponse`) and `SolrClient.ping(...)` methods, and the `solr.PingRequestHandler` class that user `solrconfig.xml` files may name. Those are breaking changes. The base already deprecates the two `SolrClient.ping` overloads with `@Deprecated(since = "10.1")`, so the removal is a planned major-version change. Can the owner confirm the target release, and whether the removal should wait for it?
2. Upgrade path. A user `solrconfig.xml` that still names `class="solr.PingRequestHandler"` will fail at core load after this change. The changelog and the upgrade notes should say which handler replaces it (the ping information now comes from the metrics and health APIs, if that is the intent) and how to remove the old entry.
3. Changelog type. A removal of public API should be `type: removed`, and the entry should name the removed classes, not only the title.
4. `CommonParams` constants. The diff removes about 22 lines from the public `CommonParams` interface. Please list the removed constant names and check that none is used by a SolrJ user outside Solr (the common param names are part of the SolrJ surface).
5. Reference guide. The `ping.adoc` page is removed and `implicit-requesthandlers.adoc` loses 13 lines. The links from other pages (`deployment-nav.adoc`, `v2-api.adoc`, `requesthandlers-searchcomponents.adoc`) are edited; a build of the ref guide should be run to catch any broken xref. That build is not available on this host.
6. Admin UI. The change touches `app.js`, `core-overview.js`, `services.js` and `core_overview.html`. The admin UI tests (`AdminUiSmokeTest` and the screen tests) are changed. A smoke run of the core overview screen would show that nothing else depended on the ping card.
7. Mechanical checks. The PR removes `ImplicitPlugins.json` ping entries and `solrconfig` entries in several test configs. Those should be checked by a full core test run, because implicit handler loading is shared by every test.
