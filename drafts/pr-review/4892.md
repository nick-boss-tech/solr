# PR review draft: apache/solr #4892 (SOLR-17864)

Status: PROPOSED. Nothing is posted. Reviewer host: vm4. Head branch `SOLR-17864_part_dieciocho` (epugh/solr), PR base as in the snapshot. Outcome: READY-WITH-NOTES (naming of one property; changelog wording).

## Summary of the change

Renames system properties to consistent names and maps the old names to the new ones. Tracing properties move to `solr.tracing.host.name` and `solr.tracing.always.on.header`. The auto-recovery skip flag `solrcloud.skip.autorecovery` moves to `test.solr.cloud.replica.autorecovery.skip.enabled`, and is read through `EnvUtils.getPropertyAsBool` in `SyncStrategy`, `ZkController` and `DefaultSolrCoreState`. `DeprecatedSystemPropertyMappings.properties` gets the new=old pairs. The reference guide (`solr-properties.adoc`, the security and auth pages, `configuring-solr-xml.adoc`) and seven test files are updated. A changelog entry is included.

## Proposed comments

1. A production flag under a `test.` prefix. `ZkController`, `DefaultSolrCoreState` and `SyncStrategy` use the auto-recovery skip flag at run time, not only in tests. The `test.` prefix tells operators that the flag is for tests, which it is not. Could it use a `solr.` name (for example `solr.cloud.replica.autorecovery.skip.enabled`), with the mapping from the old name kept?
2. Mapping direction. The mapping file is `new=old`, which matches the table in `solr-properties.adoc`. The two new tracing mappings and the autorecovery mapping follow that pattern, so this is correct. A reviewer should still check that `EnvUtils` applies the mapping in each of the three read sites.
3. Behaviour change. Reading through `EnvUtils.getPropertyAsBool` also honours the matching environment variable, which `Boolean.getBoolean` did not. That is a new way to set the flag. The changelog should say so, or the PR should note that the env form is intended.
4. Undocumented flag. `solrcloud.skip.autorecovery` is not in the reference guide at base (only in code). The new name is documented in `solr-properties.adoc` only through the mapping table in some places. Could the reference guide entry say what the flag does, and that it is for debugging recovery?
5. Changelog. The title and the changelog say "tracing property names", but the PR also renames the auto-recovery flag. The changelog should list both renames and their replacements, so an operator with the old name can find the new one.
6. Test files. Seven test files switch to the new names. A quick check that each test that used the old flag still sets the new one (for example `ZkSubcommandsTest` and the ZK ACL provider tests) would confirm the rename did not silently disable the flag in a test.
