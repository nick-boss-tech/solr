## What happens today

**A glob cannot take a raw value transformer, so `fl=*_json:[json]` returns a 400 error.**

A request such as `fl=*_json:[json]` or `fl=su*:[json]` fails with a 400 "fieldname parse error". The parser accepts a glob only when a space, a comma or the end of the string follows it ([SolrReturnFields.java lines 307-316 at the merge-base](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/search/SolrReturnFields.java#L307-L316)). It then gives up on the glob ([lines 332-333 at the merge-base](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/search/SolrReturnFields.java#L332-L333)).

## What this change does

**A glob followed by a raw value transformer now writes each matching field raw.**

- `fl=*_json:[json]` and `fl=su*:[json]` are accepted. Each returned field whose name matches is written raw, under its own name ([SolrReturnFields.java lines 318-347 at the head](https://github.com/nick-boss-tech/solr/blob/85a8d32339394fa58a1f56969cd0e4f1db00fbb8/solr/core/src/java/org/apache/solr/search/SolrReturnFields.java#L318-L347)).
- The response writer checks the marker against each field as it is written ([TextResponseWriter.java lines 122-133](https://github.com/nick-boss-tech/solr/blob/85a8d32339394fa58a1f56969cd0e4f1db00fbb8/solr/core/src/java/org/apache/solr/response/TextResponseWriter.java#L122-L133)). Only the JSON and XML writers do this ([JSONWriter.java line 110](https://github.com/nick-boss-tech/solr/blob/85a8d32339394fa58a1f56969cd0e4f1db00fbb8/solr/core/src/java/org/apache/solr/response/JSONWriter.java#L110), [XMLWriter.java line 192](https://github.com/nick-boss-tech/solr/blob/85a8d32339394fa58a1f56969cd0e4f1db00fbb8/solr/core/src/java/org/apache/solr/response/XMLWriter.java#L192)). Other writers ignore it, as they already ignore `[json]` and `[xml]`.
- A glob combined with another transformer, such as `su*:[docid]`, still returns a 400 ([lines 333-340](https://github.com/nick-boss-tech/solr/blob/85a8d32339394fa58a1f56969cd0e4f1db00fbb8/solr/core/src/java/org/apache/solr/search/SolrReturnFields.java#L333-L340)).

## A choice to check

**A bare `*` is rejected, so `fl=*:[json]` returns a 400.**

A raw transformer on every field would write each stored string field unquoted. A field that is not JSON, such as the XML values in the test index, would make the whole response invalid JSON. Only named globs such as `*_json` or `su*` are accepted. Was rejecting the bare form the right call?

## Proof

- `TestRawTransformer.testGlobJsonTransformer` ([test lines 350-408](https://github.com/nick-boss-tech/solr/blob/85a8d32339394fa58a1f56969cd0e4f1db00fbb8/solr/core/src/test/org/apache/solr/response/TestRawTransformer.java#L350-L408)) sends `fl=id,su*:[json],link?:[json]` and checks the raw output. It then sends `fl=au*:[xml]`, which is not applied to a JSON response, and `fl=su*:[docid]`, which returns a 400. On the base code the first request is rejected with a 400, so the test fails there.
- `TestRawTransformer.testSuffixGlobJsonTransformer` ([test lines 411-454](https://github.com/nick-boss-tech/solr/blob/85a8d32339394fa58a1f56969cd0e4f1db00fbb8/solr/core/src/test/org/apache/solr/response/TestRawTransformer.java#L411-L454)) sends `fl=id,*_json:[json]`, the form used as the example above. It parses the response as JSON and checks that each `payload_json` value comes back raw as a JSON array. It then sends `fl=*:[json]` and checks for a 400. The test adds a `*_json` field to its own schema copies. On the base code the `*_json` request is rejected with a 400, "Error parsing fieldname: Expected identifier at pos 0 str='*_json:[json]'", so this test fails there too.
