# SOLR-17660: Implement basic list component in Admin UI (new UI)

Draft PR description. Not opened as a GitHub PR.

## What

Adds `SolrList`, a reusable Compose composable in `ui/shared` for a list with a filter input on top.

- The filter input has an optional placeholder.
- Actions can be placed left and right of the input. Nothing is shown unless the caller passes them.
- A clear button appears inside the input only while the filter is non-empty. Pressing it calls `onFilterChange("")`.
- The caller passes the rows as a list and renders each row with `itemContent`.
- Each row scrolls horizontally on its own when it is wider than the list.
- The list scrolls vertically when the rows exceed the available height.

The component is stateless. The caller owns the filter text and the rows.

Out of scope, per the ticket: headers, sorting, and wiring to the logging section. The logging section has no data source yet, so the first consumer comes with that work.

## Testing

- `./gradlew -p ui :shared:jvmTest --tests "*SolrListTest*"`: 5 of 5 pass. Covers rows shown, clear button absent when empty, clear button empties the filter, leading and trailing actions shown, and a wide row reached by horizontal scrolling.
- Full `./gradlew -p ui :shared:jvmTest :shared:spotlessCheck` on the same head: 16 suites, 52 tests, 2 skipped (not in this component), 0 failures; spotless passes.
- Run on Linux arm64 with Mesa's EGL and GL libraries on `LD_LIBRARY_PATH`. Without them Skiko cannot load and every Compose UI test fails before its first assertion.
- Visual check: rendered the preview with and without a filter to PNG. The placeholder shows when the filter is empty, the clear button appears once it has text, and a long row is clipped at the edge where it can be scrolled.

## Blast radius

Not flagged. The component uses layout, text input, and a standard icon button. It uses no Canvas, DrawScope, graphicsLayer, or shaders.
