# SOLR-18458: deprecate debugQuery in favor of debug=all

Draft PR description. Not opened as a GitHub PR.

## Change

`SearchHandler` logs a deprecation warning through `DeprecationLog` (feature id `debugQuery`) when a request carries `debugQuery`. The log fires once per process, not per request, so shard requests from the coordinator do not flood the log. The parameter is still honored: behavior is unchanged.

## Route and tradeoffs

- Chosen: warn now, remove in a later release. The ticket says to drop the parameter and to use DeprecationLog in 10.x; this takes the first step.
- Not chosen: remove now. It breaks clients that send `debugQuery`, and the ticket notes subtle differences from `debug=all` that nobody has documented.
- Left as is: `DebugComponent` still writes `debugQuery` onto shard requests, `MoreLikeThisHandler` and `ReRankQParserPlugin` still read it, and `SolrQuery.setShowDebugInfo` (SolrJ API) still sets it. Changing these is the removal step, and changing SolrJ is a public API change, so it is a maintainer question.
