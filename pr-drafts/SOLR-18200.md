# SOLR-18200: TextProfileSignature orders equal-frequency tokens by text

## Problem

`TextProfileSignature` sorts the quantized token profile by frequency only. Tokens with the same quantized frequency keep whatever order `HashMap.values()` returns, and that order changes when the map resizes. Identical token sets therefore produce different MD5 signatures, depending on how many other tokens were added before them.

## Change

The comparator breaks frequency ties by token text, so the profile order no longer depends on the map's layout. The regression test builds a text of six frequent words, then adds 13 unique filler words that are removed by quantization and force a resize. The signature must not change.

## Behavior change (please review)

Signatures change for any document whose quantized profile contains tokens with equal frequency. Those documents get a new signature after this change. Existing stored signatures for such documents will not match new ones, so duplicate detection against an index built before the change needs a re-index. Documents whose profile has no ties keep their signature.

## Testing

- `TextProfileSignatureTest` (new): base text vs. the same text plus 13 filler words; passes with the fix, fails on the base (the signature changed after the resize).
- Gate on the fixed tree: tidy clean; Error Prone compile clean; focused test 1 of 1, 0 failures; `:solr:core:check -x test` clean.
