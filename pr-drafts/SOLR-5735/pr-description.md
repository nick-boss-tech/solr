**A safe-leader test fails when the client sends an update to a replica the monkey stops.** `ChaosMonkeySafeLeaderTest` and `ChaosMonkeySafeLeaderWithPullReplicasTest` stop replicas but spare leaders, then assert that no update failed ([line 209](https://github.com/apache/solr/blob/b73f03976fa17b857bc0a81bc8af2c6b1c31e0bb/solr/core/src/test/org/apache/solr/cloud/ChaosMonkeySafeLeaderWithPullReplicasTest.java#L209)). The cloud client in these tests is built with a random choice between sending updates to shard leaders only and sending them to any replica ([line 370](https://github.com/apache/solr/blob/b73f03976fa17b857bc0a81bc8af2c6b1c31e0bb/solr/test-framework/src/java/org/apache/solr/cloud/AbstractFullDistribZkTestBase.java#L370)). In the second mode an update can go to a pull replica, and the monkey can stop that node while the request is in flight. The request then fails with `ClosedChannelException` and the check reports `expected:<0> but was:<1>`. On main with seed `E4EFD2B86C0B81D4` on local disk, a `deleteById` sent to `collection1_shard1_replica_p11` failed 4 ms after the monkey stopped that node.

**The safe-leader tests now use a leaders-only client.** Both tests override `createCloudClient` to build the client with `shardLeadersOnly` set. Leaders are the one kind of node these tests never stop, so an update that fails now is a real failure. Nothing else changes. The NothingIsSafe tests keep the random client.

**Proof.** The failure is a timing race, so no single run fails on main. **The choice.** Three routes were available:
1. Use a leaders-only client in the safe-leader tests (this PR).
2. Leave failures caused by a stopped node out of the failure count. This also loosens the failure tolerance in the NothingIsSafe tests that read the same count.
3. Retry the cut-off update in the client. The load-balancing client does not retry an update after an I/O error, because the server may already have applied it ([line 576](https://github.com/apache/solr/blob/b73f03976fa17b857bc0a81bc8af2c6b1c31e0bb/solr/solrj/src/java/org/apache/solr/client/solrj/impl/LBSolrClient.java#L576)).

Context: the test name says leaders are safe, and a leader is the node every leaders-only update goes to. A retry on a non-idempotent update could apply it twice.

Ladder: Does the test promise no failed update? Yes, but only for updates sent to a node it spares. Is a failed update to a node the monkey stops a defect? No. Does the any-replica client lose coverage? The NothingIsSafe tests still run it, with a failure tolerance.

**Recommendation:** route 1. It keeps the zero-failure check strict, and it changes only the two tests that need it.

**Limits.** The safe-leader tests no longer send updates through a non-leader replica under chaos. Whether the client should retry an update that fails with `ClosedChannelException` is a separate question; a follow-up ticket can be opened on request.
