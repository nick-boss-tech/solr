## What happens today

**The failure summary can print a reproduce command that does not match the failing beast subtask.**

The "Reproduce with" line is built from the project's test options, so it carries the project's root seed. Beast subtasks can override the root seed. The printed command can then name a different seed from the one that failed.

Pre-change code, at the base commit (the merge-base): [gradle/testing/failed-tests-at-end.gradle line 33](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/gradle/testing/failed-tests-at-end.gradle#L33).

## What this change does

**The reproduce line now uses the seed of the subtask that failed.**

A small helper reads the failing task's seed and writes it into the reproduce line. It replaces the project seed option, or adds one when none is present. It runs for failed tests and for failed suites: [the helper, lines 40-53](https://github.com/nick-boss-tech/solr/blob/68dd5e2b154e3b9e61c715db94ca91fadad545a6/gradle/testing/failed-tests-at-end.gradle#L40-L53) and [its call sites, lines 58-67](https://github.com/nick-boss-tech/solr/blob/68dd5e2b154e3b9e61c715db94ca91fadad545a6/gradle/testing/failed-tests-at-end.gradle#L58-L67).

The helper runs for every failing test, not only for beast runs. Limits lists what was not run with it.

## Proof

**At this head, the printed seed matched the failing subtask. At the base commit, it matched the root seed instead.**

The check used a temporary test that fails on purpose. Its file was never committed and was deleted after the run. It ran as a beast task with 16 repeats, once at the base commit and once at this head.

- Base commit: the printed seed was the root seed, not the failing subtask's seed.
- This head: the printed seed was the failing subtask's seed.
- The temporary test at this head: 1 test, 1 failure (the planted assertion), 0 errors, 0 skipped.

An earlier head, 65e0b8d7, gave the same result. No production test suite was run. The planted failure is not a product test result.

## Limits

**Only the beast path was run with this change.**

- Builds without a beast task, and passing builds, were not run with this change. The helper also runs for them.
- A beast run with a seed given on the command line was not run.
- In this checkout, the beast task ran no tests until a temporary local setup wired its generated test tasks to the standard test classes. No tracked build file changed for the run.
- The branch adds no test. The check above used a temporary test that was removed.
