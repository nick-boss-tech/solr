Title: Stop the release wizard when EDITOR names a terminal editor

https://issues.apache.org/jira/browse/SOLR-17252

## What happens today

**With EDITOR set to a terminal editor, the wizard hands the terminal to that editor, and the wizard stops responding.**

The wizard runs `{{ editor }}` in the same terminal for steps such as editing `.asf.yaml` ([releaseWizard.yaml line 450](https://github.com/apache/solr/blob/3f5d4c5bf8ac96fec3a3219398b0c52c5418d48c/dev-tools/scripts/releaseWizard.yaml#L450)) and a later file edit ([line 1534](https://github.com/apache/solr/blob/3f5d4c5bf8ac96fec3a3219398b0c52c5418d48c/dev-tools/scripts/releaseWizard.yaml#L1534)). On main, `get_editor()` warns only when EDITOR is exactly `vi`, `vim`, `nano`, `pico` or `emacs`, and then uses the value anyway ([lines 196-199](https://github.com/apache/solr/blob/3f5d4c5bf8ac96fec3a3219398b0c52c5418d48c/dev-tools/scripts/releaseWizard.py#L196-L199)). A value such as `/usr/bin/nano` or `nano -x` gets no warning.

## What this change does

**The wizard now stops with a message when the first word of EDITOR names one of those five editors.**

The check compares the basename of the first word with the five names ([lines 194-199](https://github.com/nick-boss-tech/solr/blob/d730a266a0425b2609f4bcf21756555d3d3b8f52/dev-tools/scripts/releaseWizard.py#L194-L199)), so `/usr/bin/vim` and `emacs -nw` match. The exit is at [lines 206-211](https://github.com/nick-boss-tech/solr/blob/d730a266a0425b2609f4bcf21756555d3d3b8f52/dev-tools/scripts/releaseWizard.py#L206-L211). The check runs when the first checklist menu is built, which is after the release state file is written ([line 1392](https://github.com/nick-boss-tech/solr/blob/d730a266a0425b2609f4bcf21756555d3d3b8f52/dev-tools/scripts/releaseWizard.py#L1392), [line 1414](https://github.com/nick-boss-tech/solr/blob/d730a266a0425b2609f4bcf21756555d3d3b8f52/dev-tools/scripts/releaseWizard.py#L1414)).

Behavior change: a value that used to produce a warning now stops the wizard, including on `--dry-run`. GUI emacs is refused too, because `emacs` is in the list. `emacsclient` and `code --wait` pass through. The two docs pages name the same five editors ([releasing.adoc lines 56-58](https://github.com/nick-boss-tech/solr/blob/d730a266a0425b2609f4bcf21756555d3d3b8f52/dev-docs/releasing.adoc#L56-L58), [dev-tools/scripts/README.md lines 52-54](https://github.com/nick-boss-tech/solr/blob/d730a266a0425b2609f4bcf21756555d3d3b8f52/dev-tools/scripts/README.md#L52-L54)).

## Proof

**A local check script ran 21 checks at head d730a266a042 on 2026-10-07, and all 21 passed. No repository test covers this change.**

The script confirmed that `emacs` and `/usr/bin/emacs` are refused, and that `emacsclient` and `code --wait` pass through. It is not part of the repository, and this change adds no unit test for `releaseWizard.py`.

## A choice to check

**The list refuses every emacs, and the check runs at the first menu build. Other options are open.**

- Refuse only terminal-mode emacs (`emacs -nw` or `--no-window-system`), so a GUI emacs still runs. The cost is argument parsing and a flag list to keep current.
- Print a warning and let the run continue, as main does today for the exact five names. The ticket raised this option. The cost is that the terminal problem stays for anyone who ignores the warning.
- Wrap the editor in tmux, which a commenter on the ticket tested. The commenter called it working but more complicated.
- Move the check to the point where the wizard starts an editor. The cost is that a bad EDITOR fails partway through a run, after release state exists.

Was refusing every emacs, and checking at the first menu build, the right call?

## Limits

- Only the first word of EDITOR is checked, so a wrapper such as `env nano` passes.
- The list is fixed at five names. Other terminal editors, such as `nvim`, pass.
- No live terminal run was done, so the terminal symptom itself was not reproduced after the change.
- If maintainers choose one of the options above, I can submit it as a follow-up change on this branch.
