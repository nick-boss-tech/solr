Title: Document tie-order and paging differences across SolrCloud replicas

https://issues.apache.org/jira/browse/SOLR-5821

## What happens today

**The same query can return tied documents in a different order on each replica of a shard.**

The ticket reports that replicas of one shard return different results for the same query, where some documents share a score. When documents tie on every sort criterion, Solr falls back to Lucene's internal document ID, and that ID can differ between replicas. The [tie-breaker paragraph](https://github.com/nick-boss-tech/solr/blob/b8af2d1ce2f5f963250feafccd9fc698ae268289/solr/solr-ref-guide/modules/query-guide/pages/common-query-parameters.adoc#L72-L73) explains the internal ID but does not say that replicas can disagree, or what that does to paging.

## What this change does

**The change adds three sentences to the tie-breaker paragraph in common query parameters.**

The new sentences say that:

1. two replicas of one shard can order tied documents differently when the sort is only `score` or another non-unique field;
2. the documents on a page, not only their order, can differ between replicas, and consecutive pages served by different replicas can repeat or skip a document;
3. `numFound` is not affected when the replicas are in sync and have the same searcher.

The existing advice to add a unique sort field stays. See [common-query-parameters.adoc lines 74-76](https://github.com/nick-boss-tech/solr/blob/b8af2d1ce2f5f963250feafccd9fc698ae268289/solr/solr-ref-guide/modules/query-guide/pages/common-query-parameters.adoc#L74-L76). The guide already says that score sorting across replicas can skip or repeat documents in cursor requests ([pagination of results, lines 121-126](https://github.com/nick-boss-tech/solr/blob/b8af2d1ce2f5f963250feafccd9fc698ae268289/solr/solr-ref-guide/modules/query-guide/pages/pagination-of-results.adoc#L121-L126)), and that each replica opens its searcher on its own ([SolrCloud update consistency, line 73](https://github.com/nick-boss-tech/solr/blob/b8af2d1ce2f5f963250feafccd9fc698ae268289/solr/solr-ref-guide/modules/deployment-guide/pages/solrcloud-update-consistency.adoc#L73)). The new text is consistent with both.

## Limits

- The ticket also reports replica document-count differences during indexing. A commenter linked that to SOLR-4260. This change does not address it. It says `numFound` is not affected when replicas are in sync and have the same searcher. It does not describe how far replicas can drift or how to detect it.
- The new text covers tied scores. The cursor section also notes that term statistics can differ between replicas, which changes the scores themselves. This change does not describe that case.
- The documentation build ran on a tree based on 14c7aac0d151402b00259e2fb9bf5eed7049ec5d, the branch base. This page has not changed on main since that base.
- A follow-up for either item can be opened on request.
