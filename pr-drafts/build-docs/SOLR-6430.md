Title: Ref guide: without sortMissingFirst/sortMissingLast, a missing numeric or date sort value is treated as 0 (1970-01-01), not as the lowest value.

https://issues.apache.org/jira/browse/SOLR-6430

## What happens today

**The field type table does not say where a missing numeric or date value sorts.**

When neither `sortMissingFirst` nor `sortMissingLast` is set, the field type passes no missing value to the sort ([FieldType.missingValue, lines 854-862](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/schema/FieldType.java#L854-L862)). Numeric sorts then use 0. Dates use the same numeric sort path ([PointField.getSortField, lines 318-319](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/schema/PointField.java#L318-L319)). A date is indexed as milliseconds since the epoch ([DatePointField, line 196](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/schema/DatePointField.java#L196)). So a missing date sorts as 1970-01-01T00:00:00Z, between dates before 1970 and dates after it.

The table row at the base says only that the properties "control the placement of documents when a sort field is not present" ([line 202](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/solr-ref-guide/modules/indexing-guide/pages/field-type-definitions-and-properties.adoc#L202)). The code links above are at the base too.

## What this change does

**The table row now states the default placement for string, numeric and date fields.**

The [row at this head](https://github.com/nick-boss-tech/solr/blob/c0c6e5dd21c4eee60257db6b85b2fec7f01489b7/solr/solr-ref-guide/modules/indexing-guide/pages/field-type-definitions-and-properties.adoc#L202) says that, when neither property is set, string fields sort missing values first. Numeric and date fields treat a missing value as 0, which is 1970-01-01T00:00:00Z for dates. The row also says to set one of the properties for predictable placement. No code changes.
