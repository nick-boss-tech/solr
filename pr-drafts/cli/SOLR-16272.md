Title: Remove a failed package install's files unless the version may be registered

https://issues.apache.org/jira/browse/SOLR-16272

## What happens today

**A failed `bin/solr package install` leaves the files it already uploaded in the file store, so a retry of the same version fails.**

The install posts the manifest, then each artifact, then sends the registration request ([RepositoryManager.java, base, L165-L249](https://github.com/nick-boss-tech/solr/blob/14c7aac0d151402b00259e2fb9bf5eed7049ec5d/solr/core/src/java/org/apache/solr/packagemanager/RepositoryManager.java#L165-L249)). When a later step fails, the error is rethrown and nothing is removed. In the ticket, a signature error on an artifact leaves `manifest.json` behind, so the retry fails with `Path already exists`. The ticket also notes that uninstall correctly reports the version as not installed, because it never registered.

## What this change does

**The install removes the files it posted when it fails, unless the version may already be registered.**

Posted paths are collected in a list ([L178](https://github.com/nick-boss-tech/solr/blob/d2cf817391692b29c3d221ec4ebed65c3833bb91/solr/core/src/java/org/apache/solr/packagemanager/RepositoryManager.java#L178)), and each path is added after its upload ([L203](https://github.com/nick-boss-tech/solr/blob/d2cf817391692b29c3d221ec4ebed65c3833bb91/solr/core/src/java/org/apache/solr/packagemanager/RepositoryManager.java#L203), [L220](https://github.com/nick-boss-tech/solr/blob/d2cf817391692b29c3d221ec4ebed65c3833bb91/solr/core/src/java/org/apache/solr/packagemanager/RepositoryManager.java#L220)). A failed install calls the cleanup ([L258-L263](https://github.com/nick-boss-tech/solr/blob/d2cf817391692b29c3d221ec4ebed65c3833bb91/solr/core/src/java/org/apache/solr/packagemanager/RepositoryManager.java#L258-L263)). When the registration request has been sent, the cleanup first checks whether the version is registered ([mayBeRegistered, L299-L311](https://github.com/nick-boss-tech/solr/blob/d2cf817391692b29c3d221ec4ebed65c3833bb91/solr/core/src/java/org/apache/solr/packagemanager/RepositoryManager.java#L299-L311)). If the version is registered, or the check itself fails, the files are kept. Otherwise each recorded path is deleted from ZooKeeper and the file store ([cleanupPartialInstall, L278-L296](https://github.com/nick-boss-tech/solr/blob/d2cf817391692b29c3d221ec4ebed65c3833bb91/solr/core/src/java/org/apache/solr/packagemanager/RepositoryManager.java#L278-L296)).

Cleanup is best effort. A failed delete is logged and does not replace the error that the install reports.

The uninstall command is unchanged. For a version that did not register, it still reports that the version is not installed.

## Proof

**The new test fails on the base code and passes with this change.**

`PackageToolTest` 3 of 3 at head d2cf817391692b29c3d221ec4ebed65c3833bb91, verified 2026-10-04.

The new test is [`testFailedInstallLeavesNoPostedFilesBehind`](https://github.com/nick-boss-tech/solr/blob/d2cf817391692b29c3d221ec4ebed65c3833bb91/solr/core/src/test/org/apache/solr/cli/PackageToolTest.java#L443-L508). It installs a copy of the test repository under another package name, with a signature that matches no public key. After the install fails, it checks that the manifest is gone from the file store.

## Limits

- The new test covers a failure at an artifact upload, before registration. No test covers the rule for files after the registration request.
- Errors that are not one of the three types the install handles skip the cleanup, as before.
- The check reads the package registry once. If the server finishes a registration after that read, the check misses it, and the files could be removed.
- If files are kept, a retry that sends different bytes to a path still in use fails with `Path already exists` ([ClusterFileStore.java, L111-L131](https://github.com/nick-boss-tech/solr/blob/d2cf817391692b29c3d221ec4ebed65c3833bb91/solr/core/src/java/org/apache/solr/filestore/ClusterFileStore.java#L111-L131)). The same bytes and signatures are accepted.
