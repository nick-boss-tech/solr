## What happens today

**A quoted value with a space in `SOLR_OPTS` or `--jvm-opts` stops Solr from starting.**

The script splits these values on every space and keeps quote characters as ordinary text. With `SOLR_OPTS='-Dyak="white space"'`, the JVM receives `-Dyak="white` and `space"` as two arguments. Solr then fails with `Error: Could not find or load main class space"`. The same failure happens with `--jvm-opts`. The base code does the split with an unquoted expansion ([solr/bin/solr, base, L681](https://github.com/nick-boss-tech/solr/blob/14c7aac0d151402b00259e2fb9bf5eed7049ec5d/solr/bin/solr#L681)) and passes the `--jvm-opts` value to the JVM the same way ([base, L1349](https://github.com/nick-boss-tech/solr/blob/14c7aac0d151402b00259e2fb9bf5eed7049ec5d/solr/bin/solr#L1349)).

The ticket's example uses `-a`. This version of the script has no `-a` option. `--jvm-opts` is the option that takes these values now.

## What this change does

**Both values go through one small parser, and the parser expands and runs nothing.**

The parser is `parse_jvm_opts` ([solr/bin/solr, L687-L737](https://github.com/nick-boss-tech/solr/blob/4a98ef0a89d16ec5a645a1c38fbe25dc28c87e62/solr/bin/solr#L687-L737)). `SOLR_OPTS` is parsed at [L741-L742](https://github.com/nick-boss-tech/solr/blob/4a98ef0a89d16ec5a645a1c38fbe25dc28c87e62/solr/bin/solr#L741-L742). The `--jvm-opts` value is parsed inside `start_solr` at [L1278-L1284](https://github.com/nick-boss-tech/solr/blob/4a98ef0a89d16ec5a645a1c38fbe25dc28c87e62/solr/bin/solr#L1278-L1284). The rules are these:

- Single quotes keep everything up to the closing quote, as written.
- Double quotes keep everything, except that `\"`, `\\`, `\$` and `` \` `` give the character after the backslash.
- Outside quotes, a backslash escapes a space, a tab, a quote or another backslash. Before any other character, the backslash stays. So `C:\solr\logs` is unchanged.

Nothing in a value is expanded or executed. A value with `$`, a backtick or a semicolon keeps its exact text. An eval-based split would rewrite such values, for example a password that contains `$$`. This change does not use eval.

Behavior changes:

- Quote characters are removed. Before, `-Dfoo="bar"` reached the JVM with its quotes, so the property value was `"bar"`. Now the value is `bar`.
- Glob patterns such as `*` are no longer matched against files in the current directory.

## Limits

**Not covered: the Windows script and the `-e` example launch.**

- `solr/bin/solr.cmd` is not changed by this branch.
- `solr start -e <example> --jvm-opts` passes the value through the example tool, which wraps it in double quotes before it calls the start command ([RunExampleTool.java, L872-L880](https://github.com/nick-boss-tech/solr/blob/4a98ef0a89d16ec5a645a1c38fbe25dc28c87e62/solr/core/src/java/org/apache/solr/cli/RunExampleTool.java#L872-L880)). A value that has its own double quotes may not split as intended on that path. None of the three tests covers it.
- A backslash before a space escapes the space. So a Windows path that ends in a backslash joins the next option: `-Dsolr.logs.dir=C:\logs\ -Dfoo=1` becomes one argument.
- Outside single quotes, a doubled backslash becomes one backslash. A UNC path such as `\\server\share` written without quotes loses one backslash. Single quotes keep it.
