## What happens today

**On Windows, a `SOLR_LOGS_DIR` value with a space or a parenthesis can stop `bin\solr.cmd start` from working.**

The ticket reports this for `SOLR_LOGS_DIR` set in the environment. Before this change, the script tested the variable with `IF [%SOLR_LOGS_DIR%] == []` and stripped quotes with `set SOLR_LOGS_DIR=%SOLR_LOGS_DIR:"=%` ([solr/bin/solr.cmd, base, L896-L900](https://github.com/nick-boss-tech/solr/blob/97d973814336101e12475558d7419321c743de79/solr/bin/solr.cmd#L896-L900)). cmd.exe expands `%VAR%` in a whole block before it finds where the block ends. So the spaces and parentheses in the value change how the block is read.

## What this change does

**The value is read only through delayed expansion, so the path never becomes part of the block text.**

The change is in `solr/bin/solr.cmd` only ([L895-L903](https://github.com/nick-boss-tech/solr/blob/8c91cf047a96fee86dd6164b81715d1ed51ebfc4/solr/bin/solr.cmd#L895-L903)):

- `IF NOT DEFINED SOLR_LOGS_DIR` replaces the bracket test. An unset variable still gets the default, `%SOLR_SERVER_DIR%\logs`.
- Quotes are stripped with `set "SOLR_LOGS_DIR=!SOLR_LOGS_DIR:"=!"`. Delayed expansion reads the value when the line runs, after cmd.exe has read the block.
- A check after the block treats a value made only of quote characters as unset, and gives it the default. Behavior change: a value such as `""` now gets the default logs directory. Before this change, it was cleared and no default was set.

A value with no quote characters is stored as before. Delayed expansion is already on for the whole script ([solr/bin/solr.cmd, L21](https://github.com/nick-boss-tech/solr/blob/8c91cf047a96fee86dd6164b81715d1ed51ebfc4/solr/bin/solr.cmd#L21)).

## Proof

**The change is verified by construction. It has not been run on Windows, and that run is still to do.**

No test in this repository runs `solr.cmd`, so this rests on how cmd.exe parses the file at head `8c91cf047a96fee86dd6164b81715d1ed51ebfc4`:

- The old test and the old quote strip put the value into an `IF` line and a block. cmd.exe expands `%VAR%` before it finds the block boundaries, so a space or a parenthesis in the value changes the parse.
- The new lines put no value text into the parse. The value is read only by delayed expansion, which runs after the block has been read.
- Every later use of `SOLR_LOGS_DIR` in the start code is inside double quotes or delayed expansion ([L1110-L1174](https://github.com/nick-boss-tech/solr/blob/8c91cf047a96fee86dd6164b81715d1ed51ebfc4/solr/bin/solr.cmd#L1110-L1174)). Spaces and parentheses in the stored value do not break those lines.
- An unset value and a plain value give the same result as before. A value made only of quote characters differs, as described above.

The confirming run has not been done yet. It would set `SOLR_LOGS_DIR` to a path with spaces and parentheses, run `bin\solr.cmd start`, and check which logs directory Solr uses.

## Limits

**Not fixed: the `stop --all` failure in the ticket, and the report that the variable is sometimes ignored.**

- For `stop`, the script leaves at [L876](https://github.com/nick-boss-tech/solr/blob/8c91cf047a96fee86dd6164b81715d1ed51ebfc4/solr/bin/solr.cmd#L876) and never reaches the start code at [L881](https://github.com/nick-boss-tech/solr/blob/8c91cf047a96fee86dd6164b81715d1ed51ebfc4/solr/bin/solr.cmd#L881). The stop code does not use `SOLR_LOGS_DIR`. A restart does read this block. So the `stop --all` failure is not addressed here.
- This change does not explain the report that the variable is sometimes ignored.
- Values that contain `!` or `^` were not part of the reasoning above.
- The first-argument test, `IF [%1]==[] goto run_special_command` ([L375](https://github.com/nick-boss-tech/solr/blob/8c91cf047a96fee86dd6164b81715d1ed51ebfc4/solr/bin/solr.cmd#L375)), keeps its bracket form. This change does not touch it.
