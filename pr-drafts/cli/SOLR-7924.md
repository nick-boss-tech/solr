## What happens today

**On a platform whose `sleep` rejects fractional seconds, `bin/solr` prints an error for every spinner tick while Solr starts or stops.**

The spinner calls `sleep 0.5` on every tick ([solr/bin/solr, lines 453-464 at the merge base](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/bin/solr#L453-L464)). The stop wait and the start wait both use this spinner ([lines 546 and 1408](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/bin/solr#L546)). The ticket reports this on IBM AIX. There, each `sleep 0.5` fails with `sleep: invalid argument`, and the loop runs without a pause. In the reproduction on the old script, the output held at least 100 of those lines.

## What this change does

**The spinner tests `sleep` once. If `sleep` rejects fractions, the spinner uses one-second steps.**

Before its loop, the spinner runs `sleep 0.5` with its errors discarded. If that fails, it sets the delay to one second ([solr/bin/solr, lines 453-457 at the head](https://github.com/nick-boss-tech/solr/blob/96ef3a52bdbf1948578d122ec2f9d61e0944a8f2/solr/bin/solr#L453-L457)). Nothing else in the spinner changes. Both waits get the fix because both call the same function.

## Proof

**The new BATS case fails on the old script and passes with this change.**

- Old script (merge base `cabedd1d968`), verified 2026-10-10: the case `spinner falls back to whole-second sleeps when sleep rejects fractions` fails. Its `refute_output --partial 'invalid argument'` finds the errors in the output, and at least 100 `sleep: invalid argument` lines appear.
- This head (`96ef3a52bdbf`), verified 2026-10-10 at this head: the same case passes, 1 of 1.

The case runs the spinner function alone against a short-lived process, with a stand-in `sleep` that accepts only whole numbers ([test, lines 135-153](https://github.com/nick-boss-tech/solr/blob/96ef3a52bdbf1948578d122ec2f9d61e0944a8f2/solr/packaging/test/test_start_solr.bats#L135-L153)).

## A choice to check

**The spinner tests `sleep` once and uses whole seconds only where needed, instead of always using whole seconds.**

Always using one-second steps would be simpler to read. It would also slow the spinner on platforms that already accept fractions. The probe keeps the half-second pace where it works. Was the probe the right call, or should the spinner always use whole seconds?

## Limits

**The AIX behavior is simulated. No AIX system was used.**

- The stand-in `sleep` only rejects fractions. A real `sleep` on AIX was not run.
- A zero-length probe (`sleep 0.0`) was not tried. The stand-in rejects it too.
- If SOLR-18339 lands first, the start wait no longer calls this spinner ([SOLR-18339](https://issues.apache.org/jira/browse/SOLR-18339)). This change would then cover only the stop wait.
