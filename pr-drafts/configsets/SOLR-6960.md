## What happens today

**The config report shows a request handler's own values and leaves out the values that initParams add.**

An initParams block can add defaults, appends and invariants to a request handler, matched by name or by path. The live handler gets those values. The /config API's requestHandler section does not. The report is built from each handler's own solrconfig.xml entry only ([SolrConfig.java L985-L993](https://github.com/nick-boss-tech/solr/blob/9bef536fc12a3c5a1718f22b11cffa348e57a433/solr/core/src/java/org/apache/solr/core/SolrConfig.java#L985-L993)). A client that reads the report sees keys missing for values the handler really uses.

## What this change does

**The report now merges initParams into request handlers defined in solrconfig.xml. It uses the same helper the live handler uses.**

The loop in [SolrConfig.java L988-L992](https://github.com/nick-boss-tech/solr/blob/9bef536fc12a3c5a1718f22b11cffa348e57a433/solr/core/src/java/org/apache/solr/core/SolrConfig.java#L988-L992) passes each request handler through `RequestHandlers.applyInitParams`. Startup uses the same helper ([RequestHandlers.java L110-L117](https://github.com/nick-boss-tech/solr/blob/9bef536fc12a3c5a1718f22b11cffa348e57a433/solr/core/src/java/org/apache/solr/core/RequestHandlers.java#L110-L117), helper at [L134-L152](https://github.com/nick-boss-tech/solr/blob/9bef536fc12a3c5a1718f22b11cffa348e57a433/solr/core/src/java/org/apache/solr/core/RequestHandlers.java#L134-L152)). Overlay handlers, the ones added through the Config API, are shown as stored, with no merge ([SolrConfig.java L994-L996](https://github.com/nick-boss-tech/solr/blob/9bef536fc12a3c5a1718f22b11cffa348e57a433/solr/core/src/java/org/apache/solr/core/SolrConfig.java#L994-L996)).

Behavior change: the report gains keys that initParams fill in. A client that compares the exact response shape may see new keys.

## Limits

**Built-in handlers are not covered. The ticket's own example is one of them.**

The ticket's example, `/update/json/docs`, is a built-in handler ([ImplicitPlugins.json L28](https://github.com/nick-boss-tech/solr/blob/9bef536fc12a3c5a1718f22b11cffa348e57a433/solr/core/src/resources/ImplicitPlugins.json#L28)). The /config API adds built-in handlers as stored, with no initParams merge ([SolrConfigHandler.java L352-L358](https://github.com/nick-boss-tech/solr/blob/9bef536fc12a3c5a1718f22b11cffa348e57a433/solr/core/src/java/org/apache/solr/handler/SolrConfigHandler.java#L352-L358)). So the report still misses initParams values for those handlers. I can open a follow-up ticket and PR for built-in handlers on request.

Overlay handlers, added through the Config API, are reported as stored. The change does not merge into them.

The proof is a unit-level serialization test. It reads the SolrConfig object and checks the report data. It does not make a live /config request.
