## What happens today

**Old index directories can be cleaned up after the DirectoryFactory has closed.**

Before this change, closing a core started the old index directory cleanup on a new background thread ([thread start](https://github.com/nick-boss-tech/solr/blob/bdeba582fd63c812b6a0ecaa9874c42c42880e76/solr/core/src/java/org/apache/solr/core/SolrCore.java#L3519-L3524)). The same close then closed the `DirectoryFactory` ([close](https://github.com/nick-boss-tech/solr/blob/bdeba582fd63c812b6a0ecaa9874c42c42880e76/solr/core/src/java/org/apache/solr/core/SolrCore.java#L1871)). The cleanup can need that factory to be open, so the two can race. The Jira ticket describes this race.

## What this change does

**On close, the cleanup runs in the closing thread, before the factory closes. The reload path still uses the background thread.**

- The close path calls the cleanup with `async` set to false ([close call](https://github.com/nick-boss-tech/solr/blob/bdeba582fd63c812b6a0ecaa9874c42c42880e76/solr/core/src/java/org/apache/solr/core/SolrCore.java#L1840-L1841)).
- The overload that runs the cleanup inline is at [lines 3501 to 3525](https://github.com/nick-boss-tech/solr/blob/bdeba582fd63c812b6a0ecaa9874c42c42880e76/solr/core/src/java/org/apache/solr/core/SolrCore.java#L3501-L3525). The public method used by reload still starts a background thread ([public method](https://github.com/nick-boss-tech/solr/blob/bdeba582fd63c812b6a0ecaa9874c42c42880e76/solr/core/src/java/org/apache/solr/core/SolrCore.java#L3497-L3498)).
- Errors from the cleanup are still logged and not rethrown.

## Proof

**A new test fails on the base code and passes with this change.**

- `SolrCoreCleanupOnCloseTest` 1 of 1 ([test](https://github.com/nick-boss-tech/solr/blob/bdeba582fd63c812b6a0ecaa9874c42c42880e76/solr/core/src/test/org/apache/solr/core/SolrCoreCleanupOnCloseTest.java#L104-L151)). On the base code it fails with one failure: the factory close is recorded before the cleanup starts. With this change it passes.
- `SolrCoreTest` 9 of 9 and `DirectoryFactoryTest` 3 of 3 pass with this change.
- `TestCoreContainer` passes with this change: 25 tests, 3 skipped, 0 failures.
- Verified 2026-10-08 at head `bdeba582fd63`.

## A choice to check

**Close now waits for the cleanup to finish. The other route keeps the cleanup on a background thread and has close wait for that thread.**

Options considered:

- Run the cleanup in the closing thread, before the factory closes. This is the change here. The order is simple, but a slow cleanup now delays the close.
- Keep the cleanup on a background thread, with a guard so the factory close waits for it. The close still waits, but the cleanup stays off the closing thread, and the guard needs its own error handling.

Was running the cleanup in the closing thread the right call, or should close wait on a background cleanup instead?

## Limits

- Only the close path changes. Reload and the other callers of the public cleanup method still use the background thread.
- Core close now lasts as long as the cleanup. Timing on large index directories was not measured.
- The test uses a mock directory factory. Other directory factories, such as HDFS, are not exercised here.
