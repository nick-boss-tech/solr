## What happens today

**A full copy deletes the old index directory, even when a named snapshot still keeps files in it.**

After a replica installs a full copy from the leader, the code removes the old index directory right away ([IndexFetcher.java L747-L750](https://github.com/nick-boss-tech/solr/blob/b5c71bc5573c4e31b4cee5a7965d73587fc0ae58/solr/core/src/java/org/apache/solr/handler/IndexFetcher.java#L747-L750)). The removal does not check for named snapshots, so files a snapshot still needs in that directory are deleted with it. On the merge-base code, with the branch's test file in place, `testFullCopyKeepsSnapshotFilesInOldIndexDir` fails with "old index directory must be retained while a snapshot references it."

The links point to the merge-base commit `b5c71bc5573`, the code before this change.

## What this change does

**The old index directory is cleaned up after the new index is active, and files a named snapshot keeps are not deleted.**

- The right-away removal is gone. After the new index is active, the cleanup runs ([IndexFetcher.java L755-L771 at head `1004abee39ab`](https://github.com/nick-boss-tech/solr/blob/1004abee39ab07d5eae1a5ea6327572997ff50d2/solr/core/src/java/org/apache/solr/handler/IndexFetcher.java#L755-L771)). It removes the old directory only when no named snapshot is in it. Otherwise it deletes only the files no snapshot keeps ([SolrCore.java L694-L721](https://github.com/nick-boss-tech/solr/blob/1004abee39ab07d5eae1a5ea6327572997ff50d2/solr/core/src/java/org/apache/solr/core/SolrCore.java#L694-L721)).
- After a core reload, the cleanup runs on the current core, not on the closed core the fetcher started with ([L763-L770](https://github.com/nick-boss-tech/solr/blob/1004abee39ab07d5eae1a5ea6327572997ff50d2/solr/core/src/java/org/apache/solr/handler/IndexFetcher.java#L763-L770)).
- If a snapshot's recorded index directory no longer exists, the cleanup for that snapshot is skipped and logged as a warning ([SolrCore.java L649-L657](https://github.com/nick-boss-tech/solr/blob/1004abee39ab07d5eae1a5ea6327572997ff50d2/solr/core/src/java/org/apache/solr/core/SolrCore.java#L649-L657)).

Behavior change, stated openly: a full copy now keeps the files that named snapshots keep in the old index directory. The old code deleted them. Old directories that no named snapshot uses are still removed.

## Proof

**One of the four new tests fails on the merge-base code, and all four pass with the change.**

- `TestReplicationHandler`: 4 of 4 new tests pass at head `1004abee39ab`, verified 2026-10-14. The class has 28 test methods at that head. The new tests are `testFullCopyRemovesOldIndexDirWhenNoSnapshot`, [`testFullCopyKeepsSnapshotFilesInOldIndexDir`](https://github.com/nick-boss-tech/solr/blob/1004abee39ab07d5eae1a5ea6327572997ff50d2/solr/core/src/test/org/apache/solr/handler/TestReplicationHandler.java#L277-L278), `testFullCopyWithReloadRemovesOldIndexDir` and `testDeleteNamedSnapshotWithMissingIndexDir`.
- On the merge-base code `b5c71bc5573`, with the branch's test file in place, one test fails: `testFullCopyKeepsSnapshotFilesInOldIndexDir`, with "old index directory must be retained while a snapshot references it". The other three pass there. Verified 2026-10-14.

## Limits

**Three of the four new tests guard behavior but cannot fail on the base, so the reload path and the missing-directory check have no test that fails without the change.**

- `testFullCopyRemovesOldIndexDirWhenNoSnapshot` guards the new cleanup against dropping the old-directory removal. The base also removed that directory after every full copy, so the test has no failing behavior to catch on the base.
- `testFullCopyWithReloadRemovesOldIndexDir` guards against a leak the new cleanup could have had: after a reload, the cleanup could run through the old, closed core and skip the removal. The base removes the old directory directly, with no core check, so the leak cannot show there.
- `testDeleteNamedSnapshotWithMissingIndexDir` checks that the delete does not throw and that the snapshot entry is removed. On the base, the delete creates the missing directory, removes it, and returns normally, so both checks also hold there.
- A test that fails on the base for the missing-directory check would need a different setup. This change does not include one.
- The class is nightly. Its tests run only when nightly tests are enabled.
- The proof covers `TestReplicationHandler` only.
