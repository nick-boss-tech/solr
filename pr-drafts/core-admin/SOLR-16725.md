## What happens today

**CLUSTERSTATUS can show the same replica count as a string for one collection and as a number for another.**

The ticket shows `replicationFactor`, `nrtReplicas`, `tlogReplicas` and `pullReplicas` as quoted strings for a collection made with CREATE. For a collection made by RESTORE, the same keys come back as numbers. A client that parses the output with one type fails on the other ([JIRA](https://issues.apache.org/jira/browse/SOLR-16725)).

## What this change does

**CLUSTERSTATUS now returns those four counts as strings for every collection.**

A helper converts the four keys to strings before each collection's status is built ([ClusterStatus.java L341-L353](https://github.com/nick-boss-tech/solr/blob/be1838ef8ccf21a21938a9669d418abeec66e29d/solr/core/src/java/org/apache/solr/handler/admin/ClusterStatus.java#L341-L353), called at [L377](https://github.com/nick-boss-tech/solr/blob/be1838ef8ccf21a21938a9669d418abeec66e29d/solr/core/src/java/org/apache/solr/handler/admin/ClusterStatus.java#L377)). For a CREATE collection the output does not change, because it already reports strings. For a restored collection, the four counts change from numbers to strings. Other keys are not changed.

## Proof

**The restore test now checks the type of each count, and it fails on the base code.**

- `LocalFSCloudIncrementalBackupTest` 7 tests, 1 skipped, 0 failures at head `be1838ef8ccf` (verified 2026-10-07).
- On the base code, `testCustomProperties` fails. The restored collection reports `replicationFactor` as a number, and the test expects a string. With this change, it passes.

## A choice to check

**The counts are strings, the type that CREATE already uses. The other route is numbers.**

- Implemented: strings. This matches CREATE, which most collections use, and clients already read the output that way.
- Other route: numbers. This matches the JSON type of the value, but it changes the output for every collection made with CREATE.

Was keeping the CREATE type (strings) the right call, rather than switching every collection to numbers?

## Limits

**The maxShardsPerNode key is not changed, and only the CLUSTERSTATUS output changes.**

- The ticket's example also shows `maxShardsPerNode` as a string for CREATE and as a number for RESTORE. This change does not touch that key. A follow-up can cover it on request.
- Only the CLUSTERSTATUS output changes. The stored cluster state of a restored collection is not changed.
