## What happens today

**The ticket reports a 503 from COLSTATUS on a read-only collection. Current main does not return that error.**

The ticket was filed against 8.11.2. COLSTATUS asks each core for its segment data through `/admin/segments`, and that path asked for an index writer. A read-only core refuses to give one, so the request failed with "Indexing is temporarily disabled". SOLR-18083 changed both index-writer calls in [GetSegmentData.java](https://github.com/nick-boss-tech/solr/blob/14c7aac0d151402b00259e2fb9bf5eed7049ec5d/solr/core/src/java/org/apache/solr/handler/admin/api/GetSegmentData.java#L156) and [at line 260](https://github.com/nick-boss-tech/solr/blob/14c7aac0d151402b00259e2fb9bf5eed7049ec5d/solr/core/src/java/org/apache/solr/handler/admin/api/GetSegmentData.java#L260) so that they do not fail on a read-only core. That commit, f2aaf8769fd, is already on the base of this branch. No test covered the read-only segment path.

## What this change does

**This change adds one regression test and changes no production code.**

The test sets a core to read-only, requests `/admin/segments` with `coreInfo=true`, and checks the segment and core sections of the response. It resets the flag in a `finally` block. COLSTATUS sends the same kind of request to `/admin/segments`, so the test covers the per-core call that COLSTATUS makes.
