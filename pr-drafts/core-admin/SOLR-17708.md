## What happens today

**A v2 request for a JAX-RS API goes through the authorization plugin twice.**

For v2 requests, `HttpSolrCall` runs the authorization plugin before the request reaches Jersey ([HttpSolrCall.java, at the base commit](https://github.com/nick-boss-tech/solr/blob/9b3a84b1c460981eab09d8ffaef776acc4a184f8/solr/core/src/java/org/apache/solr/servlet/HttpSolrCall.java#L480-L485)). When a JAX-RS resource then matches, `SolrRequestAuthorizer` runs the plugin again for that resource ([SolrRequestAuthorizer.java, at the base commit](https://github.com/nick-boss-tech/solr/blob/9b3a84b1c460981eab09d8ffaef776acc4a184f8/solr/core/src/java/org/apache/solr/jersey/SolrRequestAuthorizer.java#L54)). That second check uses the permission name declared on the resource.

## What this change does

**For v2 requests that match no v2 API object and are admin or core requests, the first check is skipped. When a JAX-RS resource matches, the JAX-RS filter is then the only check.**

`V2HttpCall` overrides `shouldAuthorize()` to return false in that case ([V2HttpCall.java](https://github.com/nick-boss-tech/solr/blob/2eceb54730373475e9adfe55bfe555744fb3724a/solr/core/src/java/org/apache/solr/api/V2HttpCall.java#L228-L232)). `HttpSolrCall.shouldAuthorize()` changes from private to protected so the subclass can override it. Nothing else in that method changes.

Behavior change: a v2 path that matches no JAX-RS resource no longer goes through the first check. Jersey answers it with its not-found response, and the authorization plugin is not consulted for it. Non-JAX-RS v2 APIs and v1 requests are unchanged.

## Proof

**The new test fails on the base code and passes with this change. A denied call is still rejected.**

[JaxRsSingleAuthorizationTest](https://github.com/nick-boss-tech/solr/blob/2eceb54730373475e9adfe55bfe555744fb3724a/solr/core/src/test/org/apache/solr/security/JaxRsSingleAuthorizationTest.java#L47-L86) sends a v2 GET to `/cluster/nodes` and counts the authorization calls. On the base code, `testJaxRsApiIsAuthorizedOnce` fails: the plugin runs twice where the test expects once. With this change it passes. `testJaxRsApiDenialStillHolds` passes on the base code too. It guards that a denied call still gets a 403.

Counts at head `2eceb54730`, from the gate of 2026-10-11: JaxRsSingleAuthorizationTest 2 of 2, BasicAuthIntegrationTest 1 of 1, AuditLoggerIntegrationTest 9 of 9.

## Limits

**One route still checks twice, and the new test covers one API.**

- A v2 request for a collection that this node has no replica of goes to an admin route first ([V2HttpCall.java, at the base commit](https://github.com/nick-boss-tech/solr/blob/9b3a84b1c460981eab09d8ffaef776acc4a184f8/solr/core/src/java/org/apache/solr/api/V2HttpCall.java#L166)). That route still runs the first check before Jersey, so a JAX-RS API matched there is still checked twice. This change does not touch that route. A follow-up ticket and PR for it can be opened on request.
- The new test uses one container-level API, `/cluster/nodes`. The new test covers no JAX-RS API under a core.
