## What happens today

**A core never closes its resource loader, so the loader's jars stay open.**

The ticket says `SolrCore` does not close its own `SolrResourceLoader`. That loader holds the class loader for the core's lib directories. Closing it releases those jars, and the ticket notes that open jars cannot be deleted on Windows. At the merge-base commit `cabedd1d968`, the close method ends without any such step ([SolrCore.java lines 1889-1893](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/core/SolrCore.java#L1889-L1893)).

## What this change does

**The core closes its resource loader when the core closes.**

`SolrCore.close()` closes the core's `SolrResourceLoader` after the close hooks run. A failure is logged, and an `Error` is rethrown, the same way the other close steps handle failures ([SolrCore.java lines 1892-1903](https://github.com/nick-boss-tech/solr/blob/3fd85bedef646b5b73c26e26a86a6130b5fc209f/solr/core/src/java/org/apache/solr/core/SolrCore.java#L1892-L1903)).

`SolrResourceLoader.close()` now records that it ran. A package-private `isClosed()` returns that flag, and only the new test calls it ([line 141](https://github.com/nick-boss-tech/solr/blob/3fd85bedef646b5b73c26e26a86a6130b5fc209f/solr/core/src/java/org/apache/solr/core/SolrResourceLoader.java#L141), [lines 912-919](https://github.com/nick-boss-tech/solr/blob/3fd85bedef646b5b73c26e26a86a6130b5fc209f/solr/core/src/java/org/apache/solr/core/SolrResourceLoader.java#L912-L919)).

Once the core closes, its jars are released, so the closed loader should not be used for later class loading. The case that needs checking is listed under Limits.

## Limits

**Not every close path is tested, and one shared-config case is still open.**

- Shared schema: two cores built on one config set, with `shareSchema` on. When one core unloads, the other must still be able to load a lazy lib class. No test in this change runs that case, so the result is unknown.
- The test checks the loader's closed flag. It does not check that the jar files are released.
- The unload and shutdown paths are not tested on their own. The test drives a reload and a direct close.
