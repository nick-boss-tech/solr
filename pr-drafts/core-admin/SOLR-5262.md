## What happens today

**A config that uses `${solr.core.ulogDir}` fails when core.properties does not set ulogDir.**

The implicit `solr.core.*` properties are built only from the values stored in core.properties ([CoreDescriptor.java L248-L255](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/core/CoreDescriptor.java#L248-L255)). When a core leaves a property unset, its implicit value is never filled in. The ticket reports that `${solr.core.ulogDir}` in solrconfig.xml stops Solr from starting unless `ulogDir` is set in core.properties ([JIRA](https://issues.apache.org/jira/browse/SOLR-5262)). A scratch check outside the branch used the same two methods and failed with "No system property or default value specified for solr.core.ulogDir". The code links above point to the base commit `cabedd1d9680`, the code before this change.

## What this change does

**When ulogDir is not set, `solr.core.ulogDir` takes the dataDir value.**

If core.properties has no ulogDir, the implicit property uses the value of `solr.core.dataDir` ([CoreDescriptor.java L254-L258](https://github.com/nick-boss-tech/solr/blob/616efd008b05e01854dee3f90bbe0edd42815fda/solr/core/src/java/org/apache/solr/core/CoreDescriptor.java#L254-L258)). An explicit ulogDir still wins. The update log already falls back to the data directory when no ulogDir is set ([UpdateLog.java L416-L430](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/update/UpdateLog.java#L416-L430), at the base commit), so the tlog location does not change for existing cores. The stored core properties still have no ulogDir entry, and `getUlogDir()` still returns null. Before this change, the only way to make the config load was to set `ulogDir` in core.properties, which is the workaround the ticket describes. That workaround still works.

## Proof

**The new test fails on the base code and passes with this change.**

- `TestCoreDescriptorImplicitProperties` 3 of 3 at head `616efd008b05`, verified 2026-10-11. The new case `testUlogDirDefaultsToDataDir` fails on the base code, where the ulogDir value is null. The other two cases pass on the base code too.
- The base run used the base `CoreDescriptor.java` with the new test kept: 3 tests, 1 failure, with `expected:<data/> but was:<null>`.

## Limits

**The check covers property substitution, not a full core load.**

- A full core load of a config that uses `${solr.core.ulogDir}` was not run. The base failure was shown at the substitution step.
- The default is the configured dataDir value as written. When dataDir is relative, the default is relative too, the same as `solr.core.dataDir` already is.
- Explicit ulogDir values behave as before.
