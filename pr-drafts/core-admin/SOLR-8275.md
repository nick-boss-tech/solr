## What happens today

**A PREPRECOVERY timeout reports only "Timeout waiting for collection state."**

A replica asks its leader to wait until the replica reaches a given state ([RecoveryStrategy.java L959-L989](https://github.com/nick-boss-tech/solr/blob/e52e10fa50a374196d2c6adea26e5e55e37cdf57/solr/core/src/java/org/apache/solr/cloud/RecoveryStrategy.java#L959-L989)). When that wait times out, the message names neither the replica nor the state the leader last saw. The message in the ticket says the node was asked to wait for "recovering" and then says it sees "recovering," which reads as a contradiction ([JIRA](https://issues.apache.org/jira/browse/SOLR-8275)).

## What this change does

**The timeout message now names the replica, the wait settings, and the last state seen.**

Each check of the wait records what it saw, and the final error uses the last record ([PrepRecoveryOp.java L85](https://github.com/nick-boss-tech/solr/blob/e52e10fa50a374196d2c6adea26e5e55e37cdf57/solr/core/src/java/org/apache/solr/handler/admin/PrepRecoveryOp.java#L85), [L119-L123](https://github.com/nick-boss-tech/solr/blob/e52e10fa50a374196d2c6adea26e5e55e37cdf57/solr/core/src/java/org/apache/solr/handler/admin/PrepRecoveryOp.java#L119-L123), [L166-L172](https://github.com/nick-boss-tech/solr/blob/e52e10fa50a374196d2c6adea26e5e55e37cdf57/solr/core/src/java/org/apache/solr/handler/admin/PrepRecoveryOp.java#L166-L172), [L224-L237](https://github.com/nick-boss-tech/solr/blob/e52e10fa50a374196d2c6adea26e5e55e37cdf57/solr/core/src/java/org/apache/solr/handler/admin/PrepRecoveryOp.java#L224-L237)). The text has this form: the wait time in milliseconds, the replica, the collection, the target state, the checkLive flag, and then "last seen" with the recorded state. The error code and the HTTP status do not change. Only the message text changes.

## Proof

**The new test fails on the base code and passes with this change.**

- `TestPrepRecovery` 3 of 3 at head `e52e10fa50a3` (verified 2026-10-06). The new test, `testTimeoutMessageNamesLastSeenState`, fails on the base code: the message is the bare text and does not name the replica. It passes with this change. The two existing tests pass on the base code too.

## Limits

**Two message variants share this code path, and neither has a test.**

- Only the timeout path changed. No other message changed.
- "Last seen" is the last check before the timeout. A state that changed and changed back between two checks is not shown.
- Two message variants share this code and have no test: the text for a shard that is not in the cluster state, and the suffix added when `onlyIfLeaderActive` is set and the local core is not active.
