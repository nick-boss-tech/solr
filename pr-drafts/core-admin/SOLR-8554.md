## What happens today

**FORCELEADER reports success when no active leader appears, and a removed shard fails with a generic error.**

After it updates the shard's terms, FORCELEADER checks the shard up to nine times, five seconds apart ([ForceLeader.java L132-L146](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/handler/admin/api/ForceLeader.java#L132-L146)). If no active leader shows up, the code logs at INFO that the force did not succeed and returns normally, so the caller gets a success response ([L154-L160](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/handler/admin/api/ForceLeader.java#L154-L160)). If the shard or collection disappears during the wait, the code dereferences a null value and throws a NullPointerException ([L137-L139](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/handler/admin/api/ForceLeader.java#L137-L139)). The outer catch wraps that as "Error executing FORCELEADER operation" ([L163-L170](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/handler/admin/api/ForceLeader.java#L163-L170)). An interrupt goes through the same catch, and the thread's interrupt flag is not restored. The links point to the base commit `cabedd1d9680`, the code before this change.

## What this change does

**FORCELEADER now returns an error when no active leader appears, when the shard is removed, and when the wait is interrupted.**

The wait moves into a helper that throws on each of these cases ([ForceLeader.java L96-L136](https://github.com/nick-boss-tech/solr/blob/1e8a8a4b6bf0d8a2ccfa0552ecececee1a384a79/solr/core/src/java/org/apache/solr/handler/admin/api/ForceLeader.java#L96-L136)). A timeout throws a SolrException that names the collection, the shard and the last state seen ([L126-L135](https://github.com/nick-boss-tech/solr/blob/1e8a8a4b6bf0d8a2ccfa0552ecececee1a384a79/solr/core/src/java/org/apache/solr/handler/admin/api/ForceLeader.java#L126-L135)), so a timed-out call now returns a 500 error. A removed shard throws its own SolrException ([L107-L115](https://github.com/nick-boss-tech/solr/blob/1e8a8a4b6bf0d8a2ccfa0552ecececee1a384a79/solr/core/src/java/org/apache/solr/handler/admin/api/ForceLeader.java#L107-L115)). An interrupt restores the flag and is wrapped in a SolrException ([L203-L211](https://github.com/nick-boss-tech/solr/blob/1e8a8a4b6bf0d8a2ccfa0552ecececee1a384a79/solr/core/src/java/org/apache/solr/handler/admin/api/ForceLeader.java#L203-L211)).

- `ForceLeaderWaitTest` 3 of 3 at head `1e8a8a4b6b`, verified 2026-10-14 (same code as `654c1a7c3570`, verified 2026-10-11). The three cases are `testReturnsOnceLeaderIsActive`, `testFailsWhenNoActiveLeaderAppears` and `testFailsWhenShardIsRemoved`.

The compiler reports three "cannot find symbol" errors, at lines 52, 63 and 73 of the [test](https://github.com/nick-boss-tech/solr/blob/1e8a8a4b6bf0d8a2ccfa0552ecececee1a384a79/solr/core/src/test/org/apache/solr/handler/admin/api/ForceLeaderWaitTest.java#L52-L73). This is the expected result for a new helper. It does not show the old behavior by a test result.

## A choice to check

**A timed-out FORCELEADER now returns an error. Keeping the old success response is the other route.**

- Implemented: a timeout throws, so the caller gets a 500 error and learns that no leader came up.
- Other route: keep the old behavior, log the timeout, and return success. Existing callers then see no new error, but they cannot tell that the forced leader never appeared.

Was returning an error on timeout the right call?

## Limits

**The Overseer move and the async option are not done, and the cloud test was not run.**

- This does not move FORCELEADER or REBALANCELEADER into the Overseer, and it adds no async option. The ticket stays open for those.
- A timed-out FORCELEADER still makes its shard term changes first, so terms can change even when the call returns an error.
- The cloud test `ForceLeaderTest` was not run for this change.
- The shard-removed case is checked with a mock in the unit test, not in a running cluster. The interrupt case has no test.
