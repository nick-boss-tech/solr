## What happens today

**Creating a collection with a name that a collection or an alias already has is rejected, but no test checks the error message for that.**

The create path, which this branch does not change, rejects a name taken by a collection with "collection already exists: <name>", and a name taken by an alias with "collection alias already exists: <name>" ([CreateCollectionCmd.java L127-L135](https://github.com/nick-boss-tech/solr/blob/b6b2b8f10e9827e3b86e44649fb7966ce646c185/solr/core/src/java/org/apache/solr/cloud/api/collections/CreateCollectionCmd.java#L127-L135)). The link points at the base commit, `b6b2b8f10e9827e3b86e44649fb7966ce646c185`, which is the merge-base. No test in `CollectionsAPISolrJTest` checks either message for a create. The ticket asks for tests of this path ([JIRA](https://issues.apache.org/jira/browse/SOLR-8576)).

## What this change does

**One new test covers both name collisions, and it checks that the rejected creates leave the original collection in place and add no collection named like the alias.**

This is a test-only change. The create path is not changed ([CollectionsAPISolrJTest.java L1157-L1192](https://github.com/nick-boss-tech/solr/blob/883bb522caf97ca59f5303117efa81d1ec12dbfe/solr/core/src/test/org/apache/solr/cloud/CollectionsAPISolrJTest.java#L1157-L1192)). The test creates a collection and an alias. It then tries to create a collection with each name. Both creates must fail with the existing message. After that, it checks that the original collection still exists under its name and that the alias still resolves to it.

## Proof

- `testCreateCollectionNameAlreadyTaken` passed on the base commit `b6b2b8f10e` (1 test, 0 failures, recorded 2026-10-12). It checks error behavior that already exists, so it does not show a failure before the change. Its value is the coverage it adds.

## Limits

**The limits are narrow: name collisions only, and the checks match error text.**

- Only creates with a name that is already taken are covered. Other create errors are not.
- The checks match only the message text and accept any exception type, so the error code is not checked. A change to that text needs a matching test change.
