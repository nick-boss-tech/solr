## What happens today

**A core fails to start when its index directory holds only a leftover write.lock.**

Core creation decides whether an index exists by calling `exists()` on the directory. That call returns true when the directory has any entry ([CachingDirectoryFactory.java L368-L377](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/core/CachingDirectoryFactory.java#L368-L377)). A directory holding only `write.lock` therefore counts as an index. Core creation then opens a writer on it and fails, because there is no segments file. The error reads "no segments* file found in LockValidatingDirectoryWrapper ... files: [write.lock]" ([SolrCore.java L857-L866](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/core/SolrCore.java#L857-L866)). A process that ends while it still holds an index writer can leave such a directory behind. The links point to the base commit `cabedd1d9680`, the code before this change. The ticket's own case, an existing empty index directory, already works on main, because an empty directory has no entries.

## What this change does

**A directory whose only file is write.lock is treated as having no index, so a new index is created.**

A new check counts the files in the directory and returns true only when the one file is `write.lock` ([SolrCore.java L856-L868](https://github.com/nick-boss-tech/solr/blob/2e56ce9990b008c00d2d07b2498cf28cdc101a06/solr/core/src/java/org/apache/solr/core/SolrCore.java#L856-L868)). `initIndex` uses that check to decide whether an index exists ([L870-L874](https://github.com/nick-boss-tech/solr/blob/2e56ce9990b008c00d2d07b2498cf28cdc101a06/solr/core/src/java/org/apache/solr/core/SolrCore.java#L870-L874)). A directory with any other file, or with no file, behaves as before.

## Proof

**The new test fails on the base code and passes with this change.**

- `TestCoreContainer` 26 tests, 3 skipped, 0 failures at head `2e56ce9990b0`, verified 2026-10-11. The new test is `testCreateCoreOverIndexDirWithOnlyWriteLock` ([TestCoreContainer.java L116-L146](https://github.com/nick-boss-tech/solr/blob/2e56ce9990b008c00d2d07b2498cf28cdc101a06/solr/core/src/test/org/apache/solr/core/TestCoreContainer.java#L116-L146)). It selects the on-disk directory factory, because the default test factory does not see files on disk.
- On the base code, with the same test, the run is 26 tests, 3 skipped, 1 failure. The failure is the new test, a SolrException at core creation with "no segments* file found".

## A choice to check

**The fix is in Solr. The other route is a fix in Lucene.**

- Implemented: Solr treats a write.lock-only directory as empty and creates a new index.
- Other route: fix the Lucene side, as a 2017 comment on the ticket argues. That keeps the rule in one place, but it waits on a Lucene change.

Was the Solr-side fix the right call?

## Limits

**Only the write.lock-only case is covered. The empty directory case already works on main.**

- The check opens the directory with lock type "none", and the directory cache keeps the first lock type it sees. A reviewer may ask for the configured lock type, or for the check to run under the lock.
- A directory with write.lock plus any other file is not changed.
