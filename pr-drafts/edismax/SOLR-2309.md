## What happens today

**A fuzzy stopword stays in the query. The same word without the tilde is dropped.**

With `qf=name`, the query `xyz~0.5^100 Gmbh~0.5^100` parses to `+((DisjunctionMaxQuery((name:xyz~0.5)^100.0) DisjunctionMaxQuery((name:Gmbh~0.5)^100.0))~2)`. The query `xyz^100 Gmbh^100` parses to `+DisjunctionMaxQuery((name:xyz)^100.0)`. The ticket treats `Gmbh` as a stopword.

## What this change does

**A fuzzy term is dropped when the field's query analyzer removes all of its text.**

- In the fuzzy case, the field's query analyzer runs first. If it leaves no tokens, the case returns no query ([fuzzy case](https://github.com/nick-boss-tech/solr/blob/06f5a1c4a87eef0fed17435e8d30bbc422079119/solr/core/src/java/org/apache/solr/search/ExtendedDismaxQParser.java#L1480-L1485)).
- The analyzer follows `stopwords=false` in the same way the plain term does ([analysis check](https://github.com/nick-boss-tech/solr/blob/06f5a1c4a87eef0fed17435e8d30bbc422079119/solr/core/src/java/org/apache/solr/search/ExtendedDismaxQParser.java#L1498-L1517)). Only text fields are checked, so string fields and numeric fuzzy queries behave as before.
- Behavior change: a fuzzy term that the analyzer removes is no longer searched. Before, it matched approximately. A query where every term is a stopword keeps its fuzzy terms. With `alwaysStopwords=true`, a lone fuzzy stopword gives no matches.

## Limits

**We did not check prefix and wildcard terms.**

- Those terms are not changed here. If a maintainer wants the same check there, we will open a follow-up ticket and PR.
- The check adds one analysis pass for each fuzzy term and each `qf` field. We did not measure its cost.
