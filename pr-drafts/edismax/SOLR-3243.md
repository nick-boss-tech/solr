## What happens today

**An unfielded `[* TO *]` expands into one open range per qf field, so only documents with a value in one of those fields match.**

edismax sends a range with no field name through the same per-field expansion as a fielded range. The report shows the result: `+DisjunctionMaxQuery((content:[* TO *]^2.0 | id:[* TO *]^50.0 | author:[* TO *]^15.0 | meta:[* TO *]^10.0 | name:[* TO *]^20.0))` ([SOLR-3243](https://issues.apache.org/jira/browse/SOLR-3243)). A document with no value in any of those fields does not match. The reporter also noted that open ranges on string fields are costly, and that the expansion repeats for every field.

## What this change does

**An unfielded inclusive `[* TO *]` becomes a match all docs query, the same as a bare `*`. Every document matches, including one with no value in any qf field.**

This is wider than the old result, and it is intended. The parser already reads a bare `*` as match all when no field is given. The check is in [`getRangeQuery`, L1135-L1139](https://github.com/nick-boss-tech/solr/blob/1db99c13662d8f827511a5d3a51763d7e1e2ee4c/solr/core/src/java/org/apache/solr/search/ExtendedDismaxQParser.java#L1135-L1139). It applies only when no field is given and both ends are open. A fielded range such as `id:[* TO *]` keeps its meaning. A bounded range such as `[a TO z]` still expands over the qf fields.

## Proof

**Three new tests fail on the base code and pass with this change.**

- `TestExtendedDismaxParser`: 42 of 42 pass at head `1db99c13662d8f827511a5d3a51763d7e1e2ee4c`, verified 2026-10-07.
- The three new tests are `testUnfieldedOpenRangeIsMatchAllDocs`, `testUnfieldedOpenRangeMatchesDocWithoutQfValue`, and `testUnfieldedOpenRangeWithPhraseFields` ([test file](https://github.com/nick-boss-tech/solr/blob/1db99c13662d8f827511a5d3a51763d7e1e2ee4c/solr/core/src/test/org/apache/solr/search/TestExtendedDismaxParser.java#L162-L246)).
- On the base code (`97d973814336`), the same class runs 42 tests and exactly these three fail.

## A choice to check

**The implemented reading is that an unfielded `[* TO *]` means every document.**

The other option is the literal-token reading. The first patch on this ticket took that route. It turned an unfielded range into literal field queries for its tokens. The cost of the chosen reading is a compatibility change: a document with no value in any qf field now matches. Was matching every document the right reading of an unfielded inclusive range?

## Limits

**The negated form changes too, and the exclusive forms still expand per field.**

- `-[* TO *]` now excludes every document, as `-*` already does. Before, it excluded only documents with a value in a qf field.
- The exclusive forms `{* TO *}`, `[* TO *}`, and `{* TO *]` keep the old per-field expansion. Only the inclusive form changes.
- The phrase fields still see the text of an unfielded range, so pf can add an optional boost phrase built from that text. A later change can skip range text the same way the match all query is skipped. I can open that follow-up if maintainers want it.
