## What happens today

**On the base code, a lone parenthesis reaches the `pf` phrase text as `?` characters.**

Edismax builds phrase boosts from the plain words of the query. On the base code, the loop skips only fielded clauses, phrases, and the words AND, OR, NOT and TO. A bare clause that is only a parenthesis is not skipped ([ExtendedDismaxQParser.java L308-L316, merge-base commit](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/search/ExtendedDismaxQParser.java#L308-L316)). The new test uses the query `( id:s0 ) (zzzz xxxx)` with `qf=phrase_sw` and `pf=phrase_sw^10`. The base parsed query is in Proof.

## What this change does

**A bare parenthesis clause is left out of the phrase text, so the words on either side sit next to each other in that phrase.**

The loop that builds the phrase text now skips a bare clause whose raw text is only parentheses ([ExtendedDismaxQParser.java L310-L317, head](https://github.com/nick-boss-tech/solr/blob/723f61ee4ab7438220193db0c39dad32601dfe07/solr/core/src/java/org/apache/solr/search/ExtendedDismaxQParser.java#L310-L317)). The check is a helper that accepts only `(` and `)` characters ([L356-L363](https://github.com/nick-boss-tech/solr/blob/723f61ee4ab7438220193db0c39dad32601dfe07/solr/core/src/java/org/apache/solr/search/ExtendedDismaxQParser.java#L356-L363)).

Behavior change: for the query in the new test, the base phrase text holds two `?` placeholders before `zzzz xxxx`. At this head it holds none, and the new test's checks pass (see Proof). Fielded clauses, quoted phrases, and the words AND, OR, NOT and TO are handled as before.
