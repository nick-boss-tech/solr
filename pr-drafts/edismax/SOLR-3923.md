## What happens today

**On the base code, a parenthesis on its own reaches the phrase boosts for `pf`, `pf2` and `pf3`.**

Edismax builds phrase boosts from the plain words of the query. On the base code, a bare clause that is only a parenthesis is treated as one of those words, so the parenthesis goes into the phrase text ([ExtendedDismaxQParser.java L308-L316, base commit](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/search/ExtendedDismaxQParser.java#L308-L316)). An example is `( cat:foo ) bar`, where the two parentheses sit beside plain words.

## What this change does

**A bare parenthesis clause is left out of the phrase text, so the words on either side sit next to each other in that phrase.**

The loop that builds the phrase text now skips a bare clause whose text is only parentheses ([ExtendedDismaxQParser.java L310-L317, head](https://github.com/nick-boss-tech/solr/blob/723f61ee4ab7438220193db0c39dad32601dfe07/solr/core/src/java/org/apache/solr/search/ExtendedDismaxQParser.java#L310-L317)). The check is a helper that accepts only `(` and `)` characters ([L356-L363](https://github.com/nick-boss-tech/solr/blob/723f61ee4ab7438220193db0c39dad32601dfe07/solr/core/src/java/org/apache/solr/search/ExtendedDismaxQParser.java#L356-L363)).

Behavior change: for `a ( b ) c`, the phrase text on the base code keeps the two parentheses. With this change the phrase reads `a b c`. Fielded clauses, quoted phrases, and the words AND, OR, NOT and TO are handled as before.
