## What happens today

**With `pf`, `pf2`, or `pf3` set, the match all query `*:*` is analyzed as phrase text, and hit scores move away from 1.0.**

The phrase step builds a phrase clause from each bare clause, and `*:*` is one of them. A tokenizer that splits `*:*` into several tokens turns it into a phrase such as `"* : *"`. The report shows the debug output `(+MatchAllDocsQuery(*:*) DisjunctionMaxQuery((name:"* : *")))` and hit scores of about 0.07 ([SOLR-3962](https://issues.apache.org/jira/browse/SOLR-3962)). A match all query should score every hit 1.0.

## What this change does

**The phrase step skips a clause that is a match all query, so no phrase is built from its text.**

`addPhraseFieldQueries` now skips a bare clause when `isMatchAllDocsClause` says it is `*:*` ([ExtendedDismaxQParser.java, L309-L310](https://github.com/nick-boss-tech/solr/blob/e7d5f350503516dc5a01211cb28917835af64a0b/solr/core/src/java/org/apache/solr/search/ExtendedDismaxQParser.java#L309-L310)). The check accepts a leading `+` or `-`, grouping parentheses, and a plain-number boost, in any combination ([L358-L427](https://github.com/nick-boss-tech/solr/blob/e7d5f350503516dc5a01211cb28917835af64a0b/solr/core/src/java/org/apache/solr/search/ExtendedDismaxQParser.java#L358-L427)). If no clause is left to build a phrase from, the method returns early ([L319-L320](https://github.com/nick-boss-tech/solr/blob/e7d5f350503516dc5a01211cb28917835af64a0b/solr/core/src/java/org/apache/solr/search/ExtendedDismaxQParser.java#L319-L320)). The main query is not changed.

## Limits

**Range text is still analyzed, and a typed escape is skipped too.**

- The text of an unfielded range such as `[* TO *]` still reaches the phrase analyzers. SOLR-3243 changes what that range matches. The phrase step for range text is a separate case, and I can open a follow-up for it if maintainers want it.
- The check undoes the `\:` escape for every clause, so a typed `*\:*` is also skipped by the phrase step. The main query still reads it as text.
