## What happens today

**An unfielded regular expression clause in edismax does not search the qf fields.**

With `defType=edismax` and `qf=name`, the query `/.*apper/` is built on an internal placeholder field name instead of `name`. The parsed query then shows the placeholder character U+FFFC. The ticket reports zero hits for a regular expression query. The same leak appears when the qf field is reachable only through a `*` dynamic field, as in the ticket's setup.

Edismax has no regular expression override, so the clause goes straight to [`SolrQueryParserBase.getRegexpQuery`](https://github.com/nick-boss-tech/solr/blob/a41bb034a1f47c08a8f8ea6ebbe46e6d443cbb6f/solr/core/src/java/org/apache/solr/parser/SolrQueryParserBase.java#L1333) with the placeholder field.

## What this change does

**Regular expression clauses now go through the same qf aliasing that wildcard and prefix clauses already use.**

The change adds a `REGEXP` query type ([enum](https://github.com/nick-boss-tech/solr/blob/a41bb034a1f47c08a8f8ea6ebbe46e6d443cbb6f/solr/core/src/java/org/apache/solr/search/ExtendedDismaxQParser.java#L962)), a `getRegexpQuery` override that follows `getWildcardQuery` ([L1162-L1169](https://github.com/nick-boss-tech/solr/blob/a41bb034a1f47c08a8f8ea6ebbe46e6d443cbb6f/solr/core/src/java/org/apache/solr/search/ExtendedDismaxQParser.java#L1162-L1169)), and a dispatch case in `getQuery` ([L1487-L1488](https://github.com/nick-boss-tech/solr/blob/a41bb034a1f47c08a8f8ea6ebbe46e6d443cbb6f/solr/core/src/java/org/apache/solr/search/ExtendedDismaxQParser.java#L1487-L1488)).

Each qf field gets its own regular expression query. A qf list of N fields therefore builds N queries for each regular expression clause. Wildcard and prefix clauses already work this way. A bare regular expression clause that found no documents before now matches through the qf fields.

## Proof

`TestExtendedDismaxParser`: 41 of 41 pass at head `a41bb034a1f47c08a8f8ea6ebbe46e6d443cbb6f` (verified 2026-10-07).

On base `14c7aac0d151402b00259e2fb9bf5eed7049ec5d`, 2 of the 41 tests fail. They are `testRegexQueryUsesQueryFieldsNotImpossibleFieldName` and `testRegexQueryWithQfFieldFromDynamicField`, both added by this change.

## Limits

**One qf shape has no test.**

A qf field whose type cannot take regular expression text reaches the existing `catch` in `getQuery`, which returns null for that clause ([L1496-L1500](https://github.com/nick-boss-tech/solr/blob/a41bb034a1f47c08a8f8ea6ebbe46e6d443cbb6f/solr/core/src/java/org/apache/solr/search/ExtendedDismaxQParser.java#L1496-L1500)). No test covers that case. If maintainers want numeric or point fields in qf covered, a test can come in a follow-up PR.
