## What happens today

**A request that uses edismax with neither `qf` nor `df` gets a 500 server error.**

With `defType=edismax` and no `qf` or `df` parameter, Solr answers HTTP 500. A missing parameter is a client error, so the status is wrong. The parser reads `qf` and `df` when it builds its configuration. The missing parameter raises a `SyntaxError`. Before this change, the code wrapped that error in a plain `RuntimeException` on [line 1733](https://github.com/nick-boss-tech/solr/blob/4664014a919cc30448b784a5d8998c6536f69d55/solr/core/src/java/org/apache/solr/search/ExtendedDismaxQParser.java#L1733). The error text survived only as part of the wrapper's message.

## What this change does

**The same error now comes back as a 400 Bad Request, with the same message.**

The code wraps the `SyntaxError` in a `SolrException` with the `BAD_REQUEST` code ([line 1733](https://github.com/nick-boss-tech/solr/blob/4664014a919cc30448b784a5d8998c6536f69d55/solr/core/src/java/org/apache/solr/search/ExtendedDismaxQParser.java#L1733)). The message is `Neither qf nor df are present.` The change covers every edismax parser built without `qf` or `df`. That includes edismax local parameters, such as `{!edismax}` inside a filter query, not only the main query. Other parsers are unchanged.

## Proof

**The new test fails on the base code and passes at this head.**

`TestExtendedDismaxParser`: 40 of 40 pass at head `4664014a919cc30448b784a5d8998c6536f69d55` (verified 2026-10-09). On the base code, with the new test in place, 1 of 40 fails: `testNeitherQfNorDfIsBadRequest` ([test](https://github.com/nick-boss-tech/solr/blob/4664014a919cc30448b784a5d8998c6536f69d55/solr/core/src/test/org/apache/solr/search/TestExtendedDismaxParser.java#L994-L1002)). The base code throws a plain `RuntimeException`, so the expected `SolrException` check fails there. The test calls `QParser.getParser` with `defType=edismax` and no `qf` or `df`, then checks the 400 code and the message.

## Limits

**The test stops at the parser, and edismax still reads its parameters at build time.**

The test checks the exception code, not the HTTP response. Edismax reads `qf` and `df` while it builds the parser. DisMax reads them in `parse()` ([DisMaxQParser.java line 88](https://github.com/nick-boss-tech/solr/blob/4664014a919cc30448b784a5d8998c6536f69d55/solr/core/src/java/org/apache/solr/search/DisMaxQParser.java#L88)). The ticket raised this placement, and this change keeps it. I can open a follow-up ticket and PR for it if maintainers want one.
