## What happens today

A test node that is stopped and then started again on the same port can fail to start. `JettySolrRunner` gives up its port when it stops and holds nothing in its place. If another process takes that port during the gap, the restart fails with `java.net.BindException: Address already in use`. The retry only tries the same port, and it stops after 60 seconds. `LeaderElectionIntegrationTest.testSimpleSliceLeaderElection` hit this once in CI, on an unrelated pull request. No assertion ran.

## What this change does

When a runner stops, it binds a socket to its port on 127.0.0.1 and keeps it. The next start on that port closes the socket before Jetty binds the port. The sockets live in a static map, so a new runner for the same port sees them. `MiniSolrCloudCluster.shutdown()` closes the sockets for its runners after the stops finish. [HOLD: shutdown covers only runners still in the cluster's list. See Limits.]

This is a test-framework change only. Behavior changes: a stopped runner keeps its port bound, so nothing else can bind that port until the node starts on it again or the cluster shuts down.

## A choice to check

Two routes. This change holds the port in the framework, so restarts keep the same port, node names and test code. Or the one affected test could restart its node on a fresh port. That needs no reservation, but node names then change with the port, and the test compares node names. The cost of this change is one bound socket per stopped node. Was holding the port the right call?
