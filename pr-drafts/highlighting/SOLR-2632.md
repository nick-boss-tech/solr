## What happens today

**The reported failure did not reproduce on the base code.**

SOLR-2632 reports that highlighting does not work when an embedded `{!boost}` query boosts a dismax query. In checks run on 2026-10-06, a `{!boost}`-wrapped query highlighted the wrapped term for the `original` and `fastVector` methods. That run used the base code, without the branch's production changes.

The base code has no branch for `FunctionScoreQuery` ([DefaultSolrHighlighter.java, lines 298 to 303](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/highlight/DefaultSolrHighlighter.java#L298-L303), at the merge-base commit). Lucene 10.4.0 already handles that query type. Its `WeightedSpanTermExtractor.extract` and `FieldQuery.flatten` both unwrap it, as checked in the bytecode.

## What this change does

**It adds a regression test and changes no production code.**

It adds `testHighlightQueryWrappedInBoost` to [HighlighterTest.java](https://github.com/nick-boss-tech/solr/blob/1d7018f3fd7b94ad1a9858df8eb1af4843107bf8/solr/core/src/test/org/apache/solr/highlight/HighlighterTest.java#L1423-L1447). The query is `+id:1 +_query_:"{!boost b=3 v=$qq}"`. The test checks the wrapped term for the `original` and `fastVector` methods. It also adds the `unified` method as a third case.

The branch also has two production edits in [DefaultSolrHighlighter.java](https://github.com/nick-boss-tech/solr/blob/1d7018f3fd7b94ad1a9858df8eb1af4843107bf8/solr/core/src/java/org/apache/solr/highlight/DefaultSolrHighlighter.java#L303-L305) and [lines 566 to 571](https://github.com/nick-boss-tech/solr/blob/1d7018f3fd7b94ad1a9858df8eb1af4843107bf8/solr/core/src/java/org/apache/solr/highlight/DefaultSolrHighlighter.java#L566-L571). They are left out, because Lucene already does the same unwrapping.

## Proof

**The test passes on the base code by design, so it is not a fail-before proof.**

`HighlighterTest.testHighlightQueryWrappedInBoost`: 1/1 at head `1d7018f3fd7b`, and 1/1 on base with only this test file. Verified 2026-10-06. The `unified` case passed 1/1 on base in a scratch copy on 2026-10-06. It is not yet in the committed test, so it needs a fresh run at the final head.

## Limits

**No defect is claimed, and this change fixes nothing.**

- The dismax form from the ticket is not in the test. The test uses the standard query parser, and the recorded checks do not show the dismax form.
- Lucene 9.12.3 (branch_9x) was not checked for the highlighter code, so this change makes no claim for that line. main and branch_10x use Lucene 10.4.0.
- If the dismax form fails on current main, we can open a follow-up ticket and PR for it on request.
