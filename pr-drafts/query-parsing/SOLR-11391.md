## What happens today

**An unknown `method` value in a join query's local params fails as a server error.**

A query such as `{!join from=dept_ss to=dept_id_s method=nosuchmethod}title_s:MTS` reaches [`Method.valueOf`, as it stood before this change](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/search/JoinQParserPlugin.java#L221) in the join query parser. An unknown name throws `IllegalArgumentException`, which is not handled. The request answers with a server error (HTTP 500). A bad parameter value is a client error, so it should answer HTTP 400. Another entry point in the same file already maps an unknown method name to HTTP 400.

## What this change does

**The local-param path now uses the same 400 helper as that other entry point.**

The parser calls [`parseMethodString`](https://github.com/nick-boss-tech/solr/blob/b0f15a22856a887d4e369cd1542c0ce09a687059/solr/core/src/java/org/apache/solr/search/JoinQParserPlugin.java#L220), which turns an unknown name into a 400 error with the message "Provided join method '<name>' not supported". Valid method names behave as before. Behavior change: an unknown `method` local param now answers 400 instead of 500, and the error message changes.

## Proof

**One new test fails on the base code and passes with this change.**

- [`TestScoreJoinQPNoScore.testUnknownJoinMethodIsBadRequest`](https://github.com/nick-boss-tech/solr/blob/b0f15a22856a887d4e369cd1542c0ce09a687059/solr/core/src/test/org/apache/solr/search/join/TestScoreJoinQPNoScore.java#L61-L68) fails on the base code with a 500 where 400 is expected.
- It passes with this change. TestScoreJoinQPNoScore: 5 of 5; at head b0f15a22856.

## Limits

- Only the `method` local param of the join query parser changes. Valid method names are not affected.
- The change does not alter how a join method is chosen. No timing was measured.
- Other error paths for join parameters are not covered by the new test.
