## What happens today

**A query parser that has parsed a query with an unterminated comment fails on later queries that contain a valid comment.**

The ticket repro calls `parse()` on one parser instance in this order: `/*` (correctly rejected), `/* foo */ bar` (wrongly rejected), `bar` (accepted), and `/* foo */ bar` (still rejected). The lucene parser creates a new `SolrQueryParser` for each query ([LuceneQParser.java](https://github.com/nick-boss-tech/solr/blob/41893ee9ce6101224f46e0287a1f2f0bfe6a6974/solr/core/src/java/org/apache/solr/search/LuceneQParser.java#L42)), so a normal request does not reuse a parser. The problem shows only when code reuses one parser instance for several queries.

## What this change does

**Each parse call starts from a new token manager.**

The generated token manager keeps a comment nesting count, and `ReInit(CharStream)` does not reset it ([QueryParserTokenManager.java](https://github.com/nick-boss-tech/solr/blob/41893ee9ce6101224f46e0287a1f2f0bfe6a6974/solr/core/src/java/org/apache/solr/parser/QueryParserTokenManager.java#L25)). `parse()` now creates a new `QueryParserTokenManager` and passes it to a new `ReInit(QueryParserTokenManager)` method on the base class ([SolrQueryParserBase.java](https://github.com/nick-boss-tech/solr/blob/41893ee9ce6101224f46e0287a1f2f0bfe6a6974/solr/core/src/java/org/apache/solr/parser/SolrQueryParserBase.java#L238-L245)). The generated parser overrides that method. The cost is one small object per parse call, which was not measured.

## Proof

**The new test fails on the base code and passes with this change.**

- [TestSolrQueryParser.testCommentsAfterSyntaxError](https://github.com/nick-boss-tech/solr/blob/41893ee9ce6101224f46e0287a1f2f0bfe6a6974/solr/core/src/test/org/apache/solr/search/TestSolrQueryParser.java#L545-L559) is new and fails on the base code. Verified 2026-10-05 at head 41893ee9ce6101224f46e0287a1f2f0bfe6a6974: TestSolrQueryParser 38 of 38, TestExtendedDismaxParser 39 of 39, SolrQueryParserBaseTest 7 of 7, and TestReversedWildcardFilterFactory 5 of 5 pass.

## A choice to check

**A new token manager per parse, or a reset inside the grammar's generated token manager.**

The other route resets the comment count when the generated token manager is reinitialized. That change edits the grammar and needs the checked-in generated file regenerated. This change needs no regeneration. It adds a public method to the base class and one object per parse. Was a new token manager per parse the right fix, or should the grammar reset the comment count?

## Limits

**Code that calls the generated parser's `ReInit(CharStream)` directly keeps the old behavior.**

No code under `solr/core` makes that call outside the parser itself. A parser that is used once per query behaves as before.
