## What happens today

**The ticket reports an out of memory error for a query made of about 4,900 asterisks.**

The ticket reports that edismax runs out of memory when `q` is made of 4888 `*` characters, on Solr 7.2.1 and 7.4. It gives no other reproduction detail. This change does not reproduce the error on the current code, so the reported failure is still unconfirmed.

## What this change does

**Runs of unescaped `*` in a wildcard term are collapsed into one `*`. The terms matched do not change.**

[SolrQueryParserBase.java](https://github.com/nick-boss-tech/solr/blob/d1dd8a1f9f0aa17c6e34f8c5e40cb9768a83aea2/solr/core/src/java/org/apache/solr/parser/SolrQueryParserBase.java#L1271) adds `collapseRepeatedWildcards`. [`getWildcardQuery`](https://github.com/nick-boss-tech/solr/blob/d1dd8a1f9f0aa17c6e34f8c5e40cb9768a83aea2/solr/core/src/java/org/apache/solr/parser/SolrQueryParserBase.java#L1305) calls it first. An escaped star such as `\*` is kept as a literal. For example, `a**b` and `a*b` match the same strings.
