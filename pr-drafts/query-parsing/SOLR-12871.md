## What happens today

**A childfield() sort on a field that needs rewriting fails with a 400 whose message blames the field.**

Sorting with `childfield(amount,$q) desc`, where `amount` is a `CurrencyFieldType` field, fails. The ticket reports Lucene's `UnsupportedOperationException` ("Sort type REWRITEABLE is not supported") from `ToParentBlockJoinSortField`. It was filed against 6.6. On main the sort is still built. `SortSpecParsing` catches the error and returns a 400 with "sort param could not be parsed as a query, and is not a field that exists in the index" ([parse loop](https://github.com/nick-boss-tech/solr/blob/c79a49320cdb0390a9ae7118ab70efbf080826d7/solr/core/src/java/org/apache/solr/search/SortSpecParsing.java#L112-L126), [message](https://github.com/nick-boss-tech/solr/blob/c79a49320cdb0390a9ae7118ab70efbf080826d7/solr/core/src/java/org/apache/solr/search/SortSpecParsing.java#L157-L164)). The field does exist, so the message misleads. The real cause is only in the error's cause chain.

## What this change does

**The child-field sort parser rejects a REWRITEABLE field type before it builds the sort.**

- The check is in `ChildFieldValueSourceParser.parse` ([check](https://github.com/nick-boss-tech/solr/blob/c79a49320cdb0390a9ae7118ab70efbf080826d7/solr/core/src/java/org/apache/solr/search/join/ChildFieldValueSourceParser.java#L195-L203)). It throws a syntax error that names the sort field and its field type.
- The request still returns a 400 with the same status and message. The error metadata now names `SyntaxError` as the root error class. It named `UnsupportedOperationException` before.
- The server log now records the clear message ([log line](https://github.com/nick-boss-tech/solr/blob/c79a49320cdb0390a9ae7118ab70efbf080826d7/solr/core/src/java/org/apache/solr/search/join/ChildFieldValueSourceParser.java#L204-L205)). It uses the same catch as the other childfield errors.
- The check covers every field type that reports REWRITEABLE, not only currency.

## Proof

**One test class. The new test checks the error chain, not the client message.**

- `TestNestedDocsSort` 12/12 at `c79a49320cd`, verified 2026-10-07. The new test `testRewriteableSortFieldTypeIsRejected` ([test](https://github.com/nick-boss-tech/solr/blob/c79a49320cdb0390a9ae7118ab70efbf080826d7/solr/core/src/test/org/apache/solr/search/join/TestNestedDocsSort.java#L89-L103)) checks the 400 code, then the field name, the type name, and the message text in the cause chain.
- On the base code the same class runs 12 tests with one failure.

## Limits

**Sorting on a REWRITEABLE field is still not supported.**

- The ticket asks whether rewriting underneath the sort could make it work. This change rejects those sorts. It does not support them. I can open a follow-up ticket and PR for rewrite support on request.
- The client message for these sorts is the generic one above. It comes from `SortSpecParsing` and is not changed here. I can open a follow-up for that message on request.
- Sorts on other field types are unchanged.
