## What happens today

**A query that sets `v` in local-params and then adds more query text silently drops that text.**

For example, `q={!term f=text v=$qq} OR id:3` with `qq=nomatch` returns no documents. The `OR id:3` part is ignored, so document 3 is missing. A leading space before the query is a known workaround. In the code before this change, a `v` value sets the whole query, and the text after the closing brace is not read ([base code, lines 428 to 433](https://github.com/nick-boss-tech/solr/blob/e2cdb2d7e8ae0be4cf6cf0606206c67d89e7278f/solr/core/src/java/org/apache/solr/search/QParser.java#L428-L433)). This link points at the merge-base commit, `e2cdb2d7e8ae`, because it shows the code before the change.

## What this change does

**When `v` is set and more query text follows the local-params, the whole string goes to the Lucene query parser.**

The parser checks the text after the closing brace. If that text is query text, the whole string goes to the default Lucene parser. That parser understands `{!...}` clauses inside a larger query. Some shapes keep the old path. These are text made only of slop or boost suffixes (`~1`, `^3`), text attached to the brace with no space or separator (`foo`), and a lone closing parenthesis. A sort or field list written with the function parser also keeps its old path ([the check, lines 399 to 463](https://github.com/nick-boss-tech/solr/blob/50139a8e979cd33319a30317d9371ac0b9198e73/solr/core/src/java/org/apache/solr/search/QParser.java#L399-L463); [the branch, lines 494 to 503](https://github.com/nick-boss-tech/solr/blob/50139a8e979cd33319a30317d9371ac0b9198e73/solr/core/src/java/org/apache/solr/search/QParser.java#L494-L503)).

Behavior change, stated openly: a query with trailing query text now returns what that text says. Results for queries of this shape change.

## Limits

**The change covers one shape: `v` set in local-params, followed by query text after the closing brace.**

- Text attached to the closing brace with no space or separator stays ignored, as before (`{!v=$qq}foo`).
- Slop and boost suffixes (`~1`, `^3`) stay ignored, as before.
- Sort and field lists written with the function parser keep their old path.
- A lone closing parenthesis stays ignored.
