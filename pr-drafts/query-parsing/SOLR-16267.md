## What happens today

**A math function over a sparse field counts documents that have no value.**

With `avg(sqrt(field))`, the average divides by every document in the bucket. It should divide by the documents that have a value for `field`. `countvals(sqrt(field))` counts the documents with no value too. In the ticket example, a bucket has six documents and only four have a value. The average of `sqrt` is divided by six. The plain `avg(field)` is correct. See [SOLR-16267](https://issues.apache.org/jira/browse/SOLR-16267).

## What this change does

**The single and two argument math wrappers now report when their input has no value.**

The single argument wrapper ([ValueSourceParser.java L1688-L1691](https://github.com/nick-boss-tech/solr/blob/8f4b0c6d2fb0c89c833512de502f39eb1bec560e/solr/core/src/java/org/apache/solr/search/ValueSourceParser.java#L1688-L1691)) and the two argument wrapper ([L1743-L1746](https://github.com/nick-boss-tech/solr/blob/8f4b0c6d2fb0c89c833512de502f39eb1bec560e/solr/core/src/java/org/apache/solr/search/ValueSourceParser.java#L1743-L1746)) now override `exists()`. A single argument function exists when its input exists. A two argument function exists only when both inputs exist. Facet stats use that answer. So `avg`, `countvals`, `missing`, `min`, `max` and `percentile` skip the documents with no value.

This is wider than the average in the ticket. The same answer reaches `exists()` and `def()`, as the changelog says. Those results change for any sparse field used inside these math functions.

## Limits

**`exists()`, `def()` and `percentile` have no direct assertion.**

The new assertions reach them only through the facet stats. Direct assertions for `exists()`, `def()` and `percentile` are a follow-up. We can submit it after this change. Other functions are not changed by this branch.
