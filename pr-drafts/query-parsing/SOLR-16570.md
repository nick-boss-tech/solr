## What happens today

**Collapse or expand with `hint=top_fc` fails with a NullPointerException on a string field that has docValues but cannot be uninverted.**

Take a string field with `docValues="true"` and `uninvertible="false"`, for example a field named `brand`. A request with `{!collapse field=brand hint=top_fc}` fails with a NullPointerException, which the server returns as HTTP 500. The same failure happens with `expand=true`. The top-level reader wraps the segment reader in `Map.of(field, type)`. For this field the uninversion type is null, and `Map.of` rejects a null value, so the request fails before it reads the docValues ([base code, lines 610 to 624](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/search/CollapsingQParserPlugin.java#L610-L624)). This link points at the merge-base commit, `cabedd1d968`, because it shows the code before the change.

## What this change does

**For a field with no uninversion type, the top-level reader returns the field's docValues directly.**

When the type is null, the change returns the segment reader without the wrapper. Collapse and expand then read the docValues in the same way the default hint does for that field ([head, lines 621 to 624](https://github.com/nick-boss-tech/solr/blob/9d3466101a29b70ac0b45aa0770b4cf4f34e6cb3/solr/core/src/java/org/apache/solr/search/CollapsingQParserPlugin.java#L621-L624); [default path, line 591](https://github.com/nick-boss-tech/solr/blob/9d3466101a29b70ac0b45aa0770b4cf4f34e6cb3/solr/core/src/java/org/apache/solr/search/CollapsingQParserPlugin.java#L591)).

Behavior change, stated openly: with `hint=top_fc`, a field that has docValues and is either not indexed or has `uninvertible="false"` now reads its docValues. For that field the hint has no effect. The request used to fail.

The new test adds one dynamic field to the shared test schema, `*_s_dv_not_uninvert`, with docValues and `uninvertible="false"` ([schema, line 321](https://github.com/nick-boss-tech/solr/blob/9d3466101a29b70ac0b45aa0770b4cf4f34e6cb3/solr/core/src/test-files/solr/collection1/conf/schema11.xml#L321)). The test ([lines 1027 to 1059](https://github.com/nick-boss-tech/solr/blob/9d3466101a29b70ac0b45aa0770b4cf4f34e6cb3/solr/core/src/test/org/apache/solr/search/TestCollapseQParserPlugin.java#L1027-L1059)) runs a collapse and an expand with the default hint and with `hint=top_fc`, and expects the same results for both.

## Proof

**The new test fails on the base code and passes with this change.**

- `TestCollapseQParserPlugin` 20 of 20 pass at head `9d3466101a29`, verified 2026-10-09.
- On the base code, with the test in place, the same class runs 20 tests with 1 failure: `testTopFcHintOnDocValuesWithoutUninversion`, a NullPointerException from the `Map.of` call.

## Limits

**The change covers one trigger. The empty-collection case in the ticket title is a different path.**

- The ticket title describes an empty collection with `nullPolicy=expand`. Commit [0cc18eb4cae](https://github.com/nick-boss-tech/solr/commit/0cc18eb4cae37dd7b560d73b8f35affb7396aba6) (SOLR-16611) changed the null check on that path, and it is in the base of this change. This change adds no test for the empty-collection case.
- The change covers string fields with docValues that are not indexed or have `uninvertible="false"`. Other string fields keep the uninverted path. A string field with neither docValues nor uninversion is rejected earlier, as before ([check, lines 355 to 362](https://github.com/nick-boss-tech/solr/blob/9d3466101a29b70ac0b45aa0770b4cf4f34e6cb3/solr/core/src/java/org/apache/solr/search/CollapsingQParserPlugin.java#L355-L362)).
- The focused run covers `TestCollapseQParserPlugin` only. Other test classes that load the shared test schema were not run.
