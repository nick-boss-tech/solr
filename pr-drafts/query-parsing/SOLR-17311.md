## What happens today

**A cursorMark page can fail with a NullPointerException when its boundary falls on a parent with no child value.**

Sorting on a string `childfield(...)` with `cursorMark` can fail with `NullPointerException: Cannot invoke "java.lang.CharSequence.length()" because "text" is null` in `BytesRef.<init>` ([JIRA](https://issues.apache.org/jira/browse/SOLR-17311)). The string comparator builds a `BytesRef` from the page's top value. For a parent with no child value, that value is null.

## What this change does

**A null top value is passed through unchanged instead of being wrapped in a `BytesRef`.**

- The change is in `BytesToStringComparator.setTopValue` ([change](https://github.com/nick-boss-tech/solr/blob/9f7524582f9de4d6931779bc31811013c414a45f/solr/core/src/java/org/apache/solr/search/join/ChildFieldValueSourceParser.java#L63-L67)). Non-null values are wrapped as before.
- Lucene's `TermOrdValComparator` treats a null top value as the missing value. This holds in Lucene 10.4.0 and 9.12.3.
- Only string child fields use this comparator. Numeric child sorts take another path and are unchanged.

## Proof

**One test class. The new test covers cursorMark paging over a missing child value.**

- `TestNestedDocsSort` 12/12 at `9f7524582f9`, verified 2026-10-04. The new test `testCursorMarkPagingOverMissingChildValue` ([test](https://github.com/nick-boss-tech/solr/blob/9f7524582f9de4d6931779bc31811013c414a45f/solr/core/src/test/org/apache/solr/search/join/TestNestedDocsSort.java#L107-L145)) builds six parents, every other one with no child value, and pages through them one row at a time. It checks that the paged ids equal the unpaged ids.
- On the base code the new test fails with the NullPointerException from the ticket.

## Limits

**Numeric child sorts and the missing-value setting are not changed.**

- Numeric `childfield()` sorts with `cursorMark` are not covered here. I can open a follow-up ticket and PR on request if they fail in the same way.
- `childfield()` builds its sort from the child field's type only. The field's `sortMissingFirst` or `sortMissingLast` setting is not applied. That behavior predates this change. I can open a follow-up for it on request.
