## What happens today

**A tagged collapse filter works with `q.op=OR` and fails with `q.op=AND`.**

The ticket body uses `fq={!tag=collapse_tag}{!collapse field=someid}`. It reports that this filter works with `q.op=OR`. With `q.op=AND`, the request fails with `java.lang.UnsupportedOperationException: Query CollapsingPostFilter(...) does not implement createWeight`.

Under `q.op=AND`, the parser wraps the lone required clause in a BooleanQuery. The wrapper asks the clause for a Weight. [CollapsingPostFilter](https://github.com/nick-boss-tech/solr/blob/661165d2673de9211846e276c05daf1fd0e879d6/solr/core/src/java/org/apache/solr/search/CollapsingQParserPlugin.java#L269) does not implement `createWeight`, so the request fails.

## What this change does

**A lone required post filter is returned as it is, not wrapped.**

In the `Query` production, a single required clause that is a `PostFilter` is returned unwrapped ([QueryParser.jj lines 232 to 245](https://github.com/nick-boss-tech/solr/blob/661165d2673de9211846e276c05daf1fd0e879d6/solr/core/src/java/org/apache/solr/parser/QueryParser.jj#L232-L245)). A negated post filter stays wrapped, so its negation is kept. The generated [QueryParser.java](https://github.com/nick-boss-tech/solr/blob/661165d2673de9211846e276c05daf1fd0e879d6/solr/core/src/java/org/apache/solr/parser/QueryParser.java#L247-L260) was regenerated from that grammar. The grammar also changes two accessor calls on the existing lone-clause check, `getOccur()` and `getQuery()`, to `occur()` and `query()`. The generated file already used those names.

Behavior change, stated openly: under `q.op=AND`, a lone required post filter now reaches the searcher unwrapped. A bare clause already reaches it that way under `q.op=OR`.

## Proof

**One new test fails on the base code and passes with this change.**

- [testCollapseFilterIsNotWrappedWhenRequired](https://github.com/nick-boss-tech/solr/blob/661165d2673de9211846e276c05daf1fd0e879d6/solr/core/src/test/org/apache/solr/search/TestCollapseQParserPlugin.java#L287-L305) fails on the base grammar with the `UnsupportedOperationException` from `CollapsingPostFilter.createWeight`.
- [testNegatedPostFilterStaysNegated](https://github.com/nick-boss-tech/solr/blob/661165d2673de9211846e276c05daf1fd0e879d6/solr/core/src/test/org/apache/solr/search/TestCollapseQParserPlugin.java#L307-L328) passes on the base code and with this change. It uses a negated `frange` query. That query is a post filter that has a Weight, so the test checks that the negation is kept without hitting the exception.
- Verified 2026-10-04 at `661165d2673`. TestCollapseQParserPlugin: 21 of 21, 0 skipped, 0 failures.

## Limits

- Only a filter with one clause is covered. A post filter next to another clause in the same filter, such as `+{!collapse field=x} +a:1`, is not changed and has no test.
- A negated collapse, such as `-{!collapse field=x}`, is still wrapped as before. It has no test here.
- Facet exclusion through the same tag is not tested.
- I can open a follow-up ticket and pull request for the multi-clause and negated collapse cases if maintainers want them.
