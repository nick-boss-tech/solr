## What happens today

**A fuzzy query matches at most 50 index terms, and the lucene parser has no setting to raise that limit.**

A query such as `cc:worde~1` keeps only 50 of the index terms that are close to the input. Lucene's `FuzzyQuery` default is 50. A document that matches only a term outside those 50 is not returned. The hit count can change as new close terms are indexed. The ticket reports the same effect on a large index.

The new test shows the cap: in an index with 75 terms one edit away from `abc`, `fuzzyexp_s:abc~1` returns 50 documents.

## What this change does

**A new `fuzzy.maxExpansions` parameter sets the limit for the lucene parser. Other parsers keep 50.**

The parameter can be a request parameter or a local parameter, for example `{!lucene fuzzy.maxExpansions=200}`. [LuceneQParser.java](https://github.com/nick-boss-tech/solr/blob/76c777e4661e9240ac66dd01247c0dd1286cacff/solr/core/src/java/org/apache/solr/search/LuceneQParser.java#L53-L56) reads the value. [SolrQueryParserBase.java](https://github.com/nick-boss-tech/solr/blob/76c777e4661e9240ac66dd01247c0dd1286cacff/solr/core/src/java/org/apache/solr/parser/SolrQueryParserBase.java#L677-L683) passes it to the five-argument `FuzzyQuery` constructor. A query without the parameter still uses 50 expansions with transpositions on. Those are the same values the old three-argument call used, so the default behavior does not change.

## Proof

**The new test fails on the base code and passes with this change.**

- [TestSolrQueryParser.testFuzzyMaxExpansions](https://github.com/nick-boss-tech/solr/blob/76c777e4661e9240ac66dd01247c0dd1286cacff/solr/core/src/test/org/apache/solr/search/TestSolrQueryParser.java#L87-L118) is new. On the base code its check with `fuzzy.maxExpansions=200` returns 50 documents where 75 are expected. Its default check, which expects 50, passes there. Verified 2026-10-07 at head 76c777e4661e9240ac66dd01247c0dd1286cacff: TestSolrQueryParser 38 of 38 pass.
- Lucene check: lucene-core 9.12.3 and 10.4.0 both set the default number of expansions to 50. Their three-argument `FuzzyQuery` constructor passes 50 and transpositions `true`.

## A choice to check

**The parameter name and the default are the open calls.**

The ticket suggested `maxFuzzyExpansions` as a request parameter, or a larger built-in default. This change uses `fuzzy.maxExpansions` and keeps the default at 50, so no current result changes. A larger built-in default would change results for every fuzzy query. Was `fuzzy.maxExpansions` the right name, and should the default stay at 50?

## Limits

**Only the lucene parser reads the parameter. The test does not check which terms are kept.**

- edismax and the other parsers keep 50. We can open a follow-up for them on request.
- The test checks the count of matches. It does not check which 50 terms are kept when more terms match.
- A value that is not a whole number, or is zero or negative, is not checked yet. It is expected to fail with a server error instead of a 400 error.
