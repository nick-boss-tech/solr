## What happens today

**A nested dismax clause that has only stopwords makes the whole enclosing query match nothing.**

The ticket example is `(_query_:"{!dismax qf=allfields}transformation") AND (_query_:"{!dismax qf=allfields}in")`, where `in` is a stopword. The first clause finds documents. The enclosing query finds none. Before this change, the second clause added an empty MUST clause, and an empty MUST clause matches no document, so the AND failed. The ticket expects the same results as the first clause alone.

## What this change does

**A dismax user query with no terms left after analysis is treated as blank, so the enclosing query drops that clause.**

The check is in [DisMaxQParser.java lines 198-202](https://github.com/nick-boss-tech/solr/blob/505849d2d4e7d8699a2fe34d410773b8ecf3a55a/solr/core/src/java/org/apache/solr/search/DisMaxQParser.java#L198-L202). A top-level dismax query with only stopwords still matches nothing, as before. This change covers the `{!dismax}` parser only. The `{!edismax}` parser has its own code and is not changed.

## Proof

**One test method changed. It fails on the base code and passes with this change.**

[TestExtendedDismaxParser](https://github.com/nick-boss-tech/solr/blob/505849d2d4e7d8699a2fe34d410773b8ecf3a55a/solr/core/src/test/org/apache/solr/search/TestExtendedDismaxParser.java#L389-L399) adds two checks to `testFocusQueryParser`: a nested dismax clause with a stopword, and a top-level dismax stopword query. At head `505849d2d4e7d8699a2fe34d410773b8ecf3a55a`, the class passes 39 of 39. With `DisMaxQParser.java` reverted to the base code, `testFocusQueryParser` fails at the nested check, which returns 0 documents where 2 are expected.

A CI run of the same class also passed at this head (run 37639870647).

## Limits

- A nested `{!edismax}` clause with only stopwords is not changed. If maintainers want that path too, I can open a follow-up change for it.
- A stopword-only `{!dismax}` clause used as a filter query (`fq`) is not covered by the new checks.
- A nested or top-level stopword-only `{!dismax}` clause that also sets a `cache` or `cost` local parameter is not covered by the new checks.
