## What happens today

**A phrase slop is lost when an earlier clause in the same query is a nested `_query_` clause.**

On the base code, the query `_query_:"foo" text:"how brown"~2` gives the debug query `text:foo PhraseQuery(text:"how brown")`. The `~2` is gone. The ticket reports the same loss for a nested clause that comes before a phrase with slop.

## What this change does

**The parser clears its nested-query marker before it builds a phrase with an explicit slop.**

The marker is set only by a nested `_query_` clause. The base code never cleared it, so a later phrase in the same query lost its slop. The reset is in [SolrQueryParserBase.java](https://github.com/nick-boss-tech/solr/blob/151dfed119ee0a6f5a922f3a914665e7b3281427/solr/core/src/java/org/apache/solr/parser/SolrQueryParserBase.java#L545-L547). A query with an explicit phrase slop after a nested clause now keeps that slop. Matching and ranking can change for those queries.

## Proof

**The new assertion fails on the base code and passes with this change.**

- [TestSolrQueryParser.testNestedQueryModifiers](https://github.com/nick-boss-tech/solr/blob/151dfed119ee0a6f5a922f3a914665e7b3281427/solr/core/src/test/org/apache/solr/search/TestSolrQueryParser.java#L298-L301) has a new assertion. On the base code the debug query has no `~2`. Verified 2026-10-05 at head 151dfed119ee0a6f5a922f3a914665e7b3281427: TestSolrQueryParser 37 of 37 pass.

## Limits

**eDismax is not changed by this patch.**

- eDismax overrides the same slop method in [ExtendedDismaxQParser.java](https://github.com/nick-boss-tech/solr/blob/151dfed119ee0a6f5a922f3a914665e7b3281427/solr/core/src/java/org/apache/solr/search/ExtendedDismaxQParser.java#L1067-L1074) and does not call the base method. A query with a nested clause and a phrase slop was not tested in eDismax. We can open a follow-up for it on request.
