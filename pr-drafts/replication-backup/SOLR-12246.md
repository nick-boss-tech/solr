## What happens today

**A file whose checksum differs from the leader's copy is logged at WARN, although the follower only fetches it again.**

During replication or full recovery, `IndexFetcher.compareFile` compares each file with the leader's copy. A file whose checksum differs is logged at WARN as "File _0_1.liv did not match" ([IndexFetcher.java](https://github.com/nick-boss-tech/solr/blob/3ffc2539ec76cee5615f5bbfbcca784b5024ed9d/solr/core/src/java/org/apache/solr/handler/IndexFetcher.java#L1264-L1274)). The follower then fetches the file again. On the same method, a file with no checksum to compare and a different length is already logged at INFO ([IndexFetcher.java](https://github.com/nick-boss-tech/solr/blob/3ffc2539ec76cee5615f5bbfbcca784b5024ed9d/solr/core/src/java/org/apache/solr/handler/IndexFetcher.java#L1249-L1252)).

## What this change does

**The checksum mismatch message moves from WARN to INFO. The comparison result does not change.**

The one production change is the log level of that message ([IndexFetcher.java](https://github.com/nick-boss-tech/solr/blob/3ffc2539ec76cee5615f5bbfbcca784b5024ed9d/solr/core/src/java/org/apache/solr/handler/IndexFetcher.java#L1265-L1266)). The same branch covers an equal length and a different length, so both cases are logged at INFO.

## Proof

**The new test fails on the base code and passes with this change.**

`IndexFetcherCompareFileTest` 1 of 1 at head `3ffc2539ec7`, verified 2026-10-05 ([test](https://github.com/nick-boss-tech/solr/blob/3ffc2539ec76cee5615f5bbfbcca784b5024ed9d/solr/core/src/test/org/apache/solr/handler/IndexFetcherCompareFileTest.java#L29-L48)). The test writes a small `.liv` file, compares it with a wrong checksum, and checks two things: no WARN from `IndexFetcher` is logged, and the mismatch is logged at INFO. On the base code the test catches the WARN: "File _0_1.liv did not match. expected checksum is 12345 and actual is checksum 3589274946. expected length is 33 and actual length is 33." With this change it passes.

`IndexFetcherPacketProtocolTest` runs 18 tests with no failures at the same head. `TestReplicationHandler` is marked `@Nightly`, and that run skipped its 25 tests, so no replication test ran at this head.

## A choice to check

**Should a length difference keep WARN? This change lowers the whole checksum message to INFO.**

The other route keeps WARN when the lengths also differ, and lowers only the equal-length case. The route taken matches the length-only path on the same method, which is already INFO. The follower fetches the file again either way. The cost is that a real length difference no longer shows at WARN. Was lowering the whole message the right call?

## Limits

**The reason the `.liv` checksums differ is not addressed.**

This change only changes the log level. The ticket asks why a `.liv` checksum differs after a full recovery, and that question stays open. The test covers the equal-length case only. If you want the cause looked at, a follow-up ticket and pull request can take it on. No end-to-end recovery test ran for this change.
