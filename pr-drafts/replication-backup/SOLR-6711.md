## What happens today

**Turning off polling lasts only until the next restart or core reload.**

`command=disablepoll` sets an in-memory flag and logs it. It writes nothing to `replication.properties`. ([ReplicationHandler.java, lines 813-821](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/handler/ReplicationHandler.java#L813-L821), at the base commit `cabedd1d968059215188f4e7563fb303241899ed`.)

## What this change does

**With `persist=true`, `disablepoll` saves the setting, and `enablepoll` clears it.**

Both writers of `replication.properties` now share one lock. The writes are in [ReplicationHandler.java](https://github.com/nick-boss-tech/solr/blob/73c5e6e0d243a9886da0a25efe0acc7f1bbf7ec2/solr/core/src/java/org/apache/solr/handler/ReplicationHandler.java#L845-L867) and [IndexFetcher.java](https://github.com/nick-boss-tech/solr/blob/73c5e6e0d243a9886da0a25efe0acc7f1bbf7ec2/solr/core/src/java/org/apache/solr/handler/IndexFetcher.java#L925-L950). With `persist=true`, the in-memory poll flag changes only after the write succeeds ([L815-L818](https://github.com/nick-boss-tech/solr/blob/73c5e6e0d243a9886da0a25efe0acc7f1bbf7ec2/solr/core/src/java/org/apache/solr/handler/ReplicationHandler.java#L815-L818)). The same lock also covers the replication time and failure records that `IndexFetcher` writes to that file.

## Proof

**A new test fails without the production change and passes with it.**

`TestPersistedPollDisabled` ran once at head `73c5e6e0d243a9886da0a25efe0acc7f1bbf7ec2`, with 0 failures and 0 errors. The count comes from a fresh JUnit XML report dated 2026-10-12. With `IndexFetcher.java` and `ReplicationHandler.java` reverted to the base commit and the new test kept, the same test fails once with `java.lang.AssertionError: persist=true must survive a reload`. That failure comes from the check on the persisted flag, not from core startup.

At the head, the changelog YAML parses, tidy makes no changes, the Error Prone compile succeeds, and the core module check passes.

## A choice to check

**Making persistence the default would change restart behavior for every existing `disablepoll` caller.**

The implemented route saves the setting only when the request passes `persist=true`. Without that parameter, the setting stays in memory, as it does today. Was keeping persistence opt-in the right call?
