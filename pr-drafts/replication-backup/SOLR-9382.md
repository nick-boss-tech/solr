## What happens today

**A wildcard in a confFiles entry is dropped with no message, so the leader sends none of the files it would match.**

On the merge-base commit, the leader resolves each confFiles name to a path in the config directory. A name that is not an existing file is skipped without a log line ([ReplicationHandler.java](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/handler/ReplicationHandler.java#L776-L777)). A name such as `_schema_analysis_*.json` is not a file, so it is dropped. By default, managed resource files are stored in the config directory ([ManagedResourceStorage.java](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/rest/ManagedResourceStorage.java#L128-L131)), and each file name is the resource ID with `/` replaced by `_` ([L445](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/rest/ManagedResourceStorage.java#L445)).

## What this change does

**The leader expands a confFiles entry with `*` or `?` in its file name into the matching files of its config directory.**

The expansion runs before the leader's file loop ([ReplicationHandler.java](https://github.com/nick-boss-tech/solr/blob/2952bae9d3927c6f1e648308469f042795f8886a/solr/core/src/java/org/apache/solr/handler/ReplicationHandler.java#L774)), in a new method ([L810-L843](https://github.com/nick-boss-tech/solr/blob/2952bae9d3927c6f1e648308469f042795f8886a/solr/core/src/java/org/apache/solr/handler/ReplicationHandler.java#L806-L843)). The matches are regular files in that one directory, sorted by name, and a pattern cannot match outside the config directory. Plain names pass through unchanged. A pattern whose directory is missing or outside the config directory is skipped with a warning. An alias set on a pattern is ignored.

With this change it passes.

## Limits

**This change answers the wildcard suggestion only. It does not change how a standalone follower sees managed resource changes after a reload.**

- The ticket's main report is about that reload behavior, and this change does not touch it. We can open a follow-up ticket and pull request for it on request.
- Matching is not recursive. A pattern matches files in one directory only.
- The test calls the handler method directly. No replication run uses a wildcard entry.
