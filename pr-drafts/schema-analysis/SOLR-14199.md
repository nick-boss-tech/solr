## What happens today

**Schemas can set `omitNorms="false"` on point fields, and Solr accepts it without a word.**

A schema can set `omitNorms="false"` on a point field type such as `IntPointField`, or on an indexed field or dynamic field of a point type. Point fields never store norms, so the setting does nothing. Solr loads the schema and ignores the setting.

## What this change does

**Solr now rejects `omitNorms="false"` on point types and on indexed point fields.**

- `PointField.init` rejects `omitNorms="false"` on a point field type.
- [`PointField.checkSchemaField`](https://github.com/nick-boss-tech/solr/blob/2c549d9fb384363f741ce62206c37f518744153f/solr/core/src/java/org/apache/solr/schema/PointField.java#L96-L110) rejects `omitNorms="false"` on an indexed field of a point type. Fields are built through this check, so the Schema API path is covered by the same check.
- Point field types always omit norms. This includes schema versions 1.4 and older. The Schema API now reports `omitNorms` as true for point types on those versions. This is a behavior change.
- Existence queries no longer make an exception for point fields. Indexed point fields already use the unbounded range path, so their results do not change. Stored-only point fields (`indexed="false"` with no docValues) now take the same path as trie and string fields with no norms. An existence query on such a field returns 400 when the index holds that field. Before, it returned no matches. This is a behavior change.
- The numeric `*_norms` dynamic fields are removed from the `schema12.xml` test fixture.
- The upgrade note is in [`major-changes-in-solr-11.adoc`](https://github.com/nick-boss-tech/solr/blob/2c549d9fb384363f741ce62206c37f518744153f/solr/solr-ref-guide/modules/upgrade-notes/pages/major-changes-in-solr-11.adoc#L30-L35).

## A choice to check

**Point types now report `omitNorms` as true on schema versions 1.4 and older too.**

Point types now always omit norms, including on schema versions 1.4 and older. The other route keeps the old default on those versions and rejects only an explicit `omitNorms="false"`. That route leaves old schemas reporting `omitNorms` as false for point types. Was it right to report `omitNorms` as true on old schema versions too?

## Limits

**Field checks cover indexed fields only. The Schema API path and stored-only point fields have no test.**

- Field-level checks apply only to indexed fields. A field with `indexed="false"` and `omitNorms="false"` already fails to load on base, through an existing check.
- The Schema API path uses the same field check, but no test covers it.
- The stored-only point existence change above is not covered by a test.
- The new point check skips non-indexed fields. On those fields it cannot tell an explicit `omitNorms="false"` from the default, and base already rejects the explicit form (see the first bullet).
- The checks do not exempt `TEST_HACK_IGNORE_USELESS_TRIEFIELD_ARGS`. A hand-written test schema that sets `omitNorms="false"` on a point type would now fail to load even under the flag. A follow-up for that case is possible on request.
