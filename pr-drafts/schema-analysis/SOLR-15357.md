## What happens today

**Real-time get and atomic update filters miss the sub-fields of a copyField destination.**

Solr checks copyField targets with `isCopyFieldTarget`. A currency, point, or bounding box field looks like one field to users, but it has sub-fields, such as the currency amount field. Those sub-fields are not counted as copyField targets, so the check returns false for them and the filters keep them.

## What this change does

**Sub-fields of a copyField destination are now counted as copyField targets.**

Each field type reports its sub-fields through a new `FieldType.getSubFields` hook ([FieldType.java](https://github.com/nick-boss-tech/solr/blob/d717899b8736309bd72f54b11230f198ae226e7d/solr/core/src/java/org/apache/solr/schema/FieldType.java#L178-L180)), overridden by [CurrencyFieldType](https://github.com/nick-boss-tech/solr/blob/d717899b8736309bd72f54b11230f198ae226e7d/solr/core/src/java/org/apache/solr/schema/CurrencyFieldType.java#L206-L219), [AbstractSubTypeFieldType](https://github.com/nick-boss-tech/solr/blob/d717899b8736309bd72f54b11230f198ae226e7d/solr/core/src/java/org/apache/solr/schema/AbstractSubTypeFieldType.java#L143-L155) (PointType), and [BBoxField](https://github.com/nick-boss-tech/solr/blob/d717899b8736309bd72f54b11230f198ae226e7d/solr/core/src/java/org/apache/solr/schema/BBoxField.java#L131-L148). [IndexSchema](https://github.com/nick-boss-tech/solr/blob/d717899b8736309bd72f54b11230f198ae226e7d/solr/core/src/java/org/apache/solr/schema/IndexSchema.java#L1074-L1080) and [ManagedIndexSchema](https://github.com/nick-boss-tech/solr/blob/d717899b8736309bd72f54b11230f198ae226e7d/solr/core/src/java/org/apache/solr/schema/ManagedIndexSchema.java#L1037-L1046) add and remove the sub-field counts with each copyField. The multi-target warning skips sub-fields.

Behavior changes:
- `isCopyFieldTarget` is now true for these sub-fields for every caller, not only real-time get and atomic updates.
- Deleting a sub-field of a copyField destination now fails with the existing "referred to by at least one copy field directive" error ([ManagedIndexSchema.java L503](https://github.com/nick-boss-tech/solr/blob/d717899b8736309bd72f54b11230f198ae226e7d/solr/core/src/java/org/apache/solr/schema/ManagedIndexSchema.java#L503)).
- A glob destination gets no sub-fields recorded.

## Proof

Gate run at d717899b8736309bd72f54b11230f198ae226e7d, recorded 2026-10-07. ## A choice to check

**The shared copyField bookkeeping now carries sub-fields for every caller.**

Options considered: (a) count sub-fields in the shared bookkeeping, as this change does; (b) leave the bookkeeping alone and skip sub-fields only in the real-time get and atomic update paths. Option (a) also changes the delete check, which option (b) would leave alone. Was the shared bookkeeping the right place, or should the two read paths skip sub-fields themselves?

## Limits

**Some paths can still return docValues sub-fields once those sub-fields carry docValues.**
- Real-time get decorates docValues fields without the copy target check ([RealTimeGetComponent.java L356-L357](https://github.com/nick-boss-tech/solr/blob/d717899b8736309bd72f54b11230f198ae226e7d/solr/core/src/java/org/apache/solr/handler/component/RealTimeGetComponent.java#L356-L357)). This change does not touch that path. SOLR-15358 writes docValues for these sub-fields, so real-time get and `fl=*` searches can return them once it lands. A follow-up ticket and PR can cover that path, on request.
- Currency sub-fields have no docValues on this branch, so currency output does not change here.
- No test covers PointType or BBoxField sub-fields, the glob case, or the delete refusal.
