## What happens today

**A collation field can return its docValues as stored values.**

At schema version 1.6 and later, every field type uses its docValues as stored values by default ([FieldType.java lines 181 to 190 at the base commit](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/schema/FieldType.java#L181-L190)). A collation field also turns docValues on by default ([CollationField.java lines 245 to 247](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/schema/CollationField.java#L245-L247)). So `fl=*` can return those docValues. They hold binary collation keys, which are not UTF-8 text. The ticket reports an `ArrayIndexOutOfBoundsException` while Solr decodes such values, in queries and in backups.

## What this change does

**A collation field no longer uses its docValues as stored values. A schema that sets the flag on one now fails to load.**

`CollationField` clears the flag when it initializes ([lines 100 to 105 at the head](https://github.com/nick-boss-tech/solr/blob/cb988a2ff4c3e890e3a9c258019d22d1f888aebd/solr/core/src/java/org/apache/solr/schema/CollationField.java#L100-L106)). It refuses the flag on a field at every schema version ([lines 91 to 97](https://github.com/nick-boss-tech/solr/blob/cb988a2ff4c3e890e3a9c258019d22d1f888aebd/solr/core/src/java/org/apache/solr/schema/CollationField.java#L91-L97)).

Behavior changes wider than the ticket:
- `fl=*` no longer returns the docValues of collation fields.
- A schema that sets `useDocValuesAsStored` on a collation field stops loading, whatever its version. The ICU collation field has used a version rule since SOLR-15777: it warns below Lucene 9.0 and fails from 9.0 ([ICUCollationField.java lines 97 to 126 at the base commit](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/modules/analysis-extras/src/java/org/apache/solr/schema/ICUCollationField.java#L97-L126)). This change does not follow that rule.

## Proof

Verified 2026-10-09 at head cb988a2ff4c:

- With this change, `TestCollationFieldDocValues` runs 9 of 9 and passes. `TestCollationField` runs 8 of 8 and passes.

## A choice to check

**Setting the flag fails at every schema version.**

The options are to refuse the flag at every version, which this change does, or to warn below Lucene 9.0 and fail from 9.0, as the ICU collation field does. The first breaks old schemas that set the flag. The second keeps them loading with a warning until they reach 9.0. Was refusing the flag at every version the right call?

## Limits

**The backup path is not covered, and the base run stops before the `fl=*` check.**

The ticket also reports a failure in backup. The test covers `fl=*` only. The test checks the flag before it runs the `fl=*` request, so the base run does not show what `fl=*` returns on the base code. Explicit `fl` requests for these fields are not tested. The ICU collation field is not changed here.
