## What happens today

**A CSV cell whose value is a map, a NamedList or an iterator comes out missing, and the values after it move one column left.**

The base class handles these values in methods that write nothing for CSV: [writeNamedList](https://github.com/nick-boss-tech/solr/blob/64e86811548ba1a9dbc5b2ce2ec9c33983f63c15/solr/core/src/java/org/apache/solr/response/TabularResponseWriter.java#L121), [writeMap](https://github.com/nick-boss-tech/solr/blob/64e86811548ba1a9dbc5b2ce2ec9c33983f63c15/solr/core/src/java/org/apache/solr/response/TabularResponseWriter.java#L136), and [writeArray](https://github.com/nick-boss-tech/solr/blob/64e86811548ba1a9dbc5b2ce2ec9c33983f63c15/solr/core/src/java/org/apache/solr/response/TabularResponseWriter.java#L139) and [writeArray](https://github.com/nick-boss-tech/solr/blob/64e86811548ba1a9dbc5b2ce2ec9c33983f63c15/solr/core/src/java/org/apache/solr/response/TabularResponseWriter.java#L142). The cell prints nothing, so the next value is written in that cell's column.

## What this change does

**The CSV writer writes a map, NamedList, iterator or array value as one JSON cell.**

A new `writeCellVal` method writes these values with `Utils.toJSONString` and CSV escaping. Other value types go to `writeVal` as before. The method is used for each value of a multivalued field ([CSVResponseWriter.java](https://github.com/nick-boss-tech/solr/blob/64e86811548ba1a9dbc5b2ce2ec9c33983f63c15/solr/core/src/java/org/apache/solr/response/CSVResponseWriter.java#L418)) and for single values ([L436](https://github.com/nick-boss-tech/solr/blob/64e86811548ba1a9dbc5b2ce2ec9c33983f63c15/solr/core/src/java/org/apache/solr/response/CSVResponseWriter.java#L436), [L441](https://github.com/nick-boss-tech/solr/blob/64e86811548ba1a9dbc5b2ce2ec9c33983f63c15/solr/core/src/java/org/apache/solr/response/CSVResponseWriter.java#L441)). The method is defined at [L454-L465](https://github.com/nick-boss-tech/solr/blob/64e86811548ba1a9dbc5b2ce2ec9c33983f63c15/solr/core/src/java/org/apache/solr/response/CSVResponseWriter.java#L454-L465).

Behavior changes, stated openly:

- A cell that used to be missing now holds compact JSON. CSV output changes for documents with these values.
- The values after such a cell stay in their own columns.

## Limits

**This PR changes the CSV writer only.**

- The ticket asks for all response writers. The XML, Python, PHP, Ruby and Velocity writers are not changed here, and they were not checked for the same gap. I can open a follow-up ticket and PR for them on request.
- The test covers a map and a NamedList. Iterator and array values use the same code, but no test covers them.
- No test covers a multivalued field whose values are maps.
