## What happens today

**Grouped faceting on some numeric fields fails with an internal error.**

With `group.facet=true`, a grouping field on a Points field fails, and so does a Trie field with doc values. The grouped facet collector does not accept numeric doc values. The request returns a 500 error with an IllegalStateException about the doc values type, from deep inside Lucene. The ticket shows the same failure when the grouping field is a Points field, and when a single-valued Trie field has doc values.

## What this change does

**Grouped faceting now rejects these numeric fields with a 400 error that names the field.**

The check runs before the collector is built. It rejects a numeric field that is multi-valued, has doc values, or is a Points field ([SimpleFacets.java#L799-L818](https://github.com/nick-boss-tech/solr/blob/e87515c56d048f96850d4586d6e0508dc177e4c7/solr/core/src/java/org/apache/solr/request/SimpleFacets.java#L799-L818)). A single-valued Trie field without doc values keeps working. A Points facet field without doc values already returned a 400 before this check ([L471-L474](https://github.com/nick-boss-tech/solr/blob/e87515c56d048f96850d4586d6e0508dc177e4c7/solr/core/src/java/org/apache/solr/request/SimpleFacets.java#L471-L474)). Enum fields report a numeric type too, so an enum field with doc values is rejected as well.

## Proof

`SimpleFacetsTest.testGroupFacetOnNumericFieldIsBadRequest` is new ([SimpleFacetsTest.java#L609-L667](https://github.com/nick-boss-tech/solr/blob/e87515c56d048f96850d4586d6e0508dc177e4c7/solr/core/src/test/org/apache/solr/request/SimpleFacetsTest.java#L609-L667)). It expects a 400 for numeric fields that use Points or doc values, and counts for a single-valued Trie field without doc values. On the base code (22a8cfebbbdb) with the new test file, the Points and Trie-with-doc-values configurations fail with "expected 400 was 500". The Trie configuration without doc values passes on base, as expected. At head e87515c56d04, verified 2026-10-05, `SimpleFacetsTest` runs 49 tests with 0 failures, 0 errors, and 1 skipped. The new test also passes when forced into each of the three configurations.

## A choice to check

Grouped faceting on these numeric fields can be handled two ways.

- Implemented: reject these configurations with a 400 error that names the field. The change is small, and no grouped counts come back for these fields.
- Alternative: add numeric support to the grouped collector, so these fields return counts. This needs new collector code and a larger change.

Was a clear 400 the right call for this ticket, or should grouped faceting support these numeric fields here?

## Limits

- Numeric fields with doc values or Points still cannot be grouped for faceting. Real support is a separate change. I can open a follow-up ticket and PR on request.
- Multi-valued numeric fields and enum fields are rejected by the same check. The new test does not cover them.
- A Points field without doc values, used as the grouping field, is now rejected. No run covers that case.
- Distributed (sharded) grouped faceting is not tested.
