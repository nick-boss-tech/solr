## What happens today

**A facet.mincount given as a local param is ignored in distributed field faceting, so terms with a count of 0 are listed.**

Take a three-shard collection and a request with `facet.field={!key=k facet.mincount=1}t_s`, plus a filter that leaves some terms with no matching documents. The response lists those terms with a count of 0. The same minimum given as a request parameter is applied ([JIRA](https://issues.apache.org/jira/browse/SOLR-11129)).

## What this change does

**The coordinator now reads the per-field local params of field facets, as the shards already do.**

- Field facet settings from local params take precedence over plain request params, as they do on the shards. A per-field request setting, such as `f.<field>.facet.mincount`, still wins over a local value ([FacetComponent.java L1398](https://github.com/nick-boss-tech/solr/blob/dc82676b8096ed85cb018d4e5b80f6855e5d26d2/solr/core/src/java/org/apache/solr/handler/component/FacetComponent.java#L1398)).
- The coordinator drops merged terms below the field's own minimum count ([L907-L911](https://github.com/nick-boss-tech/solr/blob/dc82676b8096ed85cb018d4e5b80f6855e5d26d2/solr/core/src/java/org/apache/solr/handler/component/FacetComponent.java#L907-L911)). Before, it used the request value, so a local minimum was not applied there.
- The same change also reads facet.limit, facet.sort, facet.prefix, facet.missing, facet.zeros, and the overrequest params from local params. For facet.zeros=false, the coordinator now also drops zero-count terms, whether the setting is local or in the request. It did not do that before.

## Proof

**The new tests fail without the fix and pass at this head.**

- DistributedFacetLocalParamsMinCountTest 1 of 1 passing at dc82676b8096, verified 2026-10-12. With the base FacetComponent.java, the same test fails: the distributed response lists a term with count 0 that the single-node response does not list.
- DistributedFacetLocalParamsOffsetTest 1 of 1 passing at the same head. At the previous head, the same test fails: the distributed response starts the offset page one term later than the single-node response, because the shards and the coordinator each applied the local offset.
- DistributedFacetExistsSmallTest 1 of 1 and DistributedFacetPivotSmallTest 1 of 1 passing at the same head.

## Limits

**Only facet.mincount has a test. The other local params are read but not tested.**

- facet.limit, facet.sort, facet.prefix, facet.missing, facet.zeros, and the overrequest params have no test in this change.
- A local facet.offset is still not honored at the coordinator. The shards apply it, so a distributed request with a local offset can return the wrong page. Not changed here.
- The changelog names facet.mincount only.
