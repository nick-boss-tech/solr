## What happens today

**A schema with no name attribute makes the schema writer throw a NullPointerException.**

`SchemaXmlWriter.writeResponse` calls `toString()` on the schema name with no null check ([SchemaXmlWriter.java, base](https://github.com/apache/solr/blob/e2cdb2d7e8ae0be4cf6cf0606206c67d89e7278f/solr/core/src/java/org/apache/solr/response/SchemaXmlWriter.java#L89)). A schema with no name attribute has no name value to write, so the call fails. The Jira report came from a user who got an unclear error while loading a minimal schema.

The writer runs for `wt=schema.xml` ([SchemaXmlResponseWriter.java](https://github.com/nick-boss-tech/solr/blob/093df0d65bdce7444b3ef9a0da857b9c40edd00c/solr/core/src/java/org/apache/solr/response/SchemaXmlResponseWriter.java#L28)). It also runs when Solr saves a managed schema ([IndexSchema.java](https://github.com/nick-boss-tech/solr/blob/093df0d65bdce7444b3ef9a0da857b9c40edd00c/solr/core/src/java/org/apache/solr/schema/IndexSchema.java#L449-L458)). One caller is [ManagedIndexSchemaFactory.java](https://github.com/nick-boss-tech/solr/blob/093df0d65bdce7444b3ef9a0da857b9c40edd00c/solr/core/src/java/org/apache/solr/schema/ManagedIndexSchemaFactory.java#L390).

## What this change does

**When the name or version is missing, the writer leaves that attribute out.**

The writer writes each attribute only when its value is present ([SchemaXmlWriter.java](https://github.com/nick-boss-tech/solr/blob/093df0d65bdce7444b3ef9a0da857b9c40edd00c/solr/core/src/java/org/apache/solr/response/SchemaXmlWriter.java#L89-L98)). It logs nothing. The schema XML then has no `name` attribute.

## Proof

**One new test fails on the base code and passes with this change. The other focused classes pass.**

[SchemaXmlWriterMissingNameTest](https://github.com/nick-boss-tech/solr/blob/093df0d65bdce7444b3ef9a0da857b9c40edd00c/solr/core/src/test/org/apache/solr/response/SchemaXmlWriterMissingNameTest.java): 1 of 1 passes at head `093df0d65bd`, recorded 2026-10-05. On the base code, the test fails with the NullPointerException in `SchemaXmlWriter.writeResponse`. The counts are for the final test text, which uses `SolrTestCase`.

Same head, other focused classes: TestSolrQueryResponse 15 of 15, TestManagedSchema 15 of 15, and TestSchemaManager with 2 tests, one skipped (an existing `@Ignore`). That is 33 tests in all.

## A choice to check

**The writer leaves the attribute out. The ticket asked for a warning and a default name.**

- Implemented: write no name attribute, and log nothing.
- Ticket route: log a warning and write a default name, so every schema has a name.

Cost of the implemented route: a schema with no name gets no warning, and its XML has no name. Was leaving the attribute out the right call, or should the writer warn and use a default name?

## Limits

**Only the missing-name case can happen with a real schema. The version check is a guard that a real schema cannot trigger.**

Solr always sets a version. It uses 1.0 when the file has none ([IndexSchema.java](https://github.com/nick-boss-tech/solr/blob/093df0d65bdce7444b3ef9a0da857b9c40edd00c/solr/core/src/java/org/apache/solr/schema/IndexSchema.java#L514)). The test calls `SchemaXmlWriter.writeResponse` directly, so it does not run the save path from start to end. If maintainers want that covered, I can open a follow-up ticket and PR on request.
