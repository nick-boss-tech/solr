## What happens today

**`getDocSet` with a `MatchAllDocsQuery` and a filter builds a new DocSet on every call.**

The cached path returns `absAnswer.intersection(filter)` ([SolrIndexSearcher.java](https://github.com/nick-boss-tech/solr/blob/c92bbf9349b12e96918646a73bfaa36248b3d523/solr/core/src/java/org/apache/solr/search/SolrIndexSearcher.java#L1504)). The uncached path combines the query with the filter and collects matching documents ([DocSetUtil.java](https://github.com/nick-boss-tech/solr/blob/c92bbf9349b12e96918646a73bfaa36248b3d523/solr/core/src/java/org/apache/solr/search/DocSetUtil.java#L123-L124)). With no filter, both paths already return the live-documents set.

## What this change does

**`getDocSet(Query, DocSet)` returns the filter itself when the query matches all documents and a filter is given.**

The check runs after a `WrappedQuery` is unwrapped, so an uncached match-all query takes the same shortcut ([SolrIndexSearcher.java](https://github.com/nick-boss-tech/solr/blob/c92bbf9349b12e96918646a73bfaa36248b3d523/solr/core/src/java/org/apache/solr/search/SolrIndexSearcher.java#L1484-L1487)). With no filter, the method still returns the live-documents set.

Behavior changes, stated openly:

- With a filter, the caller gets the same DocSet object it passed in. The result is not intersected with the live documents. That matches the old result only when the filter holds no deleted documents.
- The uncached path no longer collects matching documents for this case.

## A choice to check

**The shortcut trusts the filter to hold only live documents.**

Option one is what this change does: return the filter as it is, which skips the intersection. Option two keeps an intersection with the live documents on this path. That keeps the old result for any filter, at the cost of the work this change removes. Was returning the filter as it is the right call?

## Proof

**TestIndexSearcher 6 of 6 passes at head c92bbf9349b12e96918646a73bfaa36248b3d523, verified 2026-10-09.**

On the code before this change, with the new test in place, TestIndexSearcher runs 6 tests and exactly 1 fails: the new test, `testMatchAllDocsWithFilterReturnsFilter` ([TestIndexSearcher.java](https://github.com/nick-boss-tech/solr/blob/c92bbf9349b12e96918646a73bfaa36248b3d523/solr/core/src/test/org/apache/solr/search/TestIndexSearcher.java#L172-L197)).

## Limits

- Only `getDocSet(Query, DocSet)` changes. `getDocSetNC`, `getPositiveDocSet` and `DocSetUtil.createDocSet` keep their current paths, so a direct call to `DocSetUtil.createDocSet` with a match-all query and a filter still takes the generic path.
- The method's javadoc says callers must not modify the returned DocSet. The filter object is now returned as it is, so that rule applies to it too.
- No test covers a filter that holds a deleted document.
- If maintainers want the same shortcut in `DocSetUtil.createDocSet`, I can open a follow-up ticket and PR on request.
