## What happens today

**A streaming daemon is listed only on the replica that runs it.**

Each StreamHandler keeps its own map of daemons ([StreamHandler.java, base](https://github.com/apache/solr/blob/22a8cfebbbdb026437d10b0aa47bb66ffdb23a9a/solr/core/src/java/org/apache/solr/handler/StreamHandler.java#L91)). Solr starts a daemon on one replica, picked at random. A list, stop, or kill request that lands on another core of the same collection on that node does not see it. The ticket's comments say the problem needs two replicas of one collection on the same node.

## What this change does

**Daemons are kept per collection on each node, so list, start, stop and kill see all of the collection's daemons on that node.**

On SolrCloud, [StreamHandler.java](https://github.com/nick-boss-tech/solr/blob/16e62ab654257b475ac07ee128686626bd1c8631/solr/core/src/java/org/apache/solr/handler/StreamHandler.java#L113-L126) keys the daemon map by collection name in the node's object cache. Two effects follow:

- A start with a name that a daemon on another replica of the collection already uses stops that daemon, then starts the new one.
- The map is not cleared when a core closes. A daemon still running after its collection is deleted stays listed under that name.

## Proof

**One new test fails on the base code and passes with this change. An existing test in the same file also fails on the base code, but that failure does not isolate this change.**

[DaemonStreamApiTest](https://github.com/nick-boss-tech/solr/blob/16e62ab654257b475ac07ee128686626bd1c8631/solr/core/src/test/org/apache/solr/handler/admin/DaemonStreamApiTest.java#L204-L245): 2 of 2 pass at head `16e62ab6542`, recorded 2026-10-05. On the base StreamHandler, with this change's test file, `testDaemonListedOnEveryCoreOfCollection` fails with "daemon not listed by core checkpointColl_shard2_replica_n2". `testAPIs` also fails there. The test file now creates a two-shard collection, so that failure comes from the test change and does not isolate the handler change.

## A choice to check

**Scope: one node, or the whole collection.**

- Implemented: daemons are shared by the replicas of one collection on one node. A daemon on another node is not listed.
- Collection-wide: the ticket comments name two ways to do this. Daemons register in ZooKeeper, or the handler asks every replica for its daemons. Cost: more state in ZooKeeper, or a request to each replica on every list.

Was a node-level fix the right first step, or should the collection-wide version come first?

## Limits

- Daemons running on another node are not listed by this change.
- The test runs one node with two shards, so it covers only co-located replicas.
- A daemon still running after its collection is deleted stays listed under that collection name until it stops. No test covers this.
