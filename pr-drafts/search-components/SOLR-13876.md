## What happens today

**Every expanded group reports maxScore as NaN, even when the request asks for scores.**

Before this change, the expand component gave each group a fixed `Float.NaN` max score ([ExpandComponent.java](https://github.com/nick-boss-tech/solr/blob/b5c71bc5573c4e31b4cee5a7965d73587fc0ae58/solr/core/src/java/org/apache/solr/handler/component/ExpandComponent.java#L787)). The XML response wrote that value as `maxScore="NaN"` on the group's `result` element when `fl` includes `score`.

## What this change does

**Each group reports the highest score among the documents returned for that group.**

When `fl` includes `score`, the code takes the largest score in each group slice ([ExpandComponent.java](https://github.com/nick-boss-tech/solr/blob/2e110473dbada4f6a0e23a903a4e002da2b78143/solr/core/src/java/org/apache/solr/handler/component/ExpandComponent.java#L780-L790)). It works for the relevance sort and for other `expand.sort` values. Requests without `score`, and `expand.rows=0`, give the same output as before.

## Proof

**TestExpandComponent passes 9 of 9 with this change. On the base code, 7 of the 9 tests fail.**

Verified 2026-10-07 at head 2e110473dbad. With the base production code and this branch's test file, 7 of the 9 tests fail, and every failure is a maxScore check. With this change, all 9 pass. The new test, `testExpandMaxScore`, covers a relevance sort and a non-score `expand.sort`. Its documents use a function query for the score, so the expected value is exact (30.0).

## A choice to check

**The maximum covers the returned documents of each group, not every document in the group.**

- Implemented: slice-local. The maximum is over the documents returned for each group, so it follows `expand.rows`. It works for any `expand.sort` and adds no extra scoring. For the relevance sort it equals the group maximum, because the top scored documents come back first.
- Alternative: group-wide. The maximum is over every matching document in the group. With another `expand.sort`, Solr fills in scores only for the documents it returns, so this option would need scores for documents the page does not return. The cost was not measured.

Was slice-local the right call, or should `maxScore` be the group-wide maximum?

## Limits

**The new tests do not cover multi-shard requests or a group-wide maximum.**

- No new test checks `maxScore` across shards. The coordinator passes each shard's expanded groups through unchanged ([ExpandComponent.java](https://github.com/nick-boss-tech/solr/blob/2e110473dbada4f6a0e23a903a4e002da2b78143/solr/core/src/java/org/apache/solr/handler/component/ExpandComponent.java#L475-L520)).
- The new test returns every expanded document of its group, so it does not cover a higher scoring document outside the returned slice.
- The other open Expand change, SOLR-13568 in [apache/solr #5014](https://github.com/apache/solr/pull/5014), changes filter caching only. It does not change scores or the documents returned, so the two can merge in either order.
