## What happens today

**In SolrCloud, `debug=query` does not reliably return the json.facet facet-trace.**

Shards collect facet debug information only when they are in debug mode themselves ([FacetModule.java line 150](https://github.com/apache/solr/blob/8e62c2686882aa704480ab13b6a60ee8f7b5c8af/solr/core/src/java/org/apache/solr/search/facet/FacetModule.java#L150)). For a request that is not a field fetch, [DebugComponent.java lines 176-178](https://github.com/nick-boss-tech/solr/blob/e60891d8716d89538109407aadc629987456017a/solr/core/src/java/org/apache/solr/handler/component/DebugComponent.java#L176-L178) sets `debug` and `debug.query` to `false` on the shard request. The shards therefore do not build the facet trace for `debug=query`. The ticket reports that `debug=true` does return it.

## What this change does

**Facet shard requests get query debugging when the user asked for query debugging.**

For the two facet purposes only, `DebugComponent.modifyRequest` adds `debug=query` to the shard request when the coordinating request has query debugging on ([DebugComponent.java lines 179-189](https://github.com/nick-boss-tech/solr/blob/e60891d8716d89538109407aadc629987456017a/solr/core/src/java/org/apache/solr/handler/component/DebugComponent.java#L179-L189)). Timing and track modes keep their current behavior, and a results-only request does not gain query debugging on the shards.

## Proof

**A new unit test fails on the base code and passes with this change.**

[DebugComponentTest](https://github.com/nick-boss-tech/solr/blob/e60891d8716d89538109407aadc629987456017a/solr/core/src/test/org/apache/solr/handler/component/DebugComponentTest.java#L197-L243) 7 of 7 passes at head e60891d8716, verified 2026-10-07. `testModifyRequestFacetPurposeDebugModes` fails on the base code (1 failure in that class) and passes with this change.

[TestCloudJSONFacetSKGEquiv](https://github.com/nick-boss-tech/solr/blob/e60891d8716d89538109407aadc629987456017a/solr/core/src/test/org/apache/solr/search/facet/TestCloudJSONFacetSKGEquiv.java#L269) 7 of 7 passes at the same head. Its two facet checks now send `debug=query` instead of `debug=true`. That class was not run on the base code, so the cloud test does not show the failure by itself.

## A choice to check

**Only query debugging is forwarded to facet shard requests.**

The alternative is to forward every debug mode the user asked for. That would also send shard diagnostics for `debug=results` and `debug=timing`, which could be harmless but is a behavior change. The implemented route forwards only query debugging. Was that the right call?

## Limits

- The unit test covers the query, results and timing modes. `debug=true` is not tested on its own there.
- The cloud test change only swaps the debug value. It was not compared against the base code.
