## What happens today

**Nested children from `[child]` are missing from a search response unless `fl` lists the nest-path fields or uses `*`.**

For `fl=id,[child]`, the transformer attaches the children under their nest paths, such as `toppings` and `lonely`. The response writers skip any field that `fl` does not name ([JSONWriter.java L97](https://github.com/nick-boss-tech/solr/blob/5d94e6cf3981bd8a141a2063992148893e6d1bbb/solr/core/src/java/org/apache/solr/response/JSONWriter.java#L97), [SolrReturnFields.java L554-L566](https://github.com/nick-boss-tech/solr/blob/5d94e6cf3981bd8a141a2063992148893e6d1bbb/solr/core/src/java/org/apache/solr/search/SolrReturnFields.java#L554-L566)). The children are dropped.

## What this change does

**Each document keeps the nested children the transformer attached to it, in search responses.**

The child transformer records the names it attaches to the document it is transforming, and clears them at the start of each transform ([ChildDocTransformer.java L342-L350, L153](https://github.com/nick-boss-tech/solr/blob/5d94e6cf3981bd8a141a2063992148893e6d1bbb/solr/core/src/java/org/apache/solr/response/transform/ChildDocTransformer.java#L342-L350)). The field check accepts a recorded name while that document is written ([SolrReturnFields.java L558](https://github.com/nick-boss-tech/solr/blob/5d94e6cf3981bd8a141a2063992148893e6d1bbb/solr/core/src/java/org/apache/solr/search/SolrReturnFields.java#L558)). The names reach the field check through a new `getExtraResponseFields()` hook on the transformer base class and on the wrapper that holds several transformers ([DocTransformer.java L119-L140](https://github.com/nick-boss-tech/solr/blob/5d94e6cf3981bd8a141a2063992148893e6d1bbb/solr/core/src/java/org/apache/solr/response/transform/DocTransformer.java#L119-L140)).

The behavior change is this: a field whose name matches a nest path is written when the child transformer attached it, even when `fl` does not name it. An ordinary field on another document with the same name is still filtered out.

## A choice to check

**The nest-path names apply to the document being written, not to the whole response.**

Options considered: keep the names for each document, so they apply only while that document is written (implemented), or keep one set for the whole response. The second option is simpler, and it also works for a writer that reads a document after later documents were transformed. But an ordinary root field that shares a nest-path name would then pass a field list that leaves it out. The first option has the cost named in Limits. Was per-document scope the right call?

## Limits

- Real-time get with several ids (`/get?ids=`) transforms every document before it writes the response ([RealTimeGetComponent.java L366-L375](https://github.com/nick-boss-tech/solr/blob/5d94e6cf3981bd8a141a2063992148893e6d1bbb/solr/core/src/java/org/apache/solr/handler/component/RealTimeGetComponent.java#L366-L375)). There, only the last document keeps its nested children when `fl` omits the nest-path fields. No test covers `/get`. We plan a follow-up for this path that keeps the names with each document, so a writer can check them for that document.
- A `fl` with two transformers uses the aggregation in `DocTransformers`. No test covers that combination.
- No test in this change runs a SolrCloud or distributed request.
