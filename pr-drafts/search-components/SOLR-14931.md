## What happens today

**On a SolrCloud request, macros in a handler's appends and invariants stay unexpanded on the shards.**

The Jira report uses a `/myhandler` with `appends` `fl=term_appends:'${my_term}'`. The coordinator expands the macro. The shard applies the handler's appends again and the macro reaches the document as literal text: `"term_appends": "${my_term}"`. The defaults value is expanded, so the mismatch shows only for appends.

## What this change does

**Shards now expand macros in the handler's appends and invariants, using the request parameters as the macro source.**

`RequestUtil.processParams` passes the appends and invariants values through `expandConfigMacros` ([appends](https://github.com/nick-boss-tech/solr/blob/1a7d678d9a158455b0a6afca47c215ddf88b5a0a/solr/core/src/java/org/apache/solr/request/json/RequestUtil.java#L147), [invariants](https://github.com/nick-boss-tech/solr/blob/1a7d678d9a158455b0a6afca47c215ddf88b5a0a/solr/core/src/java/org/apache/solr/request/json/RequestUtil.java#L166), [helper](https://github.com/nick-boss-tech/solr/blob/1a7d678d9a158455b0a6afca47c215ddf88b5a0a/solr/core/src/java/org/apache/solr/request/json/RequestUtil.java#L282-L292)). `MacroExpander` gets an `expand` method that reads macro values from a separate map, so the request's parameters can supply them.

Behavior changes, stated openly:

- The handler's invariants are now macro-expanded on shard requests too.
- A shard request with `expandMacros=false` skips this expansion for those values.
- Values the client sent are still not expanded on shard requests.

## A choice to check

The Jira report suggests the other route: do not apply the handler's appends and invariants a second time on shard requests. That route changes shard behavior for every appends and invariants value, not only for macros, and the report notes the author did not know whether that breaks something else. This change expands the values on the shard instead. Was expanding on the shard the right call, or should shards skip the second application?

## Proof

## Limits

- The cluster test checks one field value of the appended pseudo-field. It does not check how many times the `fl` parameter carries the appended entry on a shard.
- Defaults handling is unchanged.
