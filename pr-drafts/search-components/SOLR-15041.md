## What happens today

**When a split field value has a line break, only the text before the first break is kept.**

With `f.<field>.split=true`, the loader splits each field value on the separator. It reads only the first CSV record of the value ([CSVLoaderBase.java, base](https://github.com/apache/solr/blob/b5c71bc5573c4e31b4cee5a7965d73587fc0ae58/solr/core/src/java/org/apache/solr/handler/loader/CSVLoaderBase.java#L147-L151)). The rest of the value is dropped, including any separator after the break. A quoted field that holds `first line`, a line break, then `with break!second line` loads as one value, `first line`.

## What this change does

**Line breaks inside a split value are kept, and the split continues after them.**

After the first record, each later record is joined to the last value with the line break that came before it ([CSVLoaderBase.java](https://github.com/nick-boss-tech/solr/blob/55fca0a7c2431f0fe335aaf6fb7387c7343a66bd/solr/core/src/java/org/apache/solr/handler/loader/CSVLoaderBase.java#L168-L181)). The breaks are found by scanning the value outside quoted sections ([lines 193-242](https://github.com/nick-boss-tech/solr/blob/55fca0a7c2431f0fe335aaf6fb7387c7343a66bd/solr/core/src/java/org/apache/solr/handler/loader/CSVLoaderBase.java#L193-L242)). CRLF stays CRLF.

## Limits

**Not covered: a blank line inside a split value, a lone CR, and escaped encapsulators. The test covers LF and CRLF with a `!` separator.**

If maintainers want those cases covered, I can open a follow-up ticket and PR on request.
