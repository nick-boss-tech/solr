## What happens today

**SolrJ drops the count of the `missing` bucket from a terms facet response, so client code cannot read it.**

When a JSON facet terms request sets `missing`, the server adds a `missing` entry with a `count` ([FacetFieldProcessor.java](https://github.com/nick-boss-tech/solr/blob/b5c71bc5573c4e31b4cee5a7965d73587fc0ae58/solr/core/src/java/org/apache/solr/search/facet/FacetFieldProcessor.java#L470)). `BucketBasedJsonFacet` reads the other top-level keys, such as `allBuckets`, `before`, `after` and `between`, but not `missing`. An unknown key falls into a branch that ignores it ([BucketBasedJsonFacet.java](https://github.com/nick-boss-tech/solr/blob/b5c71bc5573c4e31b4cee5a7965d73587fc0ae58/solr/solrj/src/java/org/apache/solr/client/solrj/response/json/BucketBasedJsonFacet.java#L73-L77)). The reporter could see the count in the raw response but not through SolrJ.

## What this change does

**`BucketBasedJsonFacet` reads the `missing` entry and exposes it through a new `getMissingCount()` method.**

- The constructor stores the count of the `missing` entry ([BucketBasedJsonFacet.java](https://github.com/nick-boss-tech/solr/blob/6769b4cd8a12d8606a1616c6269c2fdb224d019b/solr/solrj/src/java/org/apache/solr/client/solrj/response/json/BucketBasedJsonFacet.java#L74-L75)).
- `getMissingCount()` returns that count. It returns `UNSET_FLAG` (-1) when the response has no `missing` entry ([BucketBasedJsonFacet.java](https://github.com/nick-boss-tech/solr/blob/6769b4cd8a12d8606a1616c6269c2fdb224d019b/solr/solrj/src/java/org/apache/solr/client/solrj/response/json/BucketBasedJsonFacet.java#L145-L153)).
- The class comment lists `missing` with the other top-level properties.

## Limits

- The server can leave the `missing` entry out when a higher `mincount` drops it (SOLR-17051). In that case `getMissingCount()` returns `UNSET_FLAG` for a request that set `missing`. If SOLR-17051 lands first or in the same release, the Javadoc on `getMissingCount()` should say that `UNSET_FLAG` is also returned in that case. Proposed sentence: "`UNSET_FLAG` is returned if the user did not request the bucket, or if the server left it out, for example when a `mincount` above 1 drops it."
- Only the SolrJ parser changes. No server behavior changes in this PR.
- No end-to-end test against a running server is included.
