## What happens today

**With an `rq` rerank, maxScore keeps the highest score from before the rerank.**

The ticket's example: `q=id:IW-02` returns score 1.4050193 and maxScore 1.4050193. Adding `rq={!rerank reRankQuery=$x}` returns the same document with score 3.9578552, but maxScore stays at 1.4050193. The searcher reads its maximum while it collects, before the rerank changes the scores ([base](https://github.com/nick-boss-tech/solr/blob/b5c71bc5573c4e31b4cee5a7965d73587fc0ae58/solr/core/src/java/org/apache/solr/search/SolrIndexSearcher.java#L1911-L1914)).

## What this change does

**For a request that uses a rank query, maxScore is now the highest final score in the collected result window.**

The searcher takes the highest score among the documents in the collected window after the rerank ([source](https://github.com/nick-boss-tech/solr/blob/57bd53ce4d07a4a392456db5318d52d64f5680a2/solr/core/src/java/org/apache/solr/search/SolrIndexSearcher.java#L1827-L1846)). Requests without a rank query are unchanged. Behavior changes, stated openly:

- The window is the collected result window: the superset the searcher collects, at least the result window size. It is not only the returned page, so a document that is not on the page can set maxScore.
- A document outside the rerank window keeps its original score. It can set maxScore when it is in the collected window.
- Single-threaded and multi-threaded searches use the same rule, and the tests run both.

## A choice to check

**maxScore covers the collected result window, not only the returned page.**

Options considered:

1. The highest final score in the collected result window (implemented). A different page size does not change the value within the window. The cost is that maxScore can come from a document that is not on the page.
2. The highest final score on the returned page only. It matches what the caller sees on the page. The cost is that maxScore changes with the page size (rows) for the same query.

Was the collected-window scope the right call?

## Limits

- A request with `rows=0` that does not collect a result window (no query result cache for the request) still reports the score from before the rerank. None of the three new tests covers this path. A follow-up can cover it on request.
