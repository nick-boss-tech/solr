## What happens today

**A stop filter factory created after its managed stopword list has loaded never receives the list. Its first use fails with "Managed stopwords not initialized correctly!"**

The Jira report shows `SolrException: Exception writing document ... possible analysis error` during document updates. The cause in the report is `IllegalStateException: Managed stopwords not initialized correctly!`. The factory's stop word set stays null, so `create()` throws. The report describes the failure as intermittent, with the list configured.

## What this change does

**A registration for a resource that is already loaded now gets the loaded data at once.**

Before, an observer that registered after the resource had loaded was added to the registration and never called. Now the new observer is called right away with the loaded init args ([RestManager](https://github.com/nick-boss-tech/solr/blob/8ffee94a5e75b17f5b5f8be9f840862a1a56524e/solr/core/src/java/org/apache/solr/rest/RestManager.java#L230-L242)). Observers that were already registered are not called again.

Behavior change, stated openly: a component that registers late is now initialized during that registration call. Before, it stayed empty.

In `TestManagedStopFilterFactory` it is [`testLateRegisteredStopFilterFactoryIsInitialized`](https://github.com/nick-boss-tech/solr/blob/8ffee94a5e75b17f5b5f8be9f840862a1a56524e/solr/core/src/test/org/apache/solr/rest/schema/analysis/TestManagedStopFilterFactory.java#L199-L242). It fails with the same `IllegalStateException` as the report.

## Limits

- This change covers one path that throws the same exception. I have not confirmed that the reporter's setup takes that path. The report's question about the standard stopword filter is not answered here.
- The regression test builds the late factory by hand and calls `inform`. It does not go through a schema reload.
- Other registration paths are unchanged.
