## What happens today

**`SolrIndexSearcherTest` has no test that compares a multi-threaded search with a single-threaded one, and the benchmark module cannot run a numeric range query with the multi-threaded flag.**

The multi-threaded search path is covered elsewhere, but not in this class. The benchmark module has no switch for the multi-threaded flag, so it cannot compare the two paths on a sorted numeric range query ([NumericSearch, head `478731e676`, line 68](https://github.com/nick-boss-tech/solr/blob/478731e676021c20a1dff6d412ff706b7e99925d/solr/benchmark/src/java/org/apache/solr/bench/search/NumericSearch.java#L68)).

## What this change does

**Two tests are added to `SolrIndexSearcherTest`, and the benchmark gets a multi-threaded switch and a range query.**

- `testMultiThreadedSearchMatchesSingleThreadedResults` runs one search with the multi-threaded flag off and one with it on, both sorted by id. It compares the match count, the document order and the scores ([head, lines 188 to 216](https://github.com/nick-boss-tech/solr/blob/478731e676021c20a1dff6d412ff706b7e99925d/solr/core/src/test/org/apache/solr/search/SolrIndexSearcherTest.java#L188-L216)).
- `testReRankCollectorFallsBackWhenRescoringAborts` checks that a re-rank collector returns the first-pass results when rescoring stops. It does not involve multi-threading ([head, line 139](https://github.com/nick-boss-tech/solr/blob/478731e676021c20a1dff6d412ff706b7e99925d/solr/core/src/test/org/apache/solr/search/SolrIndexSearcherTest.java#L139)).
- `NumericSearch` gets a `multiThreaded` parameter with values false and true, and a new `intRange` benchmark that runs a sorted numeric range query ([lines 68 to 80](https://github.com/nick-boss-tech/solr/blob/478731e676021c20a1dff6d412ff706b7e99925d/solr/benchmark/src/java/org/apache/solr/bench/search/NumericSearch.java#L68-L80), [line 272](https://github.com/nick-boss-tech/solr/blob/478731e676021c20a1dff6d412ff706b7e99925d/solr/benchmark/src/java/org/apache/solr/bench/search/NumericSearch.java#L272)).
- The benchmark `solr.xml` reads `indexSearcherExecutorThreads`, with a default of 0 ([line 29](https://github.com/nick-boss-tech/solr/blob/478731e676021c20a1dff6d412ff706b7e99925d/solr/benchmark/src/resources/solr.xml#L29)).

No server code changes. The related change for faster DocSet collection when `multiThreaded` is set, [PR #4724](https://github.com/apache/solr/pull/4724), is already in this branch's base.
