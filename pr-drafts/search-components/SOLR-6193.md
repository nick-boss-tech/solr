## What happens today

**In distributed search, the local params of a `facet.pivot` are ignored when shard responses are merged.**

For example, `facet.pivot={!facet.limit=4 facet.sort=index}place_s,company_t` returns the default limit of 100 values for the top field. A single-node search of the same request returns 4. The merge reads `facet.limit`, `facet.sort`, `facet.offset` and `facet.pivot.mincount` only from the request parameters, in [PivotFacetField.java](https://github.com/apache/solr/blob/c3cdf7b46e8cfff3673f76d881f32cf8e7b00622/solr/core/src/java/org/apache/solr/handler/component/PivotFacetField.java#L64-L67).

## What this change does

**This change covers distributed `facet.pivot` only. It does not change the `facet.field` case in the ticket.**

The top field of each pivot now reads its settings from the local params, layered over the request parameters ([PivotFacetField.java](https://github.com/nick-boss-tech/solr/blob/ec94bf50c80ce75b44eaf78452e60e43972bc284/solr/core/src/java/org/apache/solr/handler/component/PivotFacetField.java#L68-L74)). Nested fields reuse the settings of their top field. The coordinator passes the local params in [PivotFacet.java](https://github.com/nick-boss-tech/solr/blob/ec94bf50c80ce75b44eaf78452e60e43972bc284/solr/core/src/java/org/apache/solr/handler/component/PivotFacet.java#L154).

## A choice to check

**A local value loses to a request setting for the same field.**

- Keep the current order (implemented here): a request setting such as `f.place_s.facet.limit` beats a plain local `facet.limit`. A single-node search uses the same order ([SimpleFacets.java](https://github.com/nick-boss-tech/solr/blob/ec94bf50c80ce75b44eaf78452e60e43972bc284/solr/core/src/java/org/apache/solr/request/SimpleFacets.java#L191)).
- Let the plain local value win. This matches the ticket's example, where a local `facet.offset=10` is expected to beat `f.blah.facet.offset=20`. It also changes single-node results.

Was keeping the current order the right call for this change?

## Limits

**Not covered: the ticket's `facet.field` example, shard request sizing, and local offset and mincount.**

- The `facet.field` example in SOLR-6193 is not changed here. A follow-up for that path can be opened on request.
- The shard request is still sized from the request-level `facet.limit` and `facet.offset` ([FacetComponent.java](https://github.com/nick-boss-tech/solr/blob/ec94bf50c80ce75b44eaf78452e60e43972bc284/solr/core/src/java/org/apache/solr/handler/component/FacetComponent.java#L637-L645)). A local `facet.limit` above 100, or `-1`, can get fewer values from each shard than it needs. The added tests do not show whether this happens with more values per field.
- A local `facet.offset` and a local `facet.pivot.mincount` are also read at merge. No test covers them, and the shards also read a local offset, so the result may be wrong. This change does not claim that either one works. A follow-up can add tests on request.
