## What happens today

**A shard with no response makes the global stats merge throw a NullPointerException.**

When no server answers for a shard, that shard's response has no body. The merge loop calls `getException()` on the response first ([ExactStatsCache.java lines 116-120 at the merge-base](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/search/stats/ExactStatsCache.java#L116-L120)). That method reads the body before anything checks for it ([SolrResponse.java lines 48-49 at the merge-base](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/solrj/src/java/org/apache/solr/client/solrj/SolrResponse.java#L48-L49)). The merge-base has no check for a missing body before that call.

## What this change does

**A shard with no response is now skipped in the global stats merge.**

- The merge reads the response body first and skips the shard when the body is missing ([ExactStatsCache.java lines 116-126 at the head](https://github.com/nick-boss-tech/solr/blob/d4fe2e6f6620e918d29eeb63fe481cf28ec9645f/solr/core/src/java/org/apache/solr/search/stats/ExactStatsCache.java#L116-L124)).
- A shard that returned an error was already skipped at that point. The new check follows the same rule.
- The skipped shard's term statistics are left out of the global merge. Only a debug log line records it.

## Proof

**A new test fails on the base code and passes with this change.**

- `ExactStatsCacheMergeTest.testShardWithoutResponseIsSkipped` ([test lines 33-43](https://github.com/nick-boss-tech/solr/blob/d4fe2e6f6620e918d29eeb63fe481cf28ec9645f/solr/core/src/test/org/apache/solr/search/stats/ExactStatsCacheMergeTest.java#L33-L43)) gives the merge a shard response with no body and no error, next to a shard that answered with a term. It then checks that only the answering shard's term is merged.
- Verified 2026-10-15 at head d4fe2e6f6620: ExactStatsCacheMergeTest 1 of 1 and ExactStatsCacheNoAnswerTest 1 of 1. On the base code the merge test fails with the NullPointerException in the global stats merge.
- `ExactStatsCacheNoAnswerTest.testTolerantNoAnswerShardIsSkippedBeforeBodyRead` builds the state that `HttpShardHandler` records for a shard no server answered: an exception and no body. It also passes on the base code, because the tolerant skip it exercises predates this change; it pins that path while the merge test carries the new behavior.

## Limits

**The tests check the merged terms, not the full global stats.**

- `ExactStatsCacheMergeTest` asserts the merged term set only. It does not check docFreq or totalTermFreq.
- [SOLR-15319](https://issues.apache.org/jira/browse/SOLR-15319) lands after this change. Its branch has the same null-response path and does not fix it. If the two edits to `ExactStatsCache` overlap, that branch is rebased onto this one.
