## What happens today

**A real-time get leaves out stored fields that a schema copies into.**

Suppose a schema has a stored field `b` and a copy rule from `a` to `b`. A document is indexed with `b` set directly. A real-time get does not return `b`, although a search does once the document is committed. The same field is also missing from a document that has not been committed yet, and from a document built by an in-place update. The test schema uses the same pattern, with `author` copied into `author_s` ([schema_latest.xml](https://github.com/nick-boss-tech/solr/blob/14c7aac0d151402b00259e2fb9bf5eed7049ec5d/solr/core/src/test-files/solr/collection1/conf/schema_latest.xml#L312)).

Before this change, two filters caused it. Both are shown at the merge base, 14c7aac0d151. The update log removed copy-field targets after it resolved an in-place update ([L298-L299](https://github.com/nick-boss-tech/solr/blob/14c7aac0d151402b00259e2fb9bf5eed7049ec5d/solr/core/src/java/org/apache/solr/handler/component/RealTimeGetComponent.java#L298-L299)). The conversion to a response skipped them ([L916-L917](https://github.com/nick-boss-tech/solr/blob/14c7aac0d151402b00259e2fb9bf5eed7049ec5d/solr/core/src/java/org/apache/solr/handler/component/RealTimeGetComponent.java#L916-L917)).

## What this change does

**The response keeps stored copy-field targets, with the same values the index holds after a commit. Atomic updates still drop them.**

- The conversion to a response no longer skips copy-field targets ([L889-L899](https://github.com/nick-boss-tech/solr/blob/3b5f2d2357325ba993fe1d2716fafee55741fc1b/solr/core/src/java/org/apache/solr/handler/component/RealTimeGetComponent.java#L889-L899)). The update-log removal is gone.
- The atomic-update path still skips them ([L860](https://github.com/nick-boss-tech/solr/blob/3b5f2d2357325ba993fe1d2716fafee55741fc1b/solr/core/src/java/org/apache/solr/handler/component/RealTimeGetComponent.java#L860)). A copied value is not written back as if the client had sent it, and the schema's copy rule fills it in again.
- Behavior change: the default `/get` response now includes these fields for any document that has them. A request that names one in `fl` gets it.

## Proof

**At least one of the three new tests fails on the base code. With the change, all of TestRealTimeGet passes.**

- [TestRealTimeGet](https://github.com/nick-boss-tech/solr/blob/3b5f2d2357325ba993fe1d2716fafee55741fc1b/solr/core/src/test/org/apache/solr/search/TestRealTimeGet.java#L46-L91) 7 of 7 at `3b5f2d2357325ba993fe1d2716fafee55741fc1b`, verified 2026-10-03. The three new tests cover a value read before any commit, a value read after a commit, and an atomic update of a document with a copy-field target.

## A choice to check

**The default `/get` response now includes copy-field targets. The other route keeps them out unless a request asks for them.**

The route taken returns them by default, so a real-time get shows the same values the index holds after a commit. The other route adds an opt-in parameter and keeps today's default. The cost of the route taken is a changed default response for any document with a copy-field target. Was returning them by default the right call, or should a request opt in?

## Limits

**Some effects are not covered here, and one follow-up is named.**

- The Cloud MLT parser reads field names from the `/get` document ([CloudMLTQParser.java L87-L99](https://github.com/nick-boss-tech/solr/blob/3b5f2d2357325ba993fe1d2716fafee55741fc1b/solr/core/src/java/org/apache/solr/search/mlt/CloudMLTQParser.java#L87-L99)). Copy-field targets with an explicit analyzer can now join its default fields. A comment at [L118-L119](https://github.com/nick-boss-tech/solr/blob/3b5f2d2357325ba993fe1d2716fafee55741fc1b/solr/core/src/java/org/apache/solr/search/mlt/CloudMLTQParser.java#L118-L119) says `/get` leaves copy-field targets out, which is no longer true. Neither is changed here. A follow-up ticket and PR for the comment and the MLT behavior can be opened on request.
- Writes after a read are not tested. A client that reads a document with `/get` and writes it back now sends the target fields too.
- Only TestRealTimeGet is run for this description. Other suites that use `/get` are not run here.
- The base-code result is recorded for the three tests together. Which one fails on the base code is not broken down here.
