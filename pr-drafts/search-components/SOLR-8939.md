## What happens today

**A date unique key loses its milliseconds when the coordinator asks the shards for stored fields.**

A distributed query sends each hit's unique key back to the shards in the `ids` parameter. For a date key, the code wrote the value with `Date.toString()`, which has no milliseconds. The shard then gets a value that no longer matches the stored key, so a hit can be missing or an error can follow. The ticket reports both symptoms.

Two hits whose keys render to the same string can also collapse into one during the merge. The merge collects the page's hits in a map keyed by that string, so two documents with date keys in the same second leave one entry, and the other hit never reaches the response.

## What this change does

**Date keys are sent as ISO-8601 text with milliseconds, on the plain and the grouping stored-fields paths.**

- A new helper, `QueryComponent.idToString`, formats a `Date` with `Instant.toString()`. Other key types still use `toString()` ([QueryComponent.java L1463](https://github.com/nick-boss-tech/solr/blob/1a4a312bb7ab034fd932018691e76c86309f3b3d/solr/core/src/java/org/apache/solr/handler/component/QueryComponent.java#L1463)).
- The plain path calls the helper when it builds the `ids` parameter ([L1451](https://github.com/nick-boss-tech/solr/blob/1a4a312bb7ab034fd932018691e76c86309f3b3d/solr/core/src/java/org/apache/solr/handler/component/QueryComponent.java#L1451)).
- The grouping path calls it too ([StoredFieldsShardRequestFactory.java L79](https://github.com/nick-boss-tech/solr/blob/1a4a312bb7ab034fd932018691e76c86309f3b3d/solr/core/src/java/org/apache/solr/search/grouping/distributed/requestfactory/StoredFieldsShardRequestFactory.java#L79)).

## Proof

**The date test fails on the base code and passes with this change.**

- `StoredFieldsShardRequestFactoryTest` 2 of 2 and `QueryComponentIdFormatTest` 4 of 4 pass at `1a4a312bb7`, verified 2026-10-15. On the base code, `testDateUniqueKeyIsSentAsIsoWithMilliseconds` fails: the key is sent as `Mon Mar 21 06:15:30 AST 2016` instead of `2016-03-21T10:15:30.123Z`. The string-key test passes on both. On the base code the new `testSameSecondDateKeysAllReachThePage` also fails: 2 documents reach the page where 3 were expected.
- The remaining `QueryComponentIdFormatTest` tests call the new helper directly, so they do not compile on the base code and give no failing-before result.
- The proof is at unit level. No run with two or more shards was made.

## Limits

**The proof is at unit level only: no run uses two or more shards.**

- No run with two or more shards. The plain path is covered through the helper it calls, not by a run through the coordinator.
- A date with zero milliseconds is sent without a fraction, for example `2016-03-21T10:15:30Z`. The test `testDateKeyWithoutMillisecondsUsesIsoForm` covers that form.
- `idToString` is public because the grouping request factory is in another package.
