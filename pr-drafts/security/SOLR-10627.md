## What happens today

**A per-collection permission such as `update` can be saved with `"collection": null`, and that entry does not apply to requests routed to a collection.**

The Security API accepts `{"name": "update", "collection": null, "role": "some-role"}` in a set-permission command. Before this change, the set-permission step only loaded the entry ([AutorizationEditOperation.java L73-L78, base](https://github.com/nick-boss-tech/solr/blob/14c7aac0d151402b00259e2fb9bf5eed7049ec5d/solr/core/src/java/org/apache/solr/security/AutorizationEditOperation.java#L73-L78)). A request routed to a collection checks the entries for that collection and the `*` entries ([RuleBasedAuthorizationPluginBase.java L110-L123, base](https://github.com/nick-boss-tech/solr/blob/14c7aac0d151402b00259e2fb9bf5eed7049ec5d/solr/core/src/java/org/apache/solr/security/RuleBasedAuthorizationPluginBase.java#L110-L123)). Entries with a null collection are checked only for admin requests ([L104-L108, base](https://github.com/nick-boss-tech/solr/blob/14c7aac0d151402b00259e2fb9bf5eed7049ec5d/solr/core/src/java/org/apache/solr/security/RuleBasedAuthorizationPluginBase.java#L104-L108)).

## What this change does

**The Security API rejects `"collection": null` on read, update, schema-read and schema-edit, in both set-permission and update-permission.**

The check is `Permission.validateOnEdit` ([Permission.java L119-L129](https://github.com/nick-boss-tech/solr/blob/5a15dc0ba22083a294524210b3be007d870daa35/solr/core/src/java/org/apache/solr/security/Permission.java#L119-L129)). The set-permission step calls it after it loads the entry ([AutorizationEditOperation.java L73-L79](https://github.com/nick-boss-tech/solr/blob/5a15dc0ba22083a294524210b3be007d870daa35/solr/core/src/java/org/apache/solr/security/AutorizationEditOperation.java#L73-L79)). The update-permission step merges the stored entry with the new fields and then runs the same set-permission step ([L133-L136](https://github.com/nick-boss-tech/solr/blob/5a15dc0ba22083a294524210b3be007d870daa35/solr/core/src/java/org/apache/solr/security/AutorizationEditOperation.java#L133-L136)), so it gets the same check. The rejection is a command error that names the permission.

Names outside those four are not affected. Names whose default collection list already includes null still accept it: config-edit, config-read, metrics-read, health, all, and the names that use only null, such as collection-admin-edit and security-edit ([PermissionNameProvider.java L41-L61](https://github.com/nick-boss-tech/solr/blob/5a15dc0ba22083a294524210b3be007d870daa35/solr/core/src/java/org/apache/solr/security/PermissionNameProvider.java#L41-L61)). Custom path permissions still accept it ([Permission.java L121-L124](https://github.com/nick-boss-tech/solr/blob/5a15dc0ba22083a294524210b3be007d870daa35/solr/core/src/java/org/apache/solr/security/Permission.java#L121-L124)).

Stored security.json files keep loading. The check is not part of `Permission.load`, which the startup path uses ([Permission.java L48-L113](https://github.com/nick-boss-tech/solr/blob/5a15dc0ba22083a294524210b3be007d870daa35/solr/core/src/java/org/apache/solr/security/Permission.java#L48-L113), [RuleBasedAuthorizationPluginBase.java L346-L359](https://github.com/nick-boss-tech/solr/blob/5a15dc0ba22083a294524210b3be007d870daa35/solr/core/src/java/org/apache/solr/security/RuleBasedAuthorizationPluginBase.java#L346-L359)).

The check runs in standalone mode and in ZooKeeper mode. Both save through the same edit handler, which runs the plugin's edit before it writes ([SecurityConfHandler.java L134-L151](https://github.com/nick-boss-tech/solr/blob/5a15dc0ba22083a294524210b3be007d870daa35/solr/core/src/java/org/apache/solr/handler/admin/SecurityConfHandler.java#L134-L151)).

One effect reaches existing entries. An update-permission on an entry that already has a null collection is checked after the merge. An update that changes only the role is rejected until the same update also sets a collection.

## A choice to check

**The ticket asks for an error in one place and for the null to be ignored in another. This change returns an error.**

The ticket's description says the Security API should throw an error. Its first bullet says a null collection on a per-collection permission "should be ignored". Ignoring it would give the entry its default collection list, `*`, so the permission would apply to every collection ([PermissionNameProvider.java L46-L47](https://github.com/nick-boss-tech/solr/blob/5a15dc0ba22083a294524210b3be007d870daa35/solr/core/src/java/org/apache/solr/security/PermissionNameProvider.java#L46-L47)). This change returns an error instead.

Was that the right call, or should the server accept the null and use the default?

## Limits

- **The ticket's second bullet is not implemented.** A non-null collection on a permission that takes none, such as collection-admin-edit or security-edit, is still accepted. A follow-up ticket and PR for that rule can be opened on request.
- **Existing files keep their null entries.** A security.json that already has `"collection": null` on read, update, schema-read or schema-edit still loads. Those entries still do not apply to requests routed to a collection. The change adds no warning on load. A load-time warning is a possible follow-up, and can be opened on request.
- **Other null forms are not rejected.** A list that contains null, such as `"collection": [null]`, is not the JSON null value. It is read as a collection named "null" ([Permission.java L171-L172](https://github.com/nick-boss-tech/solr/blob/5a15dc0ba22083a294524210b3be007d870daa35/solr/core/src/java/org/apache/solr/security/Permission.java#L171-L172)) and accepted.
- **The new test covers set-permission only.** update-permission reaches the same check through the shared step, but no test runs that path.
- **Admin requests are not fully traced.** Only admin requests consult null entries, so the rejection removes one way to set these four names for admin requests. I did not trace every route into the admin path, so I have not confirmed that no current request depends on it.
