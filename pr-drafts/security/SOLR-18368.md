## What happens today

**The example on the Basic Authentication Plugin page cannot compile against main.**

Three lines of the page use a name or syntax that main does not have. These links point to the base commit, where the page is the same as on main:

- The sentence above the example names `Http2SolrClient.Builder` ([line 371](https://github.com/apache/solr/blob/14c7aac0d151402b00259e2fb9bf5eed7049ec5d/solr/solr-ref-guide/modules/deployment-guide/pages/basic-authentication-plugin.adoc#L371), base). Main has no class by that name. The client is named `HttpJettySolrClient`, and [a source comment](https://github.com/nick-boss-tech/solr/blob/a7ec9a1b65c05b2e359e9a186fc2938fe7b7ca7d/solr/solrj-jetty/src/java/org/apache/solr/client/solrj/jetty/HttpJettySolrClient.java#L96) records the old name.
- [Line 375](https://github.com/apache/solr/blob/14c7aac0d151402b00259e2fb9bf5eed7049ec5d/solr/solr-ref-guide/modules/deployment-guide/pages/basic-authentication-plugin.adoc#L375), base, calls `HttpJettySolrClient.Builder()` without `new`. `Builder` is a [nested class with a public constructor](https://github.com/nick-boss-tech/solr/blob/a7ec9a1b65c05b2e359e9a186fc2938fe7b7ca7d/solr/solrj-jetty/src/java/org/apache/solr/client/solrj/jetty/HttpJettySolrClient.java#L956), and no method of that name exists.
- [Line 377](https://github.com/apache/solr/blob/14c7aac0d151402b00259e2fb9bf5eed7049ec5d/solr/solr-ref-guide/modules/deployment-guide/pages/basic-authentication-plugin.adoc#L377), base, calls `withInternalClientBuilder`. [#4782](https://github.com/apache/solr/pull/4782) removed that method from `CloudSolrClient.Builder` ([commit 3ef3d093c06](https://github.com/apache/solr/commit/3ef3d093c068b46431b6c7190d4706f5f599eaf7)), and that commit is already in the base. Apart from changelog entries, the page is the only place that still uses the name.

## What this change does

**The branch corrects those three lines and changes nothing else in the page or the code.**

- The sentence now names an HTTP SolrClient builder, the type that `withHttpClientBuilder` accepts ([CloudSolrClient.java, line 1550](https://github.com/nick-boss-tech/solr/blob/a7ec9a1b65c05b2e359e9a186fc2938fe7b7ca7d/solr/solrj/src/java/org/apache/solr/client/solrj/impl/CloudSolrClient.java#L1550)). That type is [`HttpSolrClient.BuilderBase`](https://github.com/nick-boss-tech/solr/blob/a7ec9a1b65c05b2e359e9a186fc2938fe7b7ca7d/solr/solrj/src/java/org/apache/solr/client/solrj/impl/HttpSolrClient.java#L438).
- The `httpClientBuilder` line adds `new`, as the [public constructor](https://github.com/nick-boss-tech/solr/blob/a7ec9a1b65c05b2e359e9a186fc2938fe7b7ca7d/solr/solrj-jetty/src/java/org/apache/solr/client/solrj/jetty/HttpJettySolrClient.java#L956) requires. The chained [`withBasicAuthCredentials`](https://github.com/nick-boss-tech/solr/blob/a7ec9a1b65c05b2e359e9a186fc2938fe7b7ca7d/solr/solrj/src/java/org/apache/solr/client/solrj/impl/HttpSolrClient.java#L526) returns that builder, which `withHttpClientBuilder` accepts.
- The last line calls `withHttpClientBuilder`.

The example's constructor call, [`new CloudSolrClient.Builder(zkHostList, chroot)`](https://github.com/nick-boss-tech/solr/blob/a7ec9a1b65c05b2e359e9a186fc2938fe7b7ca7d/solr/solrj/src/java/org/apache/solr/client/solrj/impl/CloudSolrClient.java#L1398), already matches main. The client source under `solrj` and `solrj-jetty` is the same on the base commit, on this head, and on current main.
