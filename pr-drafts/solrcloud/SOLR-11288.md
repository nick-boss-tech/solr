## What happens today

**Three collection APIs fail when a comma-separated list repeats a name or has a space before a name.**

CLUSTERSTATUS `shard`, BALANCE_REPLICAS `nodes`, and MIGRATE_REPLICAS `sourceNodes` and `targetNodes` split the list with `Set.of`. `Set.of` throws `IllegalArgumentException` on a repeated name, so `shard=shard1,shard1` fails with a server error ([ClusterStatus.java](https://github.com/nick-boss-tech/solr/blob/cd094c3c623fadfb08afef173312d394e4407ffb/solr/core/src/java/org/apache/solr/handler/admin/ClusterStatus.java#L173-L180)). A name with a leading space, as in `shard1, shard1`, matches no shard. CLUSTERSTATUS then answers that the shard is not found ([ClusterStatus.java](https://github.com/nick-boss-tech/solr/blob/cd094c3c623fadfb08afef173312d394e4407ffb/solr/core/src/java/org/apache/solr/handler/admin/ClusterStatus.java#L260-L269)).

## What this change does

**Each name is trimmed, blanks are dropped, and a repeat is kept once. Blank-only input now behaves like an omitted value.**

Each list is split on commas, trimmed, filtered for blanks, and collected into a set ([BalanceReplicasCmd.java](https://github.com/nick-boss-tech/solr/blob/cd094c3c623fadfb08afef173312d394e4407ffb/solr/core/src/java/org/apache/solr/cloud/api/collections/BalanceReplicasCmd.java#L52-L58), [MigrateReplicasCmd.java](https://github.com/nick-boss-tech/solr/blob/cd094c3c623fadfb08afef173312d394e4407ffb/solr/core/src/java/org/apache/solr/cloud/api/collections/MigrateReplicasCmd.java#L142-L147)). Three inputs that used to fail now change meaning:

- CLUSTERSTATUS with a blank `shard` returns all shards. It used to fail with "not found."
- BALANCE_REPLICAS with a blank `nodes` balances across all live data nodes. It used to fail with "Cannot balance across a single node" ([BalanceReplicasCmd.java](https://github.com/nick-boss-tech/solr/blob/cd094c3c623fadfb08afef173312d394e4407ffb/solr/core/src/java/org/apache/solr/cloud/api/collections/BalanceReplicasCmd.java#L70-L72)). A list that repeats one node now fails with that same message, where it used to fail with a server error.
- MIGRATE_REPLICAS with a blank `targetNodes` uses all other live nodes. A blank `sourceNodes` now fails with "sourceNodes is a required param."

## Proof

**The new test method fails on the base code and passes with this change.**

`TestCollectionAPI` 4 of 4 at head `cd094c3c623`, recorded 2026-10-06. The new method, `clusterStatusWithRepeatedShard`, checks an exact repeat and a repeat with a space ([TestCollectionAPI.java](https://github.com/nick-boss-tech/solr/blob/cd094c3c623fadfb08afef173312d394e4407ffb/solr/core/src/test/org/apache/solr/cloud/api/collections/TestCollectionAPI.java#L318-L324)). On the base code the exact repeat throws `IllegalArgumentException`, and the padded repeat returns "not found." With this change both cases pass.

## A choice to check

**A blank node list now starts a rebalance across every live node, where it used to fail.**

The other route keeps the failure for a list with no names. This change follows the existing rule that an omitted `nodes` value means all live data nodes. The cost is that a blank value can now move replicas. Was it right to let a blank `nodes` value mean all live nodes?

## Limits

- Commas inside a name still cannot be expressed. The ticket asks for backslash escaping, and `StrUtils.splitSmart` already exists. This change does not add escaping. A follow-up ticket and pull request can take that on if you want it.
- The test covers CLUSTERSTATUS only. BALANCE_REPLICAS and MIGRATE_REPLICAS have no direct test for these inputs. A small follow-up can add them.
