## What happens today

**A node that wins the Overseer election but does not start the Overseer keeps its leader registration.**

The winning node writes an ephemeral leader node, then starts the Overseer only when the election context is still open and the CoreContainer is not shutting down ([write and start check](https://github.com/nick-boss-tech/solr/blob/b436d90d2a889cc8511a493a524048ca1543edb5/solr/core/src/java/org/apache/solr/cloud/OverseerElectionContext.java#L66-L73)). When the start is skipped, nothing removes the leader node. It stays until the ZooKeeper session ends. The ticket reports that the cluster can be left without an Overseer until that node is removed.

## What this change does

**When the Overseer does not start, the node deletes the leader node it wrote, if that node still belongs to it.**

The node reads the leader node and its version. It deletes the node only when the stored node id matches its own, and it deletes by that version, so a replacement registration is left alone. A missing node, a version conflict, or a closed client is ignored ([removal](https://github.com/nick-boss-tech/solr/blob/b436d90d2a889cc8511a493a524048ca1543edb5/solr/core/src/java/org/apache/solr/cloud/OverseerElectionContext.java#L77-L93)). The path that starts the Overseer is unchanged ([early return](https://github.com/nick-boss-tech/solr/blob/b436d90d2a889cc8511a493a524048ca1543edb5/solr/core/src/java/org/apache/solr/cloud/OverseerElectionContext.java#L70-L71)).

## Proof

**One new test fails on the base code and passes with this change.**

- `OverseerElectionContextTest` 1 of 1 at head b436d90d2a8, verified on 2026-10-06 ([test](https://github.com/nick-boss-tech/solr/blob/b436d90d2a889cc8511a493a524048ca1543edb5/solr/core/src/test/org/apache/solr/cloud/OverseerElectionContextTest.java#L62-L77)). `testLeaderNodeRemovedWhenOverseerIsNotStarted` fails on the base code with one failure at the assertion "leader registration must not outlive a skipped Overseer start". It passes with this change.

## Limits

**The test covers one path and runs on mocks, and the election sequence node is not touched.**

- The test covers only the skipped-start path. The ticket describes a race, and this is one shape of it. A follow-up ticket and PR can cover the other paths on request.
- The test uses a mocked CoreContainer and Overseer on a real ZooKeeper test server. There is no multi-node run.
- The election sequence node is not removed by this change. It goes when the election context is cancelled or the session ends, as before.
