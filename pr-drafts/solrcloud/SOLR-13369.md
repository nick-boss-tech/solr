## What happens today

**The TriLevelCompositeIdRoutingTest check assumes one route prefix never spans two shards, and the test was disabled for this ticket.**

The test checks that each route prefix, such as `app9/2!user32`, appears in one shard only. A composite route prefix fixes only the leading bits of the hash. The hash range it covers can cross a shard boundary, so documents with one prefix can sit in two shards. The ticket records a seed where that happens, and the check fails.

## What this change does

**The test accepts a prefix in several shards when the router searches all of those shards for that prefix.**

For each prefix, the test records every shard that holds it. It then checks that the router's search slices for that prefix include each of those shards ([TriLevelCompositeIdRoutingTest.java](https://github.com/nick-boss-tech/solr/blob/dfa0db5bdf96d119d985a8b895ff90c4d783ad47/solr/core/src/test/org/apache/solr/cloud/TriLevelCompositeIdRoutingTest.java#L143-L157)). The missing and duplicate document checks stay. The `@AwaitsFix` marker is removed, so the test runs again. The change touches the test and its changelog only.

## Proof

**No run has shown the old failure. The check is proven by construction only.**

`TriLevelCompositeIdRoutingTest` 1 of 1 at head `dfa0db5bdf96`, recorded 2026-10-07. On the base code the check passes for every seed tried, because none of them put one prefix in two shards. Six more seeds were tried and also produced none. The claim rests on the ticket's recorded failure and on the router's search code. No run has shown this test failing without the change.

## A choice to check

**The test's rule changed, and the router did not.**

The ticket's author suspected that the bit-mask prefix handling from SOLR-13210 might be the bug. This change keeps the router and changes the test to match the router's search. The other route is to change the router so that a prefix stays in one shard. Was it right to change the test rather than the router?

## Limits

- The change does not alter routing. The test checks the router against the router's own search, so it cannot catch a routing bug that both sides share.
