## What happens today

**A shutdown DOWNNODE message can mark a restarted node's replicas DOWN.**

On shutdown, a node sends a DOWNNODE message to the Overseer. If the node restarts before the Overseer processes that message, the message still marks the restarted node's replicas DOWN. Those replicas become ACTIVE again only after a shard leader election, and the ticket describes a restart where no election ran.

## What this change does

**The shutdown message now carries a flag. The Overseer skips a flagged message when the node is live at the time the message is applied.**

- The shutdown path sends the flag ([shutdown call](https://github.com/nick-boss-tech/solr/blob/ca8cb61ee957ed728034a2e6c90532e6082ef3ff/solr/core/src/java/org/apache/solr/cloud/ZkController.java#L845-L848)), and the queued message carries it ([queued message](https://github.com/nick-boss-tech/solr/blob/ca8cb61ee957ed728034a2e6c90532e6082ef3ff/solr/core/src/java/org/apache/solr/cloud/ZkController.java#L3082-L3086)).
- The guard runs in `NodeMutator.downNode`. It returns no changes when the message is flagged and the node is in the live nodes ([guard](https://github.com/nick-boss-tech/solr/blob/ca8cb61ee957ed728034a2e6c90532e6082ef3ff/solr/core/src/java/org/apache/solr/cloud/overseer/NodeMutator.java#L58-L61)).
- The one-argument `publishNodeAsDown` still sends an unflagged message, so its callers see no change ([public method](https://github.com/nick-boss-tech/solr/blob/ca8cb61ee957ed728034a2e6c90532e6082ef3ff/solr/core/src/java/org/apache/solr/cloud/ZkController.java#L3029-L3031)).

Behavior change, stated openly: a shutdown DOWNNODE that reaches the Overseer after the node is live again is skipped. Nothing else in the message handling changes.

## Proof

**Unit tests cover the new guard. The delayed-message sequence is not covered end to end. The proof is inconclusive by construction.**

- `NodeMutatorTest` 3 of 3 at head ca8cb61ee95, verified on 2026-10-07 ([test](https://github.com/nick-boss-tech/solr/blob/ca8cb61ee957ed728034a2e6c90532e6082ef3ff/solr/core/src/test/org/apache/solr/cloud/overseer/NodeMutatorTest.java#L77-L82)). `testConditionalDownNodeSkippedWhenNodeIsLiveAgain` checks that a flagged message is skipped when the node is live. The two other tests check the unchanged paths.
- The test refers to the new flag constant, which does not exist on the base code. So the base code cannot run this test, and no base failure is shown.

## A choice to check

**The guard reads the Overseer's cached live node list once, when the message is applied.**

Options considered. The implemented option is one check against the cached cluster state. It is small and uses state the Overseer already holds, but it depends on that cache being current when the message runs. The first alternative, suggested in the ticket comments, is to check again after the update is computed. The second is a conditional ZooKeeper update tied to the live nodes. It needs more change, because live node entries carry no data. Is one check against the cached live node list enough, or should the Overseer also check after it computes the update?

## Limits

**The guard has no end-to-end test, does not run on the distributed path, and is ignored by an older Overseer.**

- There is no end-to-end test with a delayed queue or with live node watch lag. The guard depends on the cached cluster state being current.
- The distributed cluster state path, used when the Overseer is disabled, does not send this message. It marks the node down during shutdown without the queue ([distributed path](https://github.com/nick-boss-tech/solr/blob/ca8cb61ee957ed728034a2e6c90532e6082ef3ff/solr/core/src/java/org/apache/solr/cloud/ZkController.java#L3053-L3060)), so the guard does not run there.
- In a mixed-version cluster, an older Overseer ignores the flag and applies the message as before.
