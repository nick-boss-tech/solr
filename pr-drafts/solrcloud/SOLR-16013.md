## What happens today

**Stopping a node can end its ZooKeeper session before its Overseer has finished closing.**

The links in this section point at the merge-base commit, `14c7aac0d151402b00259e2fb9bf5eed7049ec5d`, which is the code before this change. In [ZkController.close(), lines 883 to 918](https://github.com/nick-boss-tech/solr/blob/14c7aac0d151402b00259e2fb9bf5eed7049ec5d/solr/core/src/java/org/apache/solr/cloud/ZkController.java#L883-L918), the Overseer close is queued on a background thread at line 883 and is not waited on. The state reader and the ZooKeeper client then close at lines 904 and 910. The queued close is awaited only when the thread pool shuts down, at line 918, which is after the client has closed. If the session ends first, the election nodes can be released while the Overseer is still closing.

## What this change does

**The Overseer finishes closing before the session ends, and an interrupt does not cut that wait short.**

[ZkController.close()](https://github.com/nick-boss-tech/solr/blob/408317d7e241c62a3eba9b1115dbac62292b49a7/solr/core/src/java/org/apache/solr/cloud/ZkController.java#L883-L944) now submits the Overseer close as one task and waits on that task before it closes the state reader and the ZooKeeper client. The election nodes are released after that wait. Stopping a node can take longer, because `close()` returns only when the Overseer close is done.

If the closing thread is interrupted, the wait continues and the interrupt is remembered. The interrupt flag is restored only at the end of the close sequence, after the state reader, the ZooKeeper client and the close thread pool have closed. The session-ending closes never run on an interrupted thread, and the caller still gets its interrupt status back when `close()` returns.
