## What happens today

**Today an unknown collection, shard or replica still gets HTTP 200.**

The command hands the property change to the state updater and reports success. The updater then looks up the collection and the replica. When it cannot find them, it logs an error and skips the change. The caller never sees that failure. The lookup is in [ReplicaMutator.java L162-L175](https://github.com/nick-boss-tech/solr/blob/e2cdb2d7e8ae0be4cf6cf0606206c67d89e7278f/solr/core/src/java/org/apache/solr/cloud/overseer/ReplicaMutator.java#L162-L175) (base, e2cdb2d7e8ae). The skip is logged in [Overseer.java L436-L439](https://github.com/nick-boss-tech/solr/blob/e2cdb2d7e8ae0be4cf6cf0606206c67d89e7278f/solr/core/src/java/org/apache/solr/cloud/Overseer.java#L436-L439) (base). With distributed state updates, the same failure is logged and skipped in [DistributedClusterStateUpdater.java L819-L830](https://github.com/nick-boss-tech/solr/blob/e2cdb2d7e8ae0be4cf6cf0606206c67d89e7278f/solr/core/src/java/org/apache/solr/cloud/DistributedClusterStateUpdater.java#L819-L830) (base).

## What this change does

**ADDREPLICAPROP now returns HTTP 400 and changes nothing when the collection, the shard or the replica in that shard is not found.**

Before the update is queued, the command looks up the collection, then the shard by name, then the replica by name inside that shard ([CollApiCmds.java L345-L351](https://github.com/nick-boss-tech/solr/blob/aa2a6b8afb6f1720c0a04b7869f331ab47bf554d/solr/core/src/java/org/apache/solr/cloud/api/collections/CollApiCmds.java#L345-L351)). If one of them is missing, it throws an HTTP 400 error. The message names all three ([L352-L362](https://github.com/nick-boss-tech/solr/blob/aa2a6b8afb6f1720c0a04b7869f331ab47bf554d/solr/core/src/java/org/apache/solr/cloud/api/collections/CollApiCmds.java#L352-L362)). Nothing is queued.

This is a behavior change. A valid replica name given with the wrong shard is now rejected with HTTP 400. Before this change, that request returned 200 and set the property on no replica. For preferredleader, the old update could also clear the property on the replicas of the named shard. The old code finds a replica by name in any shard ([DocCollection.java L382-L391](https://github.com/nick-boss-tech/solr/blob/e2cdb2d7e8ae0be4cf6cf0606206c67d89e7278f/solr/solrj/src/java/org/apache/solr/common/cloud/DocCollection.java#L382-L391), base). It then updates only the named shard ([ReplicaMutator.java L184-L195](https://github.com/nick-boss-tech/solr/blob/e2cdb2d7e8ae0be4cf6cf0606206c67d89e7278f/solr/core/src/java/org/apache/solr/cloud/overseer/ReplicaMutator.java#L184-L195), base).

## Proof

**testAddReplicaPropRejectsUnknownReplica fails on the base code and passes with the change.**

The test is in [CollectionsAPISolrJTest.java L1292-L1322](https://github.com/nick-boss-tech/solr/blob/aa2a6b8afb6f1720c0a04b7869f331ab47bf554d/solr/core/src/test/org/apache/solr/cloud/CollectionsAPISolrJTest.java#L1292-L1322). With CollApiCmds.java reverted to the base, the class has one failure: testAddReplicaPropRejectsUnknownReplica. The base returns success for an unknown replica, so the first assertion fails. With the change, the class passes at head aa2a6b8afb6f, verified 2026-10-10.

The unknown replica case asserts HTTP 400. The unknown shard and unknown collection cases assert only that an exception is thrown.

## A choice to check

**A maintainer could reasonably prefer the other route for a replica name given with the wrong shard.**

The other route keeps the lookup across all shards and applies the property in the shard where the replica lives. That is kinder to callers. It also changes the update path in [ReplicaMutator.java L184-L195](https://github.com/nick-boss-tech/solr/blob/e2cdb2d7e8ae0be4cf6cf0606206c67d89e7278f/solr/core/src/java/org/apache/solr/cloud/overseer/ReplicaMutator.java#L184-L195) (base), which this change leaves alone. Was rejecting it the right call?

## Limits

**Only ADDREPLICAPROP is covered. DELETEREPLICAPROP and the other APIs the ticket mentions are not changed.**

- DELETEREPLICAPROP checks only its required fields ([CollApiCmds.java L385-L390](https://github.com/nick-boss-tech/solr/blob/aa2a6b8afb6f1720c0a04b7869f331ab47bf554d/solr/core/src/java/org/apache/solr/cloud/api/collections/CollApiCmds.java#L385-L390)). This change does not touch it. I can open a follow-up ticket and PR for DELETEREPLICAPROP and the other APIs on request.
- Collections that use per-replica states were not checked.
