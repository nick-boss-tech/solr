## What happens today

**When every retry of a per-replica state write fails, persist returns without writing and without an error.**

[PerReplicaStatesOps.persist](https://github.com/nick-boss-tech/solr/blob/14c7aac0d151402b00259e2fb9bf5eed7049ec5d/solr/solrj-zookeeper/src/java/org/apache/solr/common/cloud/PerReplicaStatesOps.java#L131-L147) retries while the state is stale. This link goes to the merge-base, the code before this change. When the last attempt also fails, the loop ends and the method returns.

## What this change does

**persist throws the last KeeperException, so each caller sees the failure.**

The last attempt no longer re-reads the state before it gives up ([L132-L158](https://github.com/nick-boss-tech/solr/blob/f614a42fbc8046e47cb7ed216f6b52b8a01f594c/solr/solrj-zookeeper/src/java/org/apache/solr/common/cloud/PerReplicaStatesOps.java#L132-L158)). Callers that relied on the silent return now get the exception. These are the call sites:

- Overseer state flush ([ZkStateWriter.java L274](https://github.com/nick-boss-tech/solr/blob/f614a42fbc8046e47cb7ed216f6b52b8a01f594c/solr/core/src/java/org/apache/solr/cloud/overseer/ZkStateWriter.java#L274)): the exception stops the flush. The Overseer loop logs it and continues ([Overseer.java L387-L390](https://github.com/nick-boss-tech/solr/blob/f614a42fbc8046e47cb7ed216f6b52b8a01f594c/solr/core/src/java/org/apache/solr/cloud/Overseer.java#L387-L390)).
- Distributed state update ([DistributedClusterStateUpdater.java L467](https://github.com/nick-boss-tech/solr/blob/f614a42fbc8046e47cb7ed216f6b52b8a01f594c/solr/core/src/java/org/apache/solr/cloud/DistributedClusterStateUpdater.java#L467)): the update stops before state.json is written.
- Leader election ([ShardLeaderElectionContextBase.java L241](https://github.com/nick-boss-tech/solr/blob/f614a42fbc8046e47cb7ed216f6b52b8a01f594c/solr/core/src/java/org/apache/solr/cloud/ShardLeaderElectionContextBase.java#L241)) and replica publish or unregister ([ZkController.java L1968](https://github.com/nick-boss-tech/solr/blob/f614a42fbc8046e47cb7ed216f6b52b8a01f594c/solr/core/src/java/org/apache/solr/cloud/ZkController.java#L1968), [L2064](https://github.com/nick-boss-tech/solr/blob/f614a42fbc8046e47cb7ed216f6b52b8a01f594c/solr/core/src/java/org/apache/solr/cloud/ZkController.java#L2064)): the exception goes up to the caller.
- Node-down publish, when distributed state updates are off ([ZkController.java L3058-L3068](https://github.com/nick-boss-tech/solr/blob/f614a42fbc8046e47cb7ed216f6b52b8a01f594c/solr/core/src/java/org/apache/solr/cloud/ZkController.java#L3058-L3068)): a KeeperException from one collection's persist is logged as a warning, and the loop moves on. The node-down message is then sent ([L3074-L3079](https://github.com/nick-boss-tech/solr/blob/f614a42fbc8046e47cb7ed216f6b52b8a01f594c/solr/core/src/java/org/apache/solr/cloud/ZkController.java#L3074-L3079)). Before this change, a KeeperException such as a lost ZooKeeper connection skipped that message, because the call had no catch of its own ([ZkController.java L3058-L3064 at the merge-base](https://github.com/nick-boss-tech/solr/blob/14c7aac0d151402b00259e2fb9bf5eed7049ec5d/solr/core/src/java/org/apache/solr/cloud/ZkController.java#L3058-L3064)).

## Proof

**TestPerReplicaStates passes 4 of 4 at head f614a42fbc80, verified 2026-10-13.**

With PerReplicaStatesOps.java and ZkController.java reverted to the merge-base, the class runs 4 tests with exactly 1 failure. The new test, [testPersistRetriesOnStaleState](https://github.com/nick-boss-tech/solr/blob/f614a42fbc8046e47cb7ed216f6b52b8a01f594c/solr/solrj-zookeeper/src/test/org/apache/solr/common/cloud/TestPerReplicaStates.java#L143-L176), checks two cases. A write that is stale on the first attempt succeeds on retry. A write that is stale on every attempt throws NodeExistsException. On the base code, the second case fails, because persist returns without throwing.

## Limits

**The test covers persist alone. The callers, the node-down change, and sustained contention are not tested.**

- The number of attempts is unchanged. Only what happens after the last failed attempt changes.
- The Overseer loop logs a failed flush ([Overseer.java L387-L390 at the merge-base](https://github.com/nick-boss-tech/solr/blob/14c7aac0d151402b00259e2fb9bf5eed7049ec5d/solr/core/src/java/org/apache/solr/cloud/Overseer.java#L387-L390)). A single per-replica update is still removed from the queue without a retry, because the queue callback runs in a `finally` ([ZkStateWriter.java L158-L162 at the merge-base](https://github.com/nick-boss-tech/solr/blob/14c7aac0d151402b00259e2fb9bf5eed7049ec5d/solr/core/src/java/org/apache/solr/cloud/overseer/ZkStateWriter.java#L158-L162)). Before this change, that removal happened without an error. A follow-up ticket and PR for retries are available on request. Sustained contention is not tested.
- persist logs an ERROR when it gives up. The Overseer loop logs the same exception at ERROR again, so one failure appears twice at that level. The node-down call site logs it as a warning.
