## What happens today

**A dimensional routed alias written the reference-guide way cannot be created.**

[CreateAliasCmd.java](https://github.com/nick-boss-tech/solr/blob/56ec140e3636d5f4150fa87fbf7103529536ac99/solr/core/src/java/org/apache/solr/cloud/api/collections/CreateAliasCmd.java#L120-L125) requires a top-level `router.name` and `router.field` before it reads the dimensions. The link goes to the merge-base, the code before this change. A dimensional alias has one field per dimension and no top-level `router.field`, so the ticket's request fails with "A routed alias requires these params: [router.field, router.name] plus some create-collection prefixed ones." The v2 endpoint with two routers fails too, because it never sends a top-level `router.name` ([CreateAlias.java L121-L133](https://github.com/nick-boss-tech/solr/blob/56ec140e3636d5f4150fa87fbf7103529536ac99/solr/core/src/java/org/apache/solr/handler/admin/api/CreateAlias.java#L121-L133)).

## What this change does

**Multi-dimensional aliases send a top-level router name, and the field check moves out of the command.**

- The v1 and v2 create paths send `router.name` as `Dimensional[<names>]` for a multi-dimensional alias ([CreateAlias.java L125-L137](https://github.com/nick-boss-tech/solr/blob/ce59bbe112d063e3d3c93b3be6a1a5269a38fc37/solr/core/src/java/org/apache/solr/handler/admin/api/CreateAlias.java#L125-L137)).
- The command checks `router.name` up front ([CreateAliasCmd.java L119-L126](https://github.com/nick-boss-tech/solr/blob/ce59bbe112d063e3d3c93b3be6a1a5269a38fc37/solr/core/src/java/org/apache/solr/cloud/api/collections/CreateAliasCmd.java#L119-L126)). `RoutedAlias.fromProps` fills in `router.field` for a dimensional alias ([RoutedAlias.java L148-L150](https://github.com/nick-boss-tech/solr/blob/ce59bbe112d063e3d3c93b3be6a1a5269a38fc37/solr/core/src/java/org/apache/solr/cloud/api/collections/RoutedAlias.java#L148-L150)). A time alias checks for `router.field` in its constructor ([TimeRoutedAlias.java L142-L147](https://github.com/nick-boss-tech/solr/blob/ce59bbe112d063e3d3c93b3be6a1a5269a38fc37/solr/core/src/java/org/apache/solr/cloud/api/collections/TimeRoutedAlias.java#L142-L147)).
- The v2 endpoint with two routers now sends the same `router.name`, so the same fix should let it create the alias too.

Error text changes for invalid requests. The client sees that text, because the command's exception is rethrown to the caller ([AdminAPIBase.java L129-L131](https://github.com/nick-boss-tech/solr/blob/ce59bbe112d063e3d3c93b3be6a1a5269a38fc37/solr/core/src/java/org/apache/solr/handler/admin/api/AdminAPIBase.java#L129-L131)).

- A time routed alias without `router.field` fails with "A time routed alias requires these params:" and lists its five required parameters. Before, it got the generic "A routed alias requires these params" message.
- A category routed alias without `router.field` fails with "Not all required params were supplied. Missing params:" and lists every missing required parameter, including `router.field` ([CreateAliasCmd.java L140-L146](https://github.com/nick-boss-tech/solr/blob/ce59bbe112d063e3d3c93b3be6a1a5269a38fc37/solr/core/src/java/org/apache/solr/cloud/api/collections/CreateAliasCmd.java#L140-L146)).

## A choice to check

**The up-front check for `router.field` moved out of the command.**

The other route keeps both up-front checks in the command and fills in `router.field` for dimensional aliases there. Its cost: the time and category messages stay generic. This change moves the check out of the command, so the error text changes for those requests. Was moving the check the right call?
