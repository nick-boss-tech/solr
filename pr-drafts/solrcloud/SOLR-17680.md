## What happens today

**A dimensional routed alias written the reference-guide way cannot be created.**

The create command requires top-level `router.name` and `router.field` before it reads the dimensions ([CreateAliasCmd.java](https://github.com/nick-boss-tech/solr/blob/56ec140e3636d5f4150fa87fbf7103529536ac99/solr/core/src/java/org/apache/solr/cloud/api/collections/CreateAliasCmd.java#L120-L125), code before this change). A dimensional alias written the reference-guide way has a field for each dimension and no top-level `router.field`. The ticket reports the request is rejected with "A routed alias requires these params: [router.field, router.name] plus some create-collection prefixed ones." The v2 aliases endpoint with two routers fails the same way, because it never sends a top-level `router.name`.

## What this change does

**Multi-dimensional aliases now send a top-level router name, and the field check moves to the routed alias parser.**

For a multi-dimensional alias, the v1 and v2 create paths now send `router.name` as `Dimensional[<names>]`, built from the per-dimension names ([CreateAlias.java](https://github.com/nick-boss-tech/solr/blob/f4b8ce83365442d775a1a746ef8e345eb2da2c03/solr/core/src/java/org/apache/solr/handler/admin/api/CreateAlias.java#L125-L137)). The command checks `router.name` up front ([CreateAliasCmd.java](https://github.com/nick-boss-tech/solr/blob/f4b8ce83365442d775a1a746ef8e345eb2da2c03/solr/core/src/java/org/apache/solr/cloud/api/collections/CreateAliasCmd.java#L119-L126)). `RoutedAlias.fromProps` fills in `router.field` for a dimensional alias from the per-dimension fields ([RoutedAlias.java](https://github.com/nick-boss-tech/solr/blob/f4b8ce83365442d775a1a746ef8e345eb2da2c03/solr/core/src/java/org/apache/solr/cloud/api/collections/RoutedAlias.java#L148-L150)). For a time alias, the alias type checks that `router.field` is present ([TimeRoutedAlias.java](https://github.com/nick-boss-tech/solr/blob/f4b8ce83365442d775a1a746ef8e345eb2da2c03/solr/core/src/java/org/apache/solr/cloud/api/collections/TimeRoutedAlias.java#L142-L147)).

Error text changes for an invalid request:

- A time routed alias without `router.field` now fails with a message that starts "A time routed alias requires these params:" and lists its five required parameters. Before, the command gave "A routed alias requires these params: followed by the two parameter names plus some create-collection prefixed ones."
- A category routed alias without `router.field` now fails with "Not all required params were supplied. Missing params: router.field". Before, it failed with the same "A routed alias requires these params" message as a time alias.

The v2 aliases endpoint with two routers starts working too, because the fix sits in the shared create path.

## A choice to check

**The up-front check for `router.field` moved out of the command.**

The other route keeps the up-front check for both fields and fills in `router.field` for dimensional aliases in the create path. That keeps the old error text. This change moves the check, so the error text changes for those requests. Was moving the check the right call?

## Limits

**No cloud test covers the v2 endpoint, and clients that match the old error text need an update.**

- No cloud test goes through the v2 endpoint. Its behavior is covered by the API unit test, which checks the message sent to the command.
- Clients that match the old error text need an update.
