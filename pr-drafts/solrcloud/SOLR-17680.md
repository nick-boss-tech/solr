## What happens today

**A dimensional routed alias written the reference-guide way cannot be created.**

The create command requires top-level `router.name` and `router.field` before it reads the dimensions ([CreateAliasCmd.java](https://github.com/nick-boss-tech/solr/blob/f4b8ce83365442d775a1a746ef8e345eb2da2c03/solr/core/src/java/org/apache/solr/cloud/api/collections/CreateAliasCmd.java#L119-L124)). A dimensional alias written the reference-guide way has a field for each dimension and no top-level `router.field`. The request fails with "A routed alias requires these params: [router.field, router.name]." The v2 aliases endpoint with two routers fails the same way, because it never sends a top-level `router.name`.

## What this change does

**Multi-dimensional aliases now send a top-level router name, and the field check moves to the routed alias parser.**

For a multi-dimensional alias, the v1 and v2 create paths now send `router.name` as `Dimensional[<names>]`, built from the per-dimension names ([CreateAlias.java](https://github.com/nick-boss-tech/solr/blob/f4b8ce83365442d775a1a746ef8e345eb2da2c03/solr/core/src/java/org/apache/solr/handler/admin/api/CreateAlias.java#L125-L137)). The command checks `router.name` up front. `RoutedAlias.fromProps` checks `router.field` and fills it in from the per-dimension fields ([CreateAliasCmd.java](https://github.com/nick-boss-tech/solr/blob/f4b8ce83365442d775a1a746ef8e345eb2da2c03/solr/core/src/java/org/apache/solr/cloud/api/collections/CreateAliasCmd.java#L119-L134)).

Error text changes for some invalid requests:

- A routed alias without `router.field` now fails with "Missing required parameter: router.field."
- A request with `router.field` but no `router.name` now fails with "Alias creation requires either a list of either collections ... or routers ..."

The v2 aliases endpoint with two routers starts working too, because the fix sits in the shared create path.

## Proof

On the base code, the dimensional success test gets a 400 with the ticket's message, and the API test fails on the expected message size (10 before, 11 now). With this change both pass. The new cases are in [CreateRoutedAliasTest.java](https://github.com/nick-boss-tech/solr/blob/f4b8ce83365442d775a1a746ef8e345eb2da2c03/solr/core/src/test/org/apache/solr/cloud/CreateRoutedAliasTest.java#L402-L500).

## A choice to check

**The field check moved out of the command and into the routed alias parser.**

The other route keeps the up-front check for both fields and fills in `router.field` for dimensional aliases in the create path. That keeps the old error text. This change moves the check, so the error text changes for those requests. Was moving the check the right call?

## Limits

**No cloud test covers the v2 endpoint, and clients that match the old error text need an update.**

- No cloud test goes through the v2 endpoint. Its behavior is covered by the API unit test, which checks the message sent to the command.
- Clients that match the old error text need an update.
