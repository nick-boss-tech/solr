## What happens today

**A provider closed before it ever connected can still open a ZooKeeper connection, and nothing closes that connection.**

The links in this section go to the merge-base, `cabedd1d968`, where the symptom is. [`ZkClientClusterStateProvider.close()`](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/solrj-zookeeper/src/java/org/apache/solr/client/solrj/impl/ZkClientClusterStateProvider.java#L185-L199) does nothing when the provider has never connected. It skips the close when the state reader is still null, so the provider is not marked closed. The next call to [`getZkStateReader()`](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/solrj-zookeeper/src/java/org/apache/solr/client/solrj/impl/ZkClientClusterStateProvider.java#L150-L182) then opens a new connection. Nothing closes it, because the caller has already called `close()`.

The connect-failure path the ticket names is already closed on main. Each failing connect closes the state reader it created, in the error branches at lines [167, 171 and 174](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/solrj-zookeeper/src/java/org/apache/solr/client/solrj/impl/ZkClientClusterStateProvider.java#L166-L175). This change covers the separate gap of closing before first use.

## What this change does

**After `close()`, the provider stays closed, including when it never connected.**

[`close()`](https://github.com/nick-boss-tech/solr/blob/1ca7bf9ad0e6efb442cb55cf95b455a8a721bd27/solr/solrj-zookeeper/src/java/org/apache/solr/client/solrj/impl/ZkClientClusterStateProvider.java#L185-L199) now marks the provider closed whenever it is not closed yet. It closes the state reader only if one exists. A provider closed before first use throws `AlreadyClosedException` from every later call.

Behavior change: after `close()`, every later call throws `AlreadyClosedException`. That includes a call that would have connected again before this change. A provider closed after it connected behaves as before.

## Proof

**Both new tests fail on the base code with a connect timeout, and pass with this change.**

`ZkClientClusterStateProviderCloseTest` passes 2 of 2 at head `1ca7bf9ad0`, verified 2026-10-14. On the base code (`cabedd1d968`, verified 2026-10-14), with the production change reverted and the test kept, the run gives 2 tests and 2 failures. Each test expected `AlreadyClosedException` and got a timeout while the provider tried to connect to `127.0.0.1:1`. `testCloseBeforeFirstUseIsFinal` failed in 1.585 s, and `testCloseIsIdempotent` failed in 1.209 s.

The [test class](https://github.com/nick-boss-tech/solr/blob/1ca7bf9ad0e6efb442cb55cf95b455a8a721bd27/solr/solrj-zookeeper/src/test/org/apache/solr/client/solrj/impl/ZkClientClusterStateProviderCloseTest.java#L26-L44) holds the two checks. `testCloseBeforeFirstUseIsFinal` closes a provider that never connected and expects `AlreadyClosedException` from `getZkStateReader()`. `testCloseIsIdempotent` closes it twice and expects the same exception.

## Limits

**The change is limited to the SolrJ ZooKeeper client. The tests use an address that nothing listens on.**

- The tests connect to `127.0.0.1:1`, so they do not exercise a live ZooKeeper connection.
- No server code changes.
