## What happens today

**A core created with an empty collection name registers under an empty collection name.**

When the `collection` property is missing, the core takes its core name. When it is present but empty, the value is kept, in [CloudDescriptor.java L53](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/cloud/CloudDescriptor.java#L53). That link goes to the merge-base, the code before this change. A 2014 comment reproduces it from the core admin page with the defaults. It reports an IllegalArgumentException about a path that ends in "/", raised only after a poison pill state is published to the Overseer queue.

## What this change does

**An empty collection name now defaults to the core name, as a missing one does.**

The fix is one line in [CloudDescriptor.java L54](https://github.com/nick-boss-tech/solr/blob/90b8baa08aefd83cbee7e6e17ca9c59fcc93b30f/solr/core/src/java/org/apache/solr/cloud/CloudDescriptor.java#L54). Cores that already have an empty `collection` value in core.properties now load under their core name, and no test covers them. The constructor is called from [CoreDescriptor.java L209](https://github.com/nick-boss-tech/solr/blob/90b8baa08aefd83cbee7e6e17ca9c59fcc93b30f/solr/core/src/java/org/apache/solr/core/CoreDescriptor.java#L209).

## Proof

**CloudDescriptorTest passes 3 of 3 at head 90b8baa08ae, recorded 2026-10-07.**

On base, the class runs 3 tests with exactly 1 failure. [testEmptyCollectionNameDefaultsToCoreName](https://github.com/nick-boss-tech/solr/blob/90b8baa08aefd83cbee7e6e17ca9c59fcc93b30f/solr/core/src/test/org/apache/solr/cloud/CloudDescriptorTest.java#L33-L38) fails, because the empty name comes back as an empty string. The missing-name and explicit-name tests pass on base and after the change.

## A choice to check

**This change defaults the empty name. The alternative is to reject it when the core is created.**

The ticket title asks for a clean failure in SolrCloud mode. Rejecting the name would give callers that error. It would also change what `collection=` returns, and it needs an error path that this change does not add. The 2014 commit messages describe the tests as checking for a default to the core name. Was defaulting the right call?

## Limits
