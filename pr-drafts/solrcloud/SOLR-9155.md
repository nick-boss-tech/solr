## What happens today

**An interrupt during the leader lookup is wrapped in a generic error, and the interrupt status is cleared.**

`getLeader` catches every exception. It logs the failure at ERROR and throws a SolrException that says only that the leader lookup failed for a shard ([generic catch](https://github.com/nick-boss-tech/solr/blob/9f08d033023331dedfd555e8f014e6f0c5a384db/solr/core/src/java/org/apache/solr/cloud/ZkController.java#L1731-L1739)). An InterruptedException goes through the same catch. The message does not say that the thread was interrupted, and the interrupt status is lost.

## What this change does

**An interrupt now restores the thread's interrupt status and is reported as an interrupt. Other failures keep their exception type and get a clearer message.**

- A separate catch for InterruptedException restores the flag and throws a SolrException that keeps the interrupt as its cause ([interrupt catch](https://github.com/nick-boss-tech/solr/blob/9f08d033023331dedfd555e8f014e6f0c5a384db/solr/core/src/java/org/apache/solr/cloud/ZkController.java#L1725-L1730)).
- The generic catch no longer logs. Its message names the collection and suggests checking ZooKeeper and the shard's elected leader ([message](https://github.com/nick-boss-tech/solr/blob/9f08d033023331dedfd555e8f014e6f0c5a384db/solr/core/src/java/org/apache/solr/cloud/ZkController.java#L1731-L1739)).
- `getLeader` is package-private instead of private, so the same-package test can call it ([signature](https://github.com/nick-boss-tech/solr/blob/9f08d033023331dedfd555e8f014e6f0c5a384db/solr/core/src/java/org/apache/solr/cloud/ZkController.java#L1675)).

Behavior changes, stated openly: the interrupt status is set when the exception reaches the caller, so code that blocks later on the same thread sees the interrupt. Two callers are in that position, [register](https://github.com/nick-boss-tech/solr/blob/9f08d033023331dedfd555e8f014e6f0c5a384db/solr/core/src/java/org/apache/solr/cloud/ZkController.java#L1485) and [rejoin](https://github.com/nick-boss-tech/solr/blob/9f08d033023331dedfd555e8f014e6f0c5a384db/solr/core/src/java/org/apache/solr/cloud/ZkController.java#L2608). The ERROR log line is removed. The cause stays in the exception chain.

## A choice to check

**The interrupt still surfaces as a SolrException, with the flag restored. The other route declares InterruptedException on getLeader.**

The implemented route keeps the signature and the callers unchanged. The cost is that the checked interrupt becomes an unchecked SolrException, which the ticket text names as a problem. The other route declares `throws InterruptedException` on getLeader. Both callers already handle Exception, so that change is small. Was wrapping the interrupt in a SolrException the right call, or should getLeader declare InterruptedException?

## Limits

- The ticket's point about exceptions used for flow control is not addressed. The conflicting-leader check still throws inside the try block, and the generic catch wraps it again ([conflict check](https://github.com/nick-boss-tech/solr/blob/9f08d033023331dedfd555e8f014e6f0c5a384db/solr/core/src/java/org/apache/solr/cloud/ZkController.java#L1695-L1702)). A follow-up ticket and PR can cover it on request.
- The generic message also covers the conflicting-leader case, where ZooKeeper may be reachable. The cause keeps the specific message.
- The test interrupts the thread before the call. It covers the first blocking step, not an interrupt that arrives while the lookup waits.

## Proof

**One new test fails on the base code and passes with this change.**

- `ZkControllerGetLeaderTest` 1 of 1 at head 9f08d033023, verified on [date to confirm] ([test](https://github.com/nick-boss-tech/solr/blob/9f08d033023331dedfd555e8f014e6f0c5a384db/solr/core/src/test/org/apache/solr/cloud/ZkControllerGetLeaderTest.java#L39-L59)). `testInterruptIsNotSwallowed` sets the interrupt flag, calls getLeader, and checks the message and the flag. On the base code the test fails at the message check, because the base message does not name an interrupt. With this change it passes.
