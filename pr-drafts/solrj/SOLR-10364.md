## What happens today

**A bean field declared as a Set cannot take several values from one document field.**

On the merge-base commit, `DocumentObjectBinder` has branches for List, Collection and array fields, and none for Set ([DocumentObjectBinder.java](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/solrj/src/java/org/apache/solr/client/solrj/beans/DocumentObjectBinder.java#L288-L297)). A multi-valued field reaches the final set call as a list ([L492-L493](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/solrj/src/java/org/apache/solr/client/solrj/beans/DocumentObjectBinder.java#L492-L493)). The reflective set fails on the Set field, so binding throws a BindingException.

## What this change does

**A bean field declared as Set, HashSet or LinkedHashSet is filled from the document's values.**

The declaration accepts the three types ([DocumentObjectBinder.java](https://github.com/nick-boss-tech/solr/blob/efb1e6717f9ffda64b52c0820efb52ba58832b50/solr/solrj/src/java/org/apache/solr/client/solrj/beans/DocumentObjectBinder.java#L299-L304)). On binding, the values go into a LinkedHashSet and the set is assigned to the field ([L498-L505](https://github.com/nick-boss-tech/solr/blob/efb1e6717f9ffda64b52c0820efb52ba58832b50/solr/solrj/src/java/org/apache/solr/client/solrj/beans/DocumentObjectBinder.java#L498-L505)). Duplicates are dropped and the first-seen order is kept. A single value becomes a one-value set. A Set field declared as a child document throws a BindingException.

## Proof

**The new test fails on the base code and passes with this change.**

`TestDocumentObjectBinder` passes 6 of 6 at head `efb1e6717f9ffda64b52c0820efb52ba58832b50`, verified 2026-10-11, with no failures. The new test is [testSetFields](https://github.com/nick-boss-tech/solr/blob/efb1e6717f9ffda64b52c0820efb52ba58832b50/solr/solrj/src/test/org/apache/solr/client/solrj/beans/TestDocumentObjectBinder.java#L172-L189). On the base `DocumentObjectBinder.java`, with the new test kept, it fails with a BindingException: the binder cannot set the list of values on the Set field. The other five tests pass there. With this change it passes.

## Limits

**Only bean Set fields are handled. Set values inside a Map are not.**

- A `Map<String, Set<String>>` field is not handled, and the Map path is unchanged. We can open a follow-up ticket and pull request for it on request.
- Other Set types, such as SortedSet and TreeSet, are not matched and keep the old behavior.
- The test covers the binder only, through `getBeans` and `toSolrInputDocument`. No query runs against a Solr server.
