## What happens today

**Queued requests with different credentials or headers can share one HTTP stream, so a document can go out under another identity or with another request's headers.**

A queued request joins an open stream when the collection and the parameters match. The check does not look at the user, the password or the headers. The stream's HTTP request is decorated with the credentials of the request that opened it ([line 209](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/solrj-jetty/src/java/org/apache/solr/client/solrj/jetty/ConcurrentUpdateJettySolrClient.java#L209)), so a later document from another user goes out under that user. The old match is at [lines 126-129](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/solrj-jetty/src/java/org/apache/solr/client/solrj/jetty/ConcurrentUpdateJettySolrClient.java#L126-L129). Both links are at the merge-base with upstream/main, `cabedd1d968059215188f4e7563fb303241899ed`, which the branch starts from.

## What this change does

**Each stream keeps a copy of the credentials and headers of the request that opened it, and only matching requests join it.**

The stream records the user, the password and a copy of the headers of the opening request ([lines 127-132 at this head](https://github.com/nick-boss-tech/solr/blob/8b2e826154afb883cfbbe32b3247b53811991939/solr/solrj-jetty/src/java/org/apache/solr/client/solrj/jetty/ConcurrentUpdateJettySolrClient.java#L127-L132)). The match checks all of them ([lines 142-148 at this head](https://github.com/nick-boss-tech/solr/blob/8b2e826154afb883cfbbe32b3247b53811991939/solr/solrj-jetty/src/java/org/apache/solr/client/solrj/jetty/ConcurrentUpdateJettySolrClient.java#L142-L148)). Requests with other credentials or headers open a separate stream. Because the stream holds its own copy, a later change to a queued request's header map does not change the match.

This is a behavior change. A client that alternates credentials or headers now opens more streams than before.

## Proof

**Two shared tests fail on the base and pass with this change: one for credentials, one for headers.**

Both tests are in [ConcurrentUpdateSolrClientTestBase](https://github.com/nick-boss-tech/solr/blob/8b2e826154afb883cfbbe32b3247b53811991939/solr/solrj/src/test/org/apache/solr/client/solrj/impl/ConcurrentUpdateSolrClientTestBase.java). The credential test is [lines 306-340](https://github.com/nick-boss-tech/solr/blob/8b2e826154afb883cfbbe32b3247b53811991939/solr/solrj/src/test/org/apache/solr/client/solrj/impl/ConcurrentUpdateSolrClientTestBase.java#L306-L340), and the header test is [lines 342-372](https://github.com/nick-boss-tech/solr/blob/8b2e826154afb883cfbbe32b3247b53811991939/solr/solrj/src/test/org/apache/solr/client/solrj/impl/ConcurrentUpdateSolrClientTestBase.java#L342-L372). Each queues 20 documents on one client. The credential test alternates two users. The header test alternates two values of a custom header, and the test servlet records the header each document arrived with. Both suites run the shared base: `ConcurrentUpdateJettySolrClientTest` and `ConcurrentUpdateJdkSolrClientTest`.

- Base (`cabedd1d968059215188f4e7563fb303241899ed`), with the branch's tests in place: `ConcurrentUpdateJettySolrClientTest`, 13 tests, 2 failures. The header test fails with a document meant for beta sent under another header (expected beta, got alpha). The credential test also fails, as expected, because the base lacks the credentials change.
- This head (`8b2e826154afb883cfbbe32b3247b53811991939`): `ConcurrentUpdateJettySolrClientTest`, 13 tests, 0 failures. `ConcurrentUpdateJdkSolrClientTest`, 13 tests, 0 failures.
- The header test also passes at `6120dae28d04a07763f44d4bc5e9d9793af025f6`, the head before the copy was added, with 13 tests and 0 failures.

Verified 2026-10-14 at head `8b2e826154`.

## Limits

**The tests depend on timing. The header copy has no test, and the user principal is not part of the match.**

- The credential and header tests need several queued updates to meet on one stream. The recorded runs are single passes at the patched head, not a deterministic proof.
- The header test would also pass without the copy, so it does not show the copy works. No test changes a queued request's headers, so the copy itself is not tested.
- Whether the per-request user principal reaches the wire on a shared stream was not checked.
- No base run was made for the JDK suite, so its failures at the base are not shown.
