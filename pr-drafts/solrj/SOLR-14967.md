## What happens today

**For params that cannot be changed, CloudSolrClient never set its own state version, so a caller's value was the only one the server saw.**

For `ModifiableSolrParams`, CloudSolrClient sets or removes `_stateVer_` on the request's own params. For other params types, such as `MultiMapSolrParams` and `MapSolrParams`, the code does nothing ([base, lines 673-679](https://github.com/nick-boss-tech/solr/blob/b5c71bc5573c4e31b4cee5a7965d73587fc0ae58/solr/solrj/src/java/org/apache/solr/client/solrj/impl/CloudSolrClient.java#L673-L679)). A `_stateVer_` that the caller put in those params is sent on the first attempt and on every retry.

## What this change does

**Requests with params that cannot be changed now get a copy of their params that carries the client's own state version.**

The copy is a new `ModifiableSolrParams`, so the caller's object is not changed ([lines 705-708](https://github.com/nick-boss-tech/solr/blob/ee76643f5b3fa1809d204b6c4953aa9d54120589/solr/solrj/src/java/org/apache/solr/client/solrj/impl/CloudSolrClient.java#L705-L708)). When the client has a state version for the collection, it replaces a caller-supplied value on the first attempt. When it has none, or on a retry that omits the version, it removes a caller-supplied value from the copy ([lines 709-713](https://github.com/nick-boss-tech/solr/blob/ee76643f5b3fa1809d204b6c4953aa9d54120589/solr/solrj/src/java/org/apache/solr/client/solrj/impl/CloudSolrClient.java#L709-L713)). Requests with modifiable params keep the existing code path.

Behavior change: these requests now carry `_stateVer_`, so the server's stale-state error can reach the client. The client already retries that error for requests that name a collection.

## Proof

**Nine tests in `CloudSolrClientCacheTest` pass at this head. Against the first version of the change, the caller-value test fails.**

- `CloudSolrClientCacheTest` 9/9 at [ee76643f5b3](https://github.com/nick-boss-tech/solr/blob/ee76643f5b3fa1809d204b6c4953aa9d54120589/solr/solrj/src/test/org/apache/solr/client/solrj/impl/CloudSolrClientCacheTest.java#L199-L286), verified 2026-10-03. The three new tests are `testImmutableParamsCarryStateVersionAndOriginalUnchanged`, `testImmutableParamsStaleRetryOmitsStateVersion` and `testImmutableParamsCallerStateVersionRemovedOnStaleRetry`.
- Against the first version, before the commit that also clears a caller-supplied value on the retry, `testImmutableParamsCallerStateVersionRemovedOnStaleRetry` fails. The retry sends `caller:999`, and the test expects no `_stateVer_` on that retry. The other eight tests pass.
- The three new tests were not run against the base commit.
- The run at this head also passed Solr's tidy check, compiled with Error Prone, and ran the solrj module check with tests skipped.

## Limits

**The tests replace the send step with a fake, and two cases are not tested.**

- A recording client replaces the send step, so no test reaches a server.
- The tests use `MultiMapSolrParams` and `MapSolrParams` only.
- Requests without a collection, such as admin requests, are not tested with a caller-supplied value.
- A follow-up test for these cases is possible on request.
