## What happens today

**A commitWithin value set on a content upload request is kept on the request but never sent to Solr.**

`ContentWriterUpdateRequest` sends its content as an opaque body. Its parent class keeps `setCommitWithin` as a plain field ([AbstractUpdateRequest.java lines 145-148 (base)](https://github.com/apache/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/solrj/src/java/org/apache/solr/client/solrj/request/AbstractUpdateRequest.java#L145-L148)). For document updates, the XML writer reads that field and writes it into the body ([XMLRequestWriter.java line 92 (base)](https://github.com/apache/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/solrj/src/java/org/apache/solr/client/solrj/request/XMLRequestWriter.java#L92)). A content upload has no such step. Nothing copies the field into the request parameters.

## What this change does

**`ContentWriterUpdateRequest` now sets the `commitWithin` request parameter when the value is set. A negative value removes the parameter.**

The override is in [ContentWriterUpdateRequest.java lines 58-71](https://github.com/nick-boss-tech/solr/blob/2ca0b3743427c1c35aa4801dbea9bfcf6d0d8fb4/solr/solrj/src/java/org/apache/solr/client/solrj/request/ContentWriterUpdateRequest.java#L58-L71). It still calls the parent method first, so `getCommitWithin()` returns the same value as before.

Behavior change: a content upload that sets `commitWithin` now sends the parameter. Before this change, it did not. The change touches this one class and adds one test class.

The failing test is `testCommitWithinIsSentAsRequestParameter`, at [line 32](https://github.com/nick-boss-tech/solr/blob/2ca0b3743427c1c35aa4801dbea9bfcf6d0d8fb4/solr/solrj/src/test/org/apache/solr/client/solrj/request/TestContentWriterUpdateRequest.java#L32). It fails with `expected:<1234> but was:<null>`, because the parameter is missing. The other test, `testNegativeCommitWithinRemovesTheParameter`, passes on the base code.

## Limits

**The test checks the request object. It does not run against a Solr server.**

- Whether each upload handler reads `commitWithin` from the request parameters is not checked here.
- Calling `setParams` after `setCommitWithin` replaces the parameter map, so the parameter is lost while the field still holds the value. [`setParams` is at AbstractUpdateRequest.java lines 112-115 (base)](https://github.com/apache/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/solrj/src/java/org/apache/solr/client/solrj/request/AbstractUpdateRequest.java#L112-L115). This change does not cover that order. A follow-up ticket and pull request for it can be opened on request.
- Only `ContentWriterUpdateRequest` changes. Other request classes are not checked.
