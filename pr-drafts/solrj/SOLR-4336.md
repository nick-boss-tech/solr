## What happens today

**A blank numeric parameter makes the request fail instead of using the default.**

The ticket's example is `/select?q=*:*&start=&rows=10`. In the base code, `getInt` passes the empty string to `Integer.valueOf`, and any failure is rethrown as a bad request error ([base](https://github.com/nick-boss-tech/solr/blob/97d973814336101e12475558d7419321c743de79/solr/solrj/src/java/org/apache/solr/common/params/SolrParams.java#L217-L223), base). The ticket reports that Solr 4.0 used the default.

## What this change does

**The numeric getters treat an exactly empty value as unset, so the default applies.**

The helpers are [`getNumeric` and `getFieldNumeric`](https://github.com/nick-boss-tech/solr/blob/798618aa08fd6de759bad798a825bdf80ee77201/solr/solrj/src/java/org/apache/solr/common/params/SolrParams.java#L209-L219). The int, long, float and double getters use them, and so do `getFieldInt`, `getFieldFloat` and `getFieldDouble`, with and without a default. A getter with no default returns null for an empty value.

A blank field value (`f.title.start=`) counts as unset for that field. It does not fall back to the plain `start` value, so the field gets the default even when `start=3` is also sent. The same empty-string rule applies to any parameter whose value is empty, including a parameter converted from an empty `str` element in a solrconfig.xml list.

## Proof

**The two new tests fail on the base code and pass with this change.**

- `SolrParamTest` 11/11 at head `798618aa08fd`. The two new tests are `testBlankNumericParamIsUnset` and `testBlankFieldNumericParamIsUnset`.
- On the base code, two of the eleven tests fail, and they are these two. A blank value throws where this change returns the default.
- The module check task, without tests, passed.

Verified 2026-10-06 at this head.

## Limits

**Whitespace, booleans, required parameters and the request path are not covered.**

- A value of only spaces still throws a bad request error.
- The boolean getters are unchanged.
- [`RequiredSolrParams`](https://github.com/nick-boss-tech/solr/blob/798618aa08fd6de759bad798a825bdf80ee77201/solr/solrj/src/java/org/apache/solr/common/params/RequiredSolrParams.java#L113-L116) passes its defaulted numeric getters to the wrapped parameters, and its `get` treats only a missing value as an error. A required numeric parameter sent blank therefore gets the default or null, not an error. No test covers that path.
- The new tests do not cover a missing key, where `get` returns null. They call `SolrParams` directly and do not send a request to a handler.
