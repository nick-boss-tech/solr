## What happens today

**A 403 or 404 answer from one server marks that server as down, even when the server is working.**

`LBSolrClient` sends a failed request to another server. For a 403 or 404 it also marks the first server as a zombie, so that server gets no traffic until the alive check revives it. The same zombie step runs for 500 and 503 ([retry codes, base lines 132-133](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/solrj/src/java/org/apache/solr/client/solrj/impl/LBSolrClient.java#L132-L133); [zombie step, base lines 647-650](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/solrj/src/java/org/apache/solr/client/solrj/impl/LBSolrClient.java#L647-L650)). A 403 or 404 does not mean the server is down. The ticket describes this case.

## What this change does

**A 403 or 404 still moves the request to another server, but the first server stays in rotation.**

The zombie step now skips 403 and 404 ([lines 650-652 at this head](https://github.com/nick-boss-tech/solr/blob/e415c409044c4a6cc846cddfe56c1d7b9f262767/solr/solrj/src/java/org/apache/solr/client/solrj/impl/LBSolrClient.java#L650-L652)). The other retry codes, 500 and 503, still mark the server as a zombie. Connection failures are handled as before.

## Limits

**Only the synchronous client changes, and only 403 and 404 change.**

- [LBAsyncSolrClient](https://github.com/nick-boss-tech/solr/blob/e415c409044c4a6cc846cddfe56c1d7b9f262767/solr/solrj/src/java/org/apache/solr/client/solrj/impl/LBAsyncSolrClient.java#L194-L197) has the same zombie step for 403 and 404. This change does not touch it. A follow-up can be opened on request.
- Other 4xx codes, such as 400, were never marked as zombies. They are not on the retry list, so the client throws them to the caller ([base lines 651-656](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/solrj/src/java/org/apache/solr/client/solrj/impl/LBSolrClient.java#L651-L656)).
- A server that keeps answering 403 or 404 stays in rotation. Some requests still try it first and then fail over to another server.
