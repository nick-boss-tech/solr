## What happens today

**At the merge-base, a fractional `spellcheck.maxResultsForSuggest` with filters is checked against one core's own slice.**

The links in this section point at the merge-base commit `e2cdb2d7e8ae0be4cf6cf0606206c67d89e7278f`. Each shard computes the threshold from its own counts ([shard](https://github.com/nick-boss-tech/solr/blob/e2cdb2d7e8ae0be4cf6cf0606206c67d89e7278f/solr/core/src/java/org/apache/solr/handler/component/SpellCheckComponent.java#L242-L292)), and the coordinator does the same ([coordinator](https://github.com/nick-boss-tech/solr/blob/e2cdb2d7e8ae0be4cf6cf0606206c67d89e7278f/solr/core/src/java/org/apache/solr/handler/component/SpellCheckComponent.java#L404)).

## What this change does

**A fractional `spellcheck.maxResultsForSuggest` is now applied to the filtered document count summed across all shards of a distributed request, not to the coordinator's own slice.**

Each shard reports its count for each filter as a list ([SpellCheckComponent.java L234-L239](https://github.com/nick-boss-tech/solr/blob/3a456c27dda52061e95eeabf9bd228cc48e1ea47/solr/core/src/java/org/apache/solr/handler/component/SpellCheckComponent.java#L234-L239)). The coordinator adds the lists up element by element and takes the smallest total across the filters ([L335-L364](https://github.com/nick-boss-tech/solr/blob/3a456c27dda52061e95eeabf9bd228cc48e1ea47/solr/core/src/java/org/apache/solr/handler/component/SpellCheckComponent.java#L335-L364)). It passes that total into the threshold ([L476-L479](https://github.com/nick-boss-tech/solr/blob/3a456c27dda52061e95eeabf9bd228cc48e1ea47/solr/core/src/java/org/apache/solr/handler/component/SpellCheckComponent.java#L476-L479)). The fallback for when no shard reports the key is unchanged.

The branch also adds a distributed test for the multi-filter case ([DistributedSpellCheckComponentTest.java L424-L464](https://github.com/nick-boss-tech/solr/blob/3a456c27dda52061e95eeabf9bd228cc48e1ea47/solr/core/src/test/org/apache/solr/handler/component/DistributedSpellCheckComponentTest.java#L424-L464)). Its per-shard counts are fixed. After it adds the fixture documents, it rebuilds the index-based spellcheck dictionary, so the new terms are visible to that handler.

## Limits

**When no shard sends a list, the coordinator uses its own slice, as before.**

During a rolling upgrade, shards on the old code send no list. The sum then covers only the upgraded shards, so the threshold can come out too small.

The core module check ran with the test tasks excluded, so the rest of the core test suite did not run at this head. The proof was run at one random seed. The class picks its request handler at random, so another seed can take a different path.
