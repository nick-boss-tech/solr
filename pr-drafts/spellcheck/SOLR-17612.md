## What happens today

**At the merge-base, a fractional `spellcheck.maxResultsForSuggest` with filters is checked against one core's own slice.**

The links in this section point at the merge-base commit `e2cdb2d7e8ae0be4cf6cf0606206c67d89e7278f`. Each shard computes the threshold from its own counts ([shard](https://github.com/nick-boss-tech/solr/blob/e2cdb2d7e8ae0be4cf6cf0606206c67d89e7278f/solr/core/src/java/org/apache/solr/handler/component/SpellCheckComponent.java#L242-L292)), and the coordinator does the same ([coordinator](https://github.com/nick-boss-tech/solr/blob/e2cdb2d7e8ae0be4cf6cf0606206c67d89e7278f/solr/core/src/java/org/apache/solr/handler/component/SpellCheckComponent.java#L404)).

## What this change does

**A fractional `spellcheck.maxResultsForSuggest` is now applied to the filtered document count summed across all shards of a distributed request, not to the coordinator's own slice.**

Each shard reports its count for each filter as a list. The coordinator adds the lists up element by element, then takes the smallest total across the filters ([SpellCheckComponent.java](https://github.com/nick-boss-tech/solr/blob/3a456c27dda52061e95eeabf9bd228cc48e1ea47/solr/core/src/java/org/apache/solr/handler/component/SpellCheckComponent.java)). The fallback for when no shard reports the key is unchanged.

The branch also adds a distributed test for the multi-filter case ([DistributedSpellCheckComponentTest.java](https://github.com/nick-boss-tech/solr/blob/3a456c27dda52061e95eeabf9bd228cc48e1ea47/solr/core/src/test/org/apache/solr/handler/component/DistributedSpellCheckComponentTest.java)). The fixture counts are fixed, but the test still picks its request handler at random. It rebuilds the spellcheck dictionary after it commits its fixture documents, so the control request returns the suggestion the test expects.

## Limits

**When no shard sends a list, the coordinator uses its own slice, as before.**

During a rolling upgrade, shards on the old code send no list, so the sum covers only the upgraded shards. The core module check ran with the test tasks excluded, so the rest of the core test suite did not run at this head.
