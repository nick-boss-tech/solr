## What happens today

**In the pre-fix tree, a distributed request with a fractional `spellcheck.maxResultsForSuggest` and several filters drops a suggestion.**

The links in this section point at the pre-fix tree, commit `dd2708fbb7e516fb8b6a593f96082a443e840b50`. Each shard reports the smallest of its own filter counts ([per-shard minimum](https://github.com/nick-boss-tech/solr/blob/dd2708fbb7e516fb8b6a593f96082a443e840b50/solr/core/src/java/org/apache/solr/handler/component/SpellCheckComponent.java#L305-L337)). The coordinator adds those counts together ([sum](https://github.com/nick-boss-tech/solr/blob/dd2708fbb7e516fb8b6a593f96082a443e840b50/solr/core/src/java/org/apache/solr/handler/component/SpellCheckComponent.java#L342-L354)), which gives the wrong threshold. The distributed response suppresses the suggestion, while the control leg, which runs on a single core, returns it.

## What this change does

**A fractional `spellcheck.maxResultsForSuggest` is now applied to the filtered document count summed across all shards of a distributed request, not to the coordinator's own slice.**

Each shard reports its count for each filter as a list. The coordinator adds the lists up element by element, then takes the smallest total across the filters ([SpellCheckComponent.java](https://github.com/nick-boss-tech/solr/blob/3a456c27dda52061e95eeabf9bd228cc48e1ea47/solr/core/src/java/org/apache/solr/handler/component/SpellCheckComponent.java)). The fallback for when no shard reports the key is unchanged.

The branch also adds a distributed test for the multi-filter case ([DistributedSpellCheckComponentTest.java](https://github.com/nick-boss-tech/solr/blob/3a456c27dda52061e95eeabf9bd228cc48e1ea47/solr/core/src/test/org/apache/solr/handler/component/DistributedSpellCheckComponentTest.java)). The test is deterministic. It rebuilds the spellcheck dictionary after it commits its fixture documents, so the control request returns the suggestion the test expects.

## Limits

**When no shard reports the key, the fallback stays silent.**

Mixed-version clusters during a rolling upgrade produce exactly that case. The core module check ran with the test tasks excluded, so the rest of the core test suite did not run at this head.
