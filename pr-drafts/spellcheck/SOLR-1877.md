## What happens today

**Spell checkers that read a Lucene index are never closed, so their readers and directories stay open.**

On reload, `IndexBasedSpellChecker` opens a new reader on the source index. It overwrites the old reader without closing it ([merge-base code](https://github.com/nick-boss-tech/solr/blob/c3cdf7b46e8cfff3673f76d881f32cf8e7b00622/solr/core/src/java/org/apache/solr/spelling/IndexBasedSpellChecker.java#L57-L66), [merge-base reload](https://github.com/nick-boss-tech/solr/blob/c3cdf7b46e8cfff3673f76d881f32cf8e7b00622/solr/core/src/java/org/apache/solr/spelling/IndexBasedSpellChecker.java#L102-L107)). Each reload leaves one more reader open.

Solr has no close path for spell checkers. The merge-base code says so in a comment: "Solr never seems to close its spell checkers" ([merge-base comment](https://github.com/nick-boss-tech/solr/blob/c3cdf7b46e8cfff3673f76d881f32cf8e7b00622/solr/core/src/java/org/apache/solr/spelling/AbstractLuceneSpellChecker.java#L232-L236)).

## What this change does

**Spell checkers now close with the core. A reload closes the old reader once no search is still using it.**

- Every spell checker has a `close()` method. The Lucene-based checkers close their spell checker and their index directory ([code](https://github.com/nick-boss-tech/solr/blob/5533ba27b17e4ed65c45d3ea863c6cf024916abd/solr/core/src/java/org/apache/solr/spelling/AbstractLuceneSpellChecker.java#L224-L231)).
- The core runs a close hook that closes every spell checker it holds ([code](https://github.com/nick-boss-tech/solr/blob/5533ba27b17e4ed65c45d3ea863c6cf024916abd/solr/core/src/java/org/apache/solr/handler/component/SpellCheckComponent.java#L737-L743)).
- `IndexBasedSpellChecker` guards its source reader with one read-write lock. Searches and builds hold the read side for their whole run. A reload takes the write side only to swap the reader. It closes the old reader and directory after the lock is released ([code](https://github.com/nick-boss-tech/solr/blob/5533ba27b17e4ed65c45d3ea863c6cf024916abd/solr/core/src/java/org/apache/solr/spelling/IndexBasedSpellChecker.java#L64-L89)).
- Behavior change: each suggestion request and each build now takes a read lock. A reload waits for searches already running, then swaps.

## Proof

**The new test does not compile on the merge-base code, so the only base result is a compile failure.**

- The new test is `testSourceReaderClosedOnReloadAndClose` ([IndexBasedSpellCheckerTest.java L313-L349](https://github.com/nick-boss-tech/solr/blob/5533ba27b17e4ed65c45d3ea863c6cf024916abd/solr/core/src/test/org/apache/solr/spelling/IndexBasedSpellCheckerTest.java#L313-L349)). It calls `close()`, which the merge-base code does not have. No test failure was seen on the merge-base code.
- Checked 2026-10-12 at head `5533ba27b17e`: `SpellCheckComponentTest` 14 run, 0 failures. `IndexBasedSpellCheckerTest` 6 run, 0 failures.

## A choice to check

**A reload closes the old reader under a lock. The other route was to drop the reload close and keep only the close at shutdown.**

- The lock has a cost. Each suggestion and build takes a read lock, and a reload waits for searches already running.
- Dropping the reload close is simpler. But the old reader would then stay open until the core closes. That leaves part of the leak the ticket names.

Was the lock the right call, or should the reload close go?

## Limits

**The race fix has no test, and the failure path for an unreadable source index is not tested.**

- No test holds a search open across a reload. The fix for that overlap was checked by reading the code.
- If opening the source index fails, the new directory is closed and the error is rethrown. That path is not tested.
- The core close hook has no test of its own. The new test calls `close()` directly.
