## What happens today

**A query word with an apostrophe is split in two. `pandora's` becomes `pandora` and `'s`.**

For the query `pandora's star`, the spellcheck query converter produces three tokens: `pandora`, `'s`, and `star`. Spellcheck then works from those pieces, not from the word the user typed.

The base pattern has no rule that keeps an apostrophe inside a word ([base code](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/core/src/java/org/apache/solr/spelling/SpellingQueryConverter.java#L86)).

## What this change does

**An apostrophe followed by letters now stays inside the word.**

- The pattern gets one optional suffix: an apostrophe (ASCII or U+2019) and the letters after it ([SpellingQueryConverter.java](https://github.com/nick-boss-tech/solr/blob/aabd678dec7330c55dbc044ce6b2f46dd00a0c29/solr/core/src/java/org/apache/solr/spelling/SpellingQueryConverter.java#L86-L88)).
- `pandora's` is one token. Contractions follow the same rule, so `don't` is one token. Elisions with a prefix of two or more letters follow it too, so `qu'il` is one token.
- The rule is not limited to possessives. It applies to any apostrophe followed by letters.
- Text with no apostrophe tokenizes as before.

## Proof

**`SpellingQueryConverterTest` fails on the base code, and this head was checked.**

- On the base code, `SpellingQueryConverterTest` has exactly one failure.
- The new test is [`testApostropheStaysInWord`](https://github.com/nick-boss-tech/solr/blob/aabd678dec7330c55dbc044ce6b2f46dd00a0c29/solr/core/src/test/org/apache/solr/spelling/SpellingQueryConverterTest.java#L74-L87). It converts `pandora's star` and checks for two tokens: `pandora's` at offsets 0 to 9, then `star`.
- Checked at head `aabd678dec7` on 2026-10-06.

## Limits

**The new test is one ASCII case, and it checks tokens.**

- The U+2019 alternative in the pattern ([line 88](https://github.com/nick-boss-tech/solr/blob/aabd678dec7330c55dbc044ce6b2f46dd00a0c29/solr/core/src/java/org/apache/solr/spelling/SpellingQueryConverter.java#L88)) has no test.
- The test does not check the final collation, only the converter's tokens.
- Contractions and elisions follow the same rule, but no test covers them.
- A one-letter word before the apostrophe does not change. `l'homme` still gives the token `'homme`, and `d'accord` gives `'accord`, because the word part needs at least two characters.
