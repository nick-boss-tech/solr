## What happens today

**A misplaced `classname` is ignored with no message.**

A `SpellCheckComponent` config can put `classname` and `sourceLocation` directly under the component, outside `<lst name="spellchecker">`. Solr loads that config with no complaint. A query to that handler returns without any spellchecking. The ticket says an error would be more appropriate.

At the merge-base, the loop over the component's settings acts only on the `spellchecker` key and has no branch for `classname` ([L697-L698](https://github.com/nick-boss-tech/solr/blob/97d973814336101e12475558d7419321c743de79/solr/core/src/java/org/apache/solr/handler/component/SpellCheckComponent.java#L697-L698)).

## What this change does

**A top-level `classname` now fails the core load.**

The check is in `inform`. It throws a `SolrException` that points to the `spellchecker` list ([SpellCheckComponent.java L698-L707](https://github.com/nick-boss-tech/solr/blob/0af6087f43fa2b03a9cedb259c1b0dd62039963c/solr/core/src/java/org/apache/solr/handler/component/SpellCheckComponent.java#L698-L707)). Components that need the core are informed while the core is built ([SolrCore.java L1141](https://github.com/nick-boss-tech/solr/blob/0af6087f43fa2b03a9cedb259c1b0dd62039963c/solr/core/src/java/org/apache/solr/core/SolrCore.java#L1141)). The core constructor catches errors from that step and rethrows them ([L1167-L1186](https://github.com/nick-boss-tech/solr/blob/0af6087f43fa2b03a9cedb259c1b0dd62039963c/solr/core/src/java/org/apache/solr/core/SolrCore.java#L1167-L1186)).

This is a behavior change. A config with a top-level `classname` loads today and ignores those settings. After this change, it fails to load.

## Proof

**The new test fails on the base code and passes at this head.**

- At head `0af6087f43fa`, `SpellCheckComponentTest` passes 15 of 15 tests (JUnit XML, verified 2026-10-06).
- On the base code, with only this branch's test file added, `SpellCheckComponentTest` runs 15 tests with one failure. The failure is the new test, [`testSpellcheckerOutsideSpellcheckerListIsRejected`](https://github.com/nick-boss-tech/solr/blob/0af6087f43fa2b03a9cedb259c1b0dd62039963c/solr/core/src/test/org/apache/solr/handler/component/SpellCheckComponentTest.java#L284-L294), which reports "Expected exception SolrException but no exception was thrown". The other 14 pass.
- The new test sets `name`, `classname`, and `sourceLocation` at the top level. It expects a `SolrException` whose message contains "spellchecker".

## Limits

**The check covers `classname` only.**

The ticket asks that any top-level name other than `queryAnalyzerFieldType` throw. This change throws for `classname` alone. A top-level `class`, `sourceLocation`, `name`, or `field` is still ignored without a message. A follow-up ticket and PR for the wider check can be opened on request.

**The test has one trigger.**

It covers a `classname` placed with `name` and `sourceLocation`. It does not cover a misplaced key on its own, or a misplaced key without `classname`.
