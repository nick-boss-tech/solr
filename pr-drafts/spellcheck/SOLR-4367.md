## What happens today

**A misplaced `classname` is ignored with no message.**

A `SpellCheckComponent` config can put `classname` and `sourceLocation` directly under the component, outside `<lst name="spellchecker">`. Solr loads that config with no complaint. A query to that handler returns without any spellchecking. The ticket says an error would be more appropriate.

## What this change does

**A top-level `classname` now fails the core load.**

The check is in `inform`. It throws a `SolrException` that points to the `spellchecker` list ([SpellCheckComponent.java L698-L706](https://github.com/nick-boss-tech/solr/blob/0af6087f43fa2b03a9cedb259c1b0dd62039963c/solr/core/src/java/org/apache/solr/handler/component/SpellCheckComponent.java#L698-L706)). `inform` runs while the core is built ([SolrCore.java L1141](https://github.com/nick-boss-tech/solr/blob/0af6087f43fa2b03a9cedb259c1b0dd62039963c/solr/core/src/java/org/apache/solr/core/SolrCore.java#L1141)). The core constructor catches errors from that step and rethrows them ([L1167-L1186](https://github.com/nick-boss-tech/solr/blob/0af6087f43fa2b03a9cedb259c1b0dd62039963c/solr/core/src/java/org/apache/solr/core/SolrCore.java#L1167-L1186)).

This is a behavior change. A config with a top-level `classname` loads today and ignores those settings. After this change, it fails to load.

## Limits

**The check covers `classname` only.**

The ticket asks that any top-level name other than `queryAnalyzerFieldType` throw. This change throws for `classname` alone. A top-level `class`, `sourceLocation`, `name`, or `field` is still ignored without a message. A follow-up ticket and PR for the wider check can be opened on request.

**The test has one trigger.**

It covers a `classname` placed with `name` and `sourceLocation`. It does not cover a misplaced key on its own, or a misplaced key without `classname`.
