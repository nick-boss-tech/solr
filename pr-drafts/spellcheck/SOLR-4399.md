## What happens today

**A FileBasedSpellChecker with no `sourceLocation` fails on its first build with a NullPointerException.**

The configuration loads without complaint, because `init` does not check for the location ([merge-base code](https://github.com/nick-boss-tech/solr/blob/97d973814336101e12475558d7419321c743de79/solr/core/src/java/org/apache/solr/spelling/FileBasedSpellChecker.java#L60-L64)). A build then passes the missing location to the resource loader ([merge-base code](https://github.com/nick-boss-tech/solr/blob/97d973814336101e12475558d7419321c743de79/solr/core/src/java/org/apache/solr/spelling/FileBasedSpellChecker.java#L67-L68), [line 105](https://github.com/nick-boss-tech/solr/blob/97d973814336101e12475558d7419321c743de79/solr/core/src/java/org/apache/solr/spelling/FileBasedSpellChecker.java#L105), [line 121](https://github.com/nick-boss-tech/solr/blob/97d973814336101e12475558d7419321c743de79/solr/core/src/java/org/apache/solr/spelling/FileBasedSpellChecker.java#L121)). The loader calls `trim()` on that name, so the build fails with a NullPointerException ([merge-base loader](https://github.com/nick-boss-tech/solr/blob/97d973814336101e12475558d7419321c743de79/solr/core/src/java/org/apache/solr/core/SolrResourceLoader.java#L350-L351)). The message does not say what is missing.

## What this change does

**The build now stops with an error that names the missing `sourceLocation` parameter.**

- `build` checks for the location first. It throws a SolrException that names the spell checker and the parameter ([code](https://github.com/nick-boss-tech/solr/blob/82c0c11373d009f773980ba7f2d512e87e817eec/solr/core/src/java/org/apache/solr/spelling/FileBasedSpellChecker.java#L68-L78)).
- A configuration without a location still loads, as it does today. It can still answer queries without a build. Only a build fails.
- The error is a server error (HTTP 500), the same status as the NullPointerException it replaces.

## Proof

**The updated test checks that init succeeds and that build fails with the named parameter.**

- `FileBasedSpellCheckerTest` runs 4 of 4 at head `82c0c11373d0`, checked 2026-10-11. The new test is `testMissingSourceLocationIsRejectedAtBuild` ([FileBasedSpellCheckerTest.java L69-L82](https://github.com/nick-boss-tech/solr/blob/82c0c11373d009f773980ba7f2d512e87e817eec/solr/core/src/test/org/apache/solr/spelling/FileBasedSpellCheckerTest.java#L69-L82)).
- The failing run used an earlier version of the guard, one that rejected the missing location at init. That run failed at init. The test now expects init to succeed.
- The merge-base code has not been run against this test.

## A choice to check

**The check runs at build, not at init. The other route was to reject the missing location at init.**

- An init check gives the error at startup, which is earlier.
- But an init check also stops a configuration that loads and answers queries today, even though it never builds. A build-time check keeps that configuration working. The cost is that the error appears only when someone runs a build.

Was build the right place for the check?

## Limits

**The error is still a server error, and the ticket's default-name option is not added.**

- The error is HTTP 500. A 400 would fit a configuration mistake better. That change is not made here.
- The ticket also offers a default name when the location is missing. That is not added. The error names the missing parameter instead. The default-name option can be opened as a follow-up on request.
- The new test calls `build` directly. It does not send a spellcheck build request.
