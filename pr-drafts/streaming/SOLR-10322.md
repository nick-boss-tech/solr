## What happens today

**A topic stream with no client cache in its context fails with a NullPointerException when it reads its checkpoints on open.**

`TopicStream` reads persisted checkpoints through the stream context's `SolrClientCache` ([base](https://github.com/nick-boss-tech/solr/blob/97d973814336101e12475558d7419321c743de79/solr/solrj-streaming/src/java/org/apache/solr/client/solrj/io/stream/TopicStream.java#L486)). With no context cache, the stream's own cache is null too ([base](https://github.com/nick-boss-tech/solr/blob/97d973814336101e12475558d7419321c743de79/solr/solrj-streaming/src/java/org/apache/solr/client/solrj/io/stream/TopicStream.java#L550)), so that read dereferences null. This happens on open, when the stream has no checkpoints of its own and the checkpoint collection has an active replica on a live node.

The ticket reports a different failure: a 401 from the checkpoint collection under basic authentication.

## What this change does

**With no context cache, the stream opens its own cache and uses it for checkpoint reads.**

- On open, the stream creates a cache only when it has none, and closes it in `close()` ([L297-L301](https://github.com/nick-boss-tech/solr/blob/80ce9d7a3c8a61dfb5c5169a371890f11d9e17ff/solr/solrj-streaming/src/java/org/apache/solr/client/solrj/io/stream/TopicStream.java#L297-L301), [L352-L353](https://github.com/nick-boss-tech/solr/blob/80ce9d7a3c8a61dfb5c5169a371890f11d9e17ff/solr/solrj-streaming/src/java/org/apache/solr/client/solrj/io/stream/TopicStream.java#L352-L353)).
- The persisted-checkpoint read ([L485](https://github.com/nick-boss-tech/solr/blob/80ce9d7a3c8a61dfb5c5169a371890f11d9e17ff/solr/solrj-streaming/src/java/org/apache/solr/client/solrj/io/stream/TopicStream.java#L485)) and the per-slice query ([L427](https://github.com/nick-boss-tech/solr/blob/80ce9d7a3c8a61dfb5c5169a371890f11d9e17ff/solr/solrj-streaming/src/java/org/apache/solr/client/solrj/io/stream/TopicStream.java#L427)) use that cache.
- With no context cache, the data streams share it ([L541-L545](https://github.com/nick-boss-tech/solr/blob/80ce9d7a3c8a61dfb5c5169a371890f11d9e17ff/solr/solrj-streaming/src/java/org/apache/solr/client/solrj/io/stream/TopicStream.java#L541-L545)). With a context cache, nothing changes ([L552-L555](https://github.com/nick-boss-tech/solr/blob/80ce9d7a3c8a61dfb5c5169a371890f11d9e17ff/solr/solrj-streaming/src/java/org/apache/solr/client/solrj/io/stream/TopicStream.java#L552-L555)).

Before, that case hit the NullPointerException. Now it does not.

## Limits

**This change does not address the 401 in the ticket.**

- No test here uses basic authentication or a secured cluster, so the 401 is not reproduced.
- The change adds no credentials. The stream's own cache is built without them ([base](https://github.com/nick-boss-tech/solr/blob/97d973814336101e12475558d7419321c743de79/solr/solrj-streaming/src/java/org/apache/solr/client/solrj/io/SolrClientCache.java#L150)), so on a secured cluster the checkpoint read may still return 401. I did not test that.
- In cloud mode, the stream handler sets the node's cache ([base](https://github.com/nick-boss-tech/solr/blob/97d973814336101e12475558d7419321c743de79/solr/core/src/java/org/apache/solr/handler/StreamHandler.java#L111-L112)) and gives it to each stream context ([base](https://github.com/nick-boss-tech/solr/blob/97d973814336101e12475558d7419321c743de79/solr/core/src/java/org/apache/solr/handler/StreamHandler.java#L233)). That path is unchanged.
- I can open a follow-up ticket and PR with a streaming test on a security-enabled cluster, if you want that case covered.
