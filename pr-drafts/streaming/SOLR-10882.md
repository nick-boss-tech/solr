## What happens today

**Sorting an array that mixes text or a boolean with numbers fails with a ClassCastException.**

With `sort=asc` or `sort=desc`, the array evaluator checks only that each value is `Comparable` ([ArrayEvaluator.java lines 67 to 77](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/solrj-streaming/src/java/org/apache/solr/client/solrj/io/eval/ArrayEvaluator.java#L67-L77)). It then sorts with a raw `compareTo` ([lines 50 to 51](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/solrj-streaming/src/java/org/apache/solr/client/solrj/io/eval/ArrayEvaluator.java#L50-L51)), so a string compared with a number throws. Links here point to the merge-base commit.

## What this change does

**A sort over mixed kinds now stops with a clear IOException.**

All numbers count as one kind. Any other value counts as its own class. Two kinds in one sort throw an IOException such as "values of different types (String and Number)" ([ArrayEvaluator.java lines 69 to 89](https://github.com/nick-boss-tech/solr/blob/b12b0ffab487e88a790c0d6dab31bd4a7464be47/solr/solrj-streaming/src/java/org/apache/solr/client/solrj/io/eval/ArrayEvaluator.java#L69-L89)).

Behavior change: two non-number classes that Java can compare, such as `java.util.Date` and `java.sql.Date`, now get the error. The base code sorts them.

## A choice to check

**Mixed kinds now fail with an error. The other route sorts them in a fixed order.**

The options were an error for any sort that mixes kinds, which this change implements, or a fixed order across kinds, such as numbers before text. The error gives mixed input no result. A fixed order gives it one, but the project must define and keep that order. Was an error the right call, or should mixed kinds sort in a fixed order?

## Limits

**No test covers a boolean mixed with numbers, or two different non-number classes.**

The boolean case was checked by reading the code only. The two-class case changes behavior and was not run. The ticket's double and long case already sorts on the base code, so this change does not address it. SOLR-10882 is a 2017 ticket that tracks restructuring the stream evaluators. This change covers the two defects above, not the whole ticket. A follow-up ticket and PR can be opened on request.
