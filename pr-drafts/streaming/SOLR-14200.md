## What happens today

**A manual shards map with no entry for a collection makes the shard lookup return null, and the streams then fail with a NullPointerException.**

When a streaming request sets a manual shards map, `TupleStream.getShards` returns the map entry for the collection ([merge base, lines 219-225](https://github.com/nick-boss-tech/solr/blob/14c7aac0d151402b00259e2fb9bf5eed7049ec5d/solr/solrj-streaming/src/java/org/apache/solr/client/solrj/io/stream/TupleStream.java#L219-L225)). For a collection the map does not name, that entry is null. Filtering by core also removes entries from the list the caller passed in.

## What this change does

**The lookup returns an empty list for a missing entry, and the shard-based streams report it with a clear message.**

- `getShards` returns an empty list for a missing entry. It copies the configured list before filtering by core, so the caller's list is left alone ([lines 221-230](https://github.com/nick-boss-tech/solr/blob/10991af9bdac7ec464ac615de98e39d17b384d69/solr/solrj-streaming/src/java/org/apache/solr/client/solrj/io/stream/TupleStream.java#L221-L230)).
- `SqlStream` and `ParallelStream` throw `No shards available for collection <name>` when the list is empty ([SqlStream.java](https://github.com/nick-boss-tech/solr/blob/10991af9bdac7ec464ac615de98e39d17b384d69/solr/solrj-streaming/src/java/org/apache/solr/client/solrj/io/stream/SqlStream.java#L195-L197), [ParallelStream.java](https://github.com/nick-boss-tech/solr/blob/10991af9bdac7ec464ac615de98e39d17b384d69/solr/solrj-streaming/src/java/org/apache/solr/client/solrj/io/stream/ParallelStream.java#L293-L295)).
- Other callers also receive an empty list. `CloudSolrStream` now throws `No shards available` instead of a NullPointerException. `DeepRandomStream` now divides by zero and throws an `ArithmeticException` instead of a NullPointerException. `SignificantTermsStream` now sends no shard requests instead of failing.

## Proof

**Three new tests fail on the base code and pass with this change.**

- On the base code, `testTupleStreamGetShardsWithMissingManualShardMapping` and `testCloudStreamMissingManualShardMappingFailsClearly` fail with a NullPointerException. `testTupleStreamGetShardsLocalFilterDoesNotMutateContextShards` fails because the caller's list changes. Run 37177771725.
- With this change: `StreamingTest` 37 tests, 1 skipped, 0 failures; verified 2026-10-03 at `10991af9bda` (run 37177770661).

## Limits

**The ticket's own scenario does not fail on current main, so this change does not fix it.**

- In a run on current main (2026-10-04), a two-shard collection whose second shard lost its only replica returned the live shard's 20 documents with no exception. The result was the same with this change. The new tests use a manual shards map, not the ticket's crash.
- With every slice dead, `SqlStream` on current main fails with an `IOException` wrapping an `IndexOutOfBoundsException`. With this change it fails with the clear message.
