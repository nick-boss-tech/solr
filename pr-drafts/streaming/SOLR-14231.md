## What happens today

**With one node, or with no nodes, scoreNodes sends its /terms request with no field and no collection.**

scoreNodes reads the field and the collection only from the second node on ([ScoreNodesStream.java L214-L218, base](https://github.com/nick-boss-tech/solr/blob/b5c71bc5573c4e31b4cee5a7965d73587fc0ae58/solr/solrj-streaming/src/java/org/apache/solr/client/solrj/io/stream/ScoreNodesStream.java#L214-L218)). With one node, or with none, neither value is set. The request then goes out with a null collection ([L233, base](https://github.com/nick-boss-tech/solr/blob/b5c71bc5573c4e31b4cee5a7965d73587fc0ae58/solr/solrj-streaming/src/java/org/apache/solr/client/solrj/io/stream/ScoreNodesStream.java#L233)). Current main has the same code.

## What this change does

**scoreNodes now sets the field and collection from every node, returns no tuples when there are no nodes, and sends its /terms request as a POST.**

The loop sets both values for every node ([ScoreNodesStream.java L218-L219](https://github.com/nick-boss-tech/solr/blob/2f73d00a3996da1623156ccef649b59be0b59d45/solr/solrj-streaming/src/java/org/apache/solr/client/solrj/io/stream/ScoreNodesStream.java#L218-L219)). With no nodes, the function returns before it builds the request ([L223-L226](https://github.com/nick-boss-tech/solr/blob/2f73d00a3996da1623156ccef649b59be0b59d45/solr/solrj-streaming/src/java/org/apache/solr/client/solrj/io/stream/ScoreNodesStream.java#L223-L226)). The request is now a POST, not a GET, so a long node list goes in the request body, not the URL ([L235-L237](https://github.com/nick-boss-tech/solr/blob/2f73d00a3996da1623156ccef649b59be0b59d45/solr/solrj-streaming/src/java/org/apache/solr/client/solrj/io/stream/ScoreNodesStream.java#L235-L237)).

Behavior changes: with no nodes, the stream returns no tuples and sends no /terms request. With one or more nodes, the request is a POST. With two or more nodes, the result is unchanged, because the field and collection still come from the last node.

## Limits

**Not covered: scoreNodes fed by a nested gather over one indexed document.**

In that setup the nested gather returns no tuples on its own, before scoreNodes runs. That gather code is outside this change, so this change does not test or claim the case. The single-node case is covered by the two tests above.
