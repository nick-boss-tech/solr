## What happens today

**A blended suggester with no weight field does not sort by match position, and the ref guide did not explain why.**

The reporter configured `BlendedInfixLookupFactory` over `DocumentDictionaryFactory` with no `weightField`. For the query `blue` they expected `blue, blue whale, blue water, sky blue`. They got `sky blue, blue whale, blue water, blue` ([JIRA](https://issues.apache.org/jira/browse/SOLR-11844)). The section described the blend only as scoring higher when a hit is closer to the start of the suggestion ([base section](https://github.com/nick-boss-tech/solr/blob/cabedd1d968059215188f4e7563fb303241899ed/solr/solr-ref-guide/modules/query-guide/pages/suggester.adoc#L399-L400)). It did not mention weights.

## What this change does

**The ref guide now says what the blend does when a dictionary supplies no weight.**

- The blended score is the weight times a coefficient for the position of the first match. With no `weightField`, the dictionary gives each suggestion a weight of `0`. A weight of `0` counts as `1` in the blend. Suggestions with equal weights still follow match position ([section](https://github.com/nick-boss-tech/solr/blob/cbd08c20e9a4594ad05073e2ee2acbed53c4038d/solr/solr-ref-guide/modules/query-guide/pages/suggester.adoc#L402-L406)).
- Docs only. No code or default changes.

## Proof

**Docs only, with no test. The blend rules were checked in Lucene's bytecode.**

- There is no test and no failing-before run, because this is a docs change.
- The pinned Lucene 10.4.0 `lucene-suggest` jar was read with `javap -c -p`. In `BlendedInfixSuggester`, a weight of 0 is promoted to 1, a weight with absolute value under 10 is multiplied by 10, and the result is then multiplied by the position coefficient. The formula is weight times coefficient. The blend rules were checked against Lucene 10.4.0 and Lucene 9.12.3 bytecode; in both, a weight of 0 counts as 1, a weight with absolute value under 10 is multiplied by 10, and the result is multiplied by the position coefficient.
- `DocumentDictionary` returns weight 0 when no `weightField` is set, on every path without a stored value.
- Checked 2026-10-09.

## Limits

**The text describes the blend. It does not explain the order the reporter saw.**

- The reporter's order does not follow match position, and this text says equal weights still do. The text does not account for the difference.
- The reporter ran Solr 6.5. The Lucene check is against 10.4.0 and 9.12.3.
- The check read bytecode, not Lucene source. No sources jar was available locally.
