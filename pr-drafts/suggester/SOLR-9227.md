## What happens today

**A failed store logs one ERROR, and the message names no suggester.**

When a suggester has a `storeDir`, `SolrSuggester.build` stores the lookup after building it. If `lookup.store` returns false, the base code logs `Store Lookup build failed` at ERROR ([base code](https://github.com/nick-boss-tech/solr/blob/97d973814336101e12475558d7419321c743de79/solr/core/src/java/org/apache/solr/spelling/suggest/SolrSuggester.java#L185-L186)). A lookup that persists its own data can return false here, so the ERROR reads like a build failure. The ticket asks for the suggester identity and the cause to be reported.

## What this change does

**A store failure now names the suggester and the path. A false store return logs a WARN instead of an ERROR.**

- An `IOException` from the store call is rethrown with the suggester name and the absolute store path. The original exception is the cause ([SolrSuggester.java#L186-L191](https://github.com/nick-boss-tech/solr/blob/3c23fc5cfa6cba5d6f932cae1806c4f44fbacba4/solr/core/src/java/org/apache/solr/spelling/suggest/SolrSuggester.java#L186-L191)).
- A false return logs a WARN with the suggester name, the lookup class, and the target path. It says the lookup may persist elsewhere ([#L192-L197](https://github.com/nick-boss-tech/solr/blob/3c23fc5cfa6cba5d6f932cae1806c4f44fbacba4/solr/core/src/java/org/apache/solr/spelling/suggest/SolrSuggester.java#L192-L197)).
- The `lookup.build` call is unchanged, so build failures still propagate ([#L174-L182](https://github.com/nick-boss-tech/solr/blob/3c23fc5cfa6cba5d6f932cae1806c4f44fbacba4/solr/core/src/java/org/apache/solr/spelling/suggest/SolrSuggester.java#L174-L182)).

## Limits

**Only the store step of `build` is covered. The wider logging audit is not attempted.**

- The `IOException` branch is implemented, but no test covers it.
- The WARN text is new. Anything that alerts on the old ERROR text sees a level change for the infix family.
- A follow-up for the wider logging audit can be opened as its own ticket and PR, on request.
- The store file's absolute path appears in log lines, as it already did for successful stores, and in the error returned to a build request that fails while storing (suggest.build or buildAll). Suggest queries that do not request a build never see it. ([base INFO line](https://github.com/nick-boss-tech/solr/blob/97d973814336101e12475558d7419321c743de79/solr/core/src/java/org/apache/solr/spelling/suggest/SolrSuggester.java#L189); [build call](https://github.com/nick-boss-tech/solr/blob/3c23fc5cfa6cba5d6f932cae1806c4f44fbacba4/solr/core/src/java/org/apache/solr/handler/component/SuggestComponent.java#L196-L199).)
