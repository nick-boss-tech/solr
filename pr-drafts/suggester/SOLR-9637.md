## What happens today

**A distributed suggest request can return the same text twice.**

Each shard returns its own top suggestions, and `SuggestComponent` merges them into one list. The base merge keeps every shard's copy, so a text found on two shards appears twice ([base merge](https://github.com/nick-boss-tech/solr/blob/dd6c82924fff6b8f7cedaf020494c2f06ab502a2/solr/core/src/java/org/apache/solr/handler/component/SuggestComponent.java#L368-L377)). The list is cut to `suggest.count` after that, so the copies also use up slots. The reporter ran two shards on Solr 4.9.1 and got `test` twice in each dictionary's list ([SOLR-9637](https://issues.apache.org/jira/browse/SOLR-9637)).

## What this change does

**Suggestions with the same text become one entry, and their weights add up.**

- The merge groups the shard suggestions by their text and sums the weights. It sorts and cuts the merged list afterwards ([merge](https://github.com/nick-boss-tech/solr/blob/c50fa4ffd932ede86c36b0748ee6aabe34d30e0a/solr/core/src/java/org/apache/solr/handler/component/SuggestComponent.java#L369-L383)).
- A text found on several shards ranks by its total weight, so it can rank above a text that one shard scores higher.
- The merged entry keeps the highlight key, payload, and contexts of the first copy ([sumWeights](https://github.com/nick-boss-tech/solr/blob/c50fa4ffd932ede86c36b0748ee6aabe34d30e0a/solr/core/src/java/org/apache/solr/handler/component/SuggestComponent.java#L389-L397)).

## Limits

**The sum counts only shards that kept the text in their own top list. The rebased PR is not yet gated.**

- Each shard returns at most `count` results ([shard lookup](https://github.com/nick-boss-tech/solr/blob/c50fa4ffd932ede86c36b0748ee6aabe34d30e0a/solr/core/src/java/org/apache/solr/handler/component/SuggestComponent.java#L274-L287)). A shard's copy counts only if it made that shard's top list, so the sum can fall short. SOLR-17393 has the same per-shard cut.
- Copies with different payloads keep the first copy's payload. This is not tested.
- The new tests call `merge` directly. No cluster test covers a text found on real shards, and the reporter's setup was not rerun.
- This branch is stacked on SOLR-17393 at [dd6c82924fff](https://github.com/nick-boss-tech/solr/commit/dd6c82924fff6b8f7cedaf020494c2f06ab502a2). That branch has since gained two packaging commits. This PR opens after SOLR-17393 lands, rebased onto the landed tip. The proof ran on the stacked base, not on the rebased tree.
