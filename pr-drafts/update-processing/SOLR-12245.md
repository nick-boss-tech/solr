## What happens today

**A failed distributed update reports its message only. It does not say which replica it was sent to.**

When a distributed update fails asynchronously, the error reads "Async exception during distributed update:" followed by the message.

## What this change does

**The error names the replica, collection and shard. A remote error does not repeat the host.**

- When the request has a target node, the error adds "(while sending to ...)". It holds the replica URL, or the core name for a remote error (next point), then `collection=` and `shard=` when they are known ([describe](https://github.com/nick-boss-tech/solr/blob/f325d5d0576e582d4488570eabdeabc7410a8a0f/solr/core/src/java/org/apache/solr/update/processor/DistributedUpdateProcessor.java#L1243-L1269)).
- When the server's own message already contains its base URL, the suffix uses the core name, so the host appears once ([host check](https://github.com/nick-boss-tech/solr/blob/f325d5d0576e582d4488570eabdeabc7410a8a0f/solr/core/src/java/org/apache/solr/update/processor/DistributedUpdateProcessor.java#L1254-L1257)).
- The server's own message is kept as it was.
- The single-error and multi-error forms both use this text ([build](https://github.com/nick-boss-tech/solr/blob/f325d5d0576e582d4488570eabdeabc7410a8a0f/solr/core/src/java/org/apache/solr/update/processor/DistributedUpdateProcessor.java#L1299-L1307)).
- Behavior change: asynchronous distributed update errors with a target node get a longer message. Code that matches the old text exactly will see a different message.

## Proof

**The host-once test fails before this fix and passes with it.**

- The fail-before test is [`testDistribErrorMessageNamesTheHostOnce`](https://github.com/nick-boss-tech/solr/blob/f325d5d0576e582d4488570eabdeabc7410a8a0f/solr/core/src/test/org/apache/solr/update/processor/DistributedUpdateProcessorTest.java#L215-L240). The fix commit `f325d5d0576e` added it. Run with the head test class against the pre-fix production code at `4a93167458b5`, it fails. There the full URL is always added, so the host appears twice when the server's message already names it.
- The other new check is [`testDistribErrorMessageNamesTheTargetReplica`](https://github.com/nick-boss-tech/solr/blob/f325d5d0576e582d4488570eabdeabc7410a8a0f/solr/core/src/test/org/apache/solr/update/processor/DistributedUpdateProcessorTest.java#L155-L212). It checks that the replica URL, collection and shard appear in the error. It is not the fail-before test.
- `DistributedUpdateProcessorTest` 6 of 6 pass with this change.
- Verified 2026-10-09 at this head.

## A choice to check

**The replica name goes in the error text. The other route keeps it in the logs only.**

The other route keeps the error text as it was and writes the replica detail to the logs. A client would then see no replica name in the error. This branch puts the name in the error itself.

Was putting the replica in the error text the right call, or should it go to the logs only?

## Limits

**The MDC ask and null-guard coverage are not in this change.**

- The ticket's MDC ask is not addressed by this change. A follow-up submission is planned for it.
- The `error.req == null` guard in `describe()` is covered by `testStatusCodeOnDistribError_NotSolrException`. The other null checks in `describe()` (node, message, base URL, core name, collection and shard) are not covered by a test.
- The tests build the error by hand. They do not run a failing distributed update.
- An error with no target node keeps the old text. No replica is named for it.
