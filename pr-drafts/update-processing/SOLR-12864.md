## What happens today

**No test runs echo and mapUniqueKeyOnly together on the JSON update path.**

The ticket reports an empty `text` list in the echoed document when `mapUniqueKeyOnly` is set. Reading the code on base, the echoed copy keeps the collected values, so this symptom does not reproduce there ([getDocMap](https://github.com/nick-boss-tech/solr/blob/b9c6c1e71ffa9a7f68d7ac126206cd2f14af4aaa/solr/core/src/java/org/apache/solr/handler/loader/JsonLoader.java#L295-L326)). The existing tests cover echo alone (`testEchoDocs`) and `mapUniqueKeyOnly` alone (`testSrcAndUniqueDocs`). The combination has no test.

## What this change does

**Adds one test method for the SOLR-16811 path. It is coverage, not a bug fix.**

- Adds [`testEchoDocsWithMapUniqueKeyOnly`](https://github.com/nick-boss-tech/solr/blob/b9c6c1e71ffa9a7f68d7ac126206cd2f14af4aaa/solr/core/src/test/org/apache/solr/handler/JsonLoaderTest.java#L401-L436). It sends `echo=true`, `mapUniqueKeyOnly=true` and `df=_catch_all` to the `/update/json/docs` path, with or without `srcField`. It checks the echoed documents.
- The path it covers was changed by [SOLR-16811](https://issues.apache.org/jira/browse/SOLR-16811), which is already in base.
- The test guards one regression. If the echoed copy ever pointed into the reused record map, the `df` values would go empty again.
- The only file that differs from base is `JsonLoaderTest.java`.
