## What happens today

**`testDateMathInStart` does not run in normal CI. When it runs, it waits on the test's own ZooKeeper watcher.**

The method sits in `TimeRoutedAliasUpdateProcessorTest`. That class has a class-level `@AwaitsFix` for SOLR-13059 ([annotation](https://github.com/nick-boss-tech/solr/blob/cc155cf68e1d8e79f1bcecd2e4c25ada864d8f53/solr/core/src/test/org/apache/solr/update/processor/TimeRoutedAliasUpdateProcessorTest.java#L69-L70)), so its methods are skipped in normal mode. The method also had its own `@AwaitsFix` for SOLR-13943.

After the add, the test waits on a latch that counts down when its own watcher on `/aliases.json` fires. Then it reads the start value from the cluster state provider.

## What this change does

**The test moves to its own class with no skip annotation. Its second wait now polls the provider.**

- The method moves to `TimeRoutedAliasDateMathInStartTest`, a new class. It has the same base class and no `@AwaitsFix` ([class](https://github.com/nick-boss-tech/solr/blob/cc155cf68e1d8e79f1bcecd2e4c25ada864d8f53/solr/core/src/test/org/apache/solr/update/processor/TimeRoutedAliasDateMathInStartTest.java#L51)). The test is at [L84-L160](https://github.com/nick-boss-tech/solr/blob/cc155cf68e1d8e79f1bcecd2e4c25ada864d8f53/solr/core/src/test/org/apache/solr/update/processor/TimeRoutedAliasDateMathInStartTest.java#L84-L160).
- The wait after the add now polls the cluster state provider every 100 ms, for up to 30 seconds. On an HTTP-based provider, it first asks the provider to refresh the alias. The test passes once the start value parses as an instant. It fails at the timeout ([poll loop](https://github.com/nick-boss-tech/solr/blob/cc155cf68e1d8e79f1bcecd2e4c25ada864d8f53/solr/core/src/test/org/apache/solr/update/processor/TimeRoutedAliasDateMathInStartTest.java#L135-L159)). The old wait had no time limit.
- The first wait, before the add, still uses the test's own watcher ([L109](https://github.com/nick-boss-tech/solr/blob/cc155cf68e1d8e79f1bcecd2e4c25ada864d8f53/solr/core/src/test/org/apache/solr/update/processor/TimeRoutedAliasDateMathInStartTest.java#L109)). This change leaves it as it was.
- The new comment gives the reason. The watcher can fire before the provider has refreshed its aliases ([comment](https://github.com/nick-boss-tech/solr/blob/cc155cf68e1d8e79f1bcecd2e4c25ada864d8f53/solr/core/src/test/org/apache/solr/update/processor/TimeRoutedAliasDateMathInStartTest.java#L132-L134)).
- The change touches tests only. No production code changes.
