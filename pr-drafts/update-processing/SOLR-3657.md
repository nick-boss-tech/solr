## What happens today

**A failed copyField value is reported with the source field only.**

When a value cannot be indexed into a copyField destination, the error reads `Error adding field '<source>'='<value>' msg=...`. The message names the source field and ends with the parse error. It does not name the destination that failed. For example, a non-numeric `id` value copied into a numeric destination in the test schema gives this kind of error. The wrapper that builds the message is [DocumentBuilder.java#L286-L297](https://github.com/nick-boss-tech/solr/blob/14edaca577c0c1c38dc50b1ffa632c31fd1613de/solr/core/src/java/org/apache/solr/update/DocumentBuilder.java#L286-L297).

## What this change does

**Copy-field errors now name the destination field. Error text changes for clients.**

- Each copyField indexing call is wrapped. A failure is rethrown with the prefix `copyField destination '<field>': ` followed by the original message ([DocumentBuilder.java#L390-L406](https://github.com/nick-boss-tech/solr/blob/14edaca577c0c1c38dc50b1ffa632c31fd1613de/solr/core/src/java/org/apache/solr/update/DocumentBuilder.java#L390-L406)).
- The status code does not change. A `SolrException` keeps its code. Any other runtime exception becomes `BAD_REQUEST`, as before.
- The outer message still names the source field. The destination text appears inside its `msg=` part.
- Any client that matches the old message text will see a different message.

- The new wrapper carries the code, message and cause only. Other `SolrException` fields are not copied, as the existing outer wrapper also does. This is left as is. I can open a follow-up on request.
