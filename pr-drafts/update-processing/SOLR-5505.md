## What happens today

**With `infoStream` on, IndexWriter log lines do not name their core.**

On main, setting `<infoStream>true</infoStream>` creates a `LoggingInfoStream` with no core name ([SolrIndexConfig.java](https://github.com/nick-boss-tech/solr/blob/44c444aa5cd38618424c504fff307ead5cf466cf/solr/core/src/java/org/apache/solr/update/SolrIndexConfig.java#L185-L188)). Its lines carry only the component and the thread name ([LoggingInfoStream.java](https://github.com/nick-boss-tech/solr/blob/44c444aa5cd38618424c504fff307ead5cf466cf/solr/core/src/java/org/apache/solr/update/LoggingInfoStream.java#L46)).

## What this change does

**Each log line gets the core name as a `[core]` segment.**

When the configured stream is a `LoggingInfoStream`, each IndexWriter gets its own copy that knows the core name ([SolrIndexConfig.java](https://github.com/nick-boss-tech/solr/blob/44c444aa5cd38618424c504fff307ead5cf466cf/solr/core/src/java/org/apache/solr/update/SolrIndexConfig.java#L261-L265)). A line now reads `[core][component][thread]: message` ([LoggingInfoStream.java](https://github.com/nick-boss-tech/solr/blob/44c444aa5cd38618424c504fff307ead5cf466cf/solr/core/src/java/org/apache/solr/update/LoggingInfoStream.java#L49)). Any other `InfoStream` passes through unchanged.

API addition: the public constructor `LoggingInfoStream(String coreName)` ([LoggingInfoStream.java](https://github.com/nick-boss-tech/solr/blob/44c444aa5cd38618424c504fff307ead5cf466cf/solr/core/src/java/org/apache/solr/update/LoggingInfoStream.java#L38-L40)). The no-argument constructor stays.

Behavior change: with infoStream on, every line gains the `[core]` segment. Log parsers that match the old format will see the change. No setting keeps the old format.

## Proof

**`TestInfoStreamLogging.testMessagesNameTheCore` checks that a logged line names the core.**

The test is [TestInfoStreamLogging.java](https://github.com/nick-boss-tech/solr/blob/44c444aa5cd38618424c504fff307ead5cf466cf/solr/core/src/test/org/apache/solr/core/TestInfoStreamLogging.java#L40-L47).

- On base production code, TestInfoStreamLogging runs 2 tests with exactly 1 failure (testMessagesNameTheCore). The base line has no core name, so the `[core][IW]` check is the one that fails.
- Verified 2026-10-07 at head `44c444aa5cd3`: TestInfoStreamLogging 2/2, neighbor TestSolrIndexConfig 2/2. The module checks pass.

## A choice to check

**The core name is always on. The other route makes it opt-in.**

The other route adds a setting that turns the `[core]` segment on. The old format stays the default, and that change's changelog type would be `added`. As implemented, there is no setting and the changelog type is `changed`.

Was an always-on core name the right call, or should an opt-in setting keep the old format by default?

## Limits

**Two parts are not covered by a test.**

- The reload path is checked by reading only. Each reload builds a new IndexWriterConfig, so the core name follows the core.
- The new format is not tested against any log parser.
