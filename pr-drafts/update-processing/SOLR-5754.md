## What happens today

**The retry pass reads the errors, then clears the list in a second call. An error added in between can be cleared without a retry.**

Before this change, the retry pass copied the live error list and cleared it later in the same method. An error added between those two steps was cleared unseen. On the paths read, that window does not open, so this change is hardening, not a fix for a reproduced bug.

## What this change does

**Errors are read as a snapshot, and the retry pass takes them with one atomic drain.**

- `getErrors()` returns a copy taken under the list's lock ([StreamingSolrClients.java](https://github.com/nick-boss-tech/solr/blob/46b919e2d4e8bc287ac913edb789c21509e1b215/solr/core/src/java/org/apache/solr/update/StreamingSolrClients.java#L61-L66)). This is a public behavior change. A caller now gets a snapshot, not the live list.
- `drainErrors()` copies and clears the list in one step under the same lock ([StreamingSolrClients.java](https://github.com/nick-boss-tech/solr/blob/46b919e2d4e8bc287ac913edb789c21509e1b215/solr/core/src/java/org/apache/solr/update/StreamingSolrClients.java#L68-L75)).
- The retry pass calls `drainErrors()` ([SolrCmdDistributor.java](https://github.com/nick-boss-tech/solr/blob/46b919e2d4e8bc287ac913edb789c21509e1b215/solr/core/src/java/org/apache/solr/update/SolrCmdDistributor.java#L107)). The later `clearErrors()` call is removed.
- The `errors` field is package-private and final, so the tests can seed it ([StreamingSolrClients.java](https://github.com/nick-boss-tech/solr/blob/46b919e2d4e8bc287ac913edb789c21509e1b215/solr/core/src/java/org/apache/solr/update/StreamingSolrClients.java#L51-L52)).

## Limits

**This is hardening. The race is not reproduced, and the tests are single-threaded.**

- On the paths read, no runner thread adds an error during the retry window. This was checked by reading, not by a run.
- The tests check snapshot and drain behavior. They do not exercise the concurrent window. A follow-up submission is planned to test that window.
- `clearErrors()` stays public and has no caller in main code. This change does not remove it.
- SOLR-5939 changes the same two files. The textual merge is clean, and the proof above covers the merged tree.
