## What happens today

**Bad-document errors name the field but not the core.**

An update with a document that has an unknown field returns a 400 error. The text is built in `DocumentBuilder` from the document id and the field name ([DocumentBuilder.java](https://github.com/nick-boss-tech/solr/blob/c4c57ef7bcbde765807bf02f9e3a6db605868b7e/solr/core/src/java/org/apache/solr/update/DocumentBuilder.java#L301-L305)).

## What this change does

**The error text gets a `core <name>:` prefix.**

Every path that builds a Lucene document from an add command now goes through a wrapper, `toLuceneDocument` ([AddUpdateCommand.java](https://github.com/nick-boss-tech/solr/blob/c4c57ef7bcbde765807bf02f9e3a6db605868b7e/solr/core/src/java/org/apache/solr/update/AddUpdateCommand.java#L235-L248)). The wrapper covers in-place updates, single documents, and nested documents ([line 103](https://github.com/nick-boss-tech/solr/blob/c4c57ef7bcbde765807bf02f9e3a6db605868b7e/solr/core/src/java/org/apache/solr/update/AddUpdateCommand.java#L103), [line 212](https://github.com/nick-boss-tech/solr/blob/c4c57ef7bcbde765807bf02f9e3a6db605868b7e/solr/core/src/java/org/apache/solr/update/AddUpdateCommand.java#L212), [line 231](https://github.com/nick-boss-tech/solr/blob/c4c57ef7bcbde765807bf02f9e3a6db605868b7e/solr/core/src/java/org/apache/solr/update/AddUpdateCommand.java#L231)). For a 400 error from `DocumentBuilder`, with a core on the request, the wrapper rethrows the error with `core <name>: ` added before the original text. The error code stays 400. Other errors, and requests with no core, keep their current text.

Behavior change: the text no longer starts with `ERROR:`. Anything that matches the start of the text will see a change. The tolerant update processor records these messages in its response, so clients see the new text there too.

## Proof

**`DocumentBuilderTest.testAddUpdateCommandErrorNamesCore` checks that the error names the core.**

The test ([DocumentBuilderTest.java](https://github.com/nick-boss-tech/solr/blob/c4c57ef7bcbde765807bf02f9e3a6db605868b7e/solr/core/src/test/org/apache/solr/update/DocumentBuilderTest.java#L78-L92)) sends a document with an unknown field through `AddUpdateCommand.makeLuceneDocs()`. It checks the 400 status, the core name, and the field name. On the base code the message has no core name, so the core check fails there. The field check passes on base, because the base text already names the field. Both points were checked by reading the code. No base run is recorded here.

With this change, the local gate's second run is recorded as covering this exact tree. No test counts are given here. A GitHub Actions run on the CI branch finished with success (run 37635905367). That CI commit adds one file on top of this head.
