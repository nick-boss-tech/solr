## What happens today

**Bad-document errors name the field but not the core.**

An update with a document that has an unknown field returns a 400 error. The text is built in `DocumentBuilder` from the document id and the field name ([DocumentBuilder.java](https://github.com/nick-boss-tech/solr/blob/c4c57ef7bcbde765807bf02f9e3a6db605868b7e/solr/core/src/java/org/apache/solr/update/DocumentBuilder.java#L301-L305)).

## What this change does

**The error text gets a `core <name>:` prefix.**

The add paths in `AddUpdateCommand` now go through a wrapper, `toLuceneDocument` ([AddUpdateCommand.java](https://github.com/nick-boss-tech/solr/blob/c4c57ef7bcbde765807bf02f9e3a6db605868b7e/solr/core/src/java/org/apache/solr/update/AddUpdateCommand.java#L235-L248)). The wrapper covers in-place updates, single documents, and nested documents ([line 103](https://github.com/nick-boss-tech/solr/blob/c4c57ef7bcbde765807bf02f9e3a6db605868b7e/solr/core/src/java/org/apache/solr/update/AddUpdateCommand.java#L103), [line 212](https://github.com/nick-boss-tech/solr/blob/c4c57ef7bcbde765807bf02f9e3a6db605868b7e/solr/core/src/java/org/apache/solr/update/AddUpdateCommand.java#L212), [line 231](https://github.com/nick-boss-tech/solr/blob/c4c57ef7bcbde765807bf02f9e3a6db605868b7e/solr/core/src/java/org/apache/solr/update/AddUpdateCommand.java#L231)). For a 400 error from `DocumentBuilder`, with a core on the request, the wrapper rethrows the error with `core <name>: ` added before the original text. The error code stays 400. Other errors, and requests with no core, keep their current text.

Behavior change: the text no longer starts with `ERROR:`. Anything that matches the start of the text will see a change. The tolerant update processor records these messages in its response, so clients see the new text there too.

## Proof

**`DocumentBuilderTest.testAddUpdateCommandErrorNamesCore` checks that the error names the core.**

The test ([DocumentBuilderTest.java](https://github.com/nick-boss-tech/solr/blob/c4c57ef7bcbde765807bf02f9e3a6db605868b7e/solr/core/src/test/org/apache/solr/update/DocumentBuilderTest.java#L78-L92)) sends a document with an unknown field through `AddUpdateCommand.makeLuceneDocs()`. It checks the 400 status, the core name, and the field name. On base production, `DocumentBuilderTest` runs 17 tests with exactly one failure: `testAddUpdateCommandErrorNamesCore`. The base message has no core name, which is what this test checks.

With this change, `DocumentBuilderTest` passes 17 of 17 (verified 2026-10-07 at this head).

## Limits

**The classification processor keeps the old error text, and three existing test classes were checked by reading, not run.**

- The classification processor calls `DocumentBuilder` directly, outside the wrapper ([ClassificationUpdateProcessor.java](https://github.com/nick-boss-tech/solr/blob/c4c57ef7bcbde765807bf02f9e3a6db605868b7e/solr/core/src/java/org/apache/solr/update/processor/ClassificationUpdateProcessor.java#L128)). A follow-up submission is planned to route it through the wrapper.
- These are `TolerantUpdateProcessorTest`, `TestManagedSchema`, and `TestSolrJErrorHandling`. They match the message text with `contains`, so the new prefix should not break them. None of them was run for this change. A follow-up submission is planned to run them.
- `DocumentBuilderTest` is not in that list. It passed 17 of 17 at this head on 2026-10-07.
