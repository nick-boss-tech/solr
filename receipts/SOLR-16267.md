## def() behavior check against Lucene 9.12.3 and 10.4.0 (2026-10-12)

Record job gates/SOLR-16267-def-check.md, run by vm1. Question: does Lucene's `def()` (org.apache.lucene.queries.function.valuesource.DefFunction) decide from the wrapped ValueSource's `exists()`, so that a wrapped math function whose `exists()` now reports false for a document makes `def()` return its default for that document? The gate at the head ran against Lucene 10.4.0; branch_9x pins 9.12.3, so both versions were read.

Artifacts read (bytecode, javap -c on the extracted classes; no source jars ship with either artifact):

- Lucene 9.12.3: lucene-queries-9.12.3.jar (from ~/workspace/tools/lucene-9.12.3/ on vm1), classes DefFunction and its anonymous Values class DefFunction$1.
- Lucene 10.4.0: lucene-queries-10.4.0.jar (from the Gradle cache, ~/.gradle/caches/modules-2/files-2.1/org.apache.lucene/lucene-queries/10.4.0/), same two classes.

Findings, the same in both versions:

- Every typed value accessor of DefFunction$1 (byteVal, shortVal, floatVal, intVal, longVal, doubleVal, strVal, boolVal, bytesVal, objectVal) first calls a private selector, `get(doc)`, and reads the value from the FunctionValues that selector returns.
- The selector is the deciding code. Its decompiled shape, identical in 9.12.3 and 10.4.0:

```java
private FunctionValues get(int doc) throws IOException {
  for (int i = 0; i < upto; i++) {           // upto = number of sources - 1
    FunctionValues vals = valsArr[i];
    if (vals.exists(doc)) return vals;       // FunctionValues.exists(I)Z, bytecode offset 19
  }
  return valsArr[upto];                      // the last source, used unconditionally: the default
}
```

- So DefFunction's value path does consult each wrapped source's `exists()`, in argument order, and the default (the last argument) is used exactly when no earlier source reports `exists()` true for the document. DefFunction$1's own `exists(doc)` likewise returns true when any source's `exists(doc)` does. The only bytecode difference between the two versions is constructor plumbing in the anonymous class; the selector and accessors are instruction-for-instruction the same logic.
- No scratch probe was run: the bytecode settles the 9.12.3 behavior unambiguously, so the reading needed no probe under the job's terms.

Verdict: the draft's claim stands for both versions. Because DefFunction consults the wrapped source's `exists()` on Lucene 9.12.3 exactly as it does on 10.4.0, the answer that reaches `exists()` also reaches `def()` on branch_9x's pinned Lucene, and the draft sentence "The same answer reaches `exists()` and `def()`, as the changelog says" does not need narrowing for 9.x.
