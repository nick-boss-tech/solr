- Root cause (trace): `FacetProcessor.handleFilterExclusions` recomputes a facet's base from the root query and filters minus the excluded tags. It then intersects every ancestor bucket filter with the root set. It never applies an ancestor's block-join domain, and it applies child-level bucket filters before the parent's block join. For a nested facet under `blockChildren` with its own `excludeTags`, the base therefore became parent-level books instead of the child domain, and the nested `stars` buckets came back empty.
- Fix: replay the context chain from the root. For each ancestor, intersect its bucket filter, then apply its block-join domain (`toChildren` or `toParents`, using the parent's filter as accept docs). The current context's own domain is applied later, as before. Parsing of the parent query moved into a shared helper `blockJoinParents`, used by both paths.
- Limit: the replay covers ancestor block-join domains. It does not replay ancestor join-field, graph or query domains, and it still does not carry ancestor exclusions (the existing `TODO: we lose parent exclusions`). Exclusion composition with block-join domains beyond this is the open Choice for the PR draft, not settled here.
