## What was wrong (round 1) and what changed (round 2)

1. `SolrConfigHandler.getJerseyResources()` listed only `GetConfig`. `ModifyConfigComponentAPI` was never registered with Jersey, so every JAX-RS write route was missing. Fixed by registering it.
2. The root `POST /config` (command bundle) had no route after the migration. Restored in `ModifyConfigApi` as `runConfigCommands`.
3. The root route used Jackson to read the body, which rejects the single-quoted and unquoted v1 command syntax the existing tests use. It now parses the raw body with `CommandOperation.parse`, as the v1 handler does.
4. `POST /config/params` (paramset bundles) had no route. Added `runParamSetCommands`, which runs with the paramset flag.
5. Test: added `testUpsertRequestHandler` (upsert on new and existing handlers, and the unchanged create and update errors).
6. Test helper `runConfigCommandExpectFailure` no longer requires a top-level `errorMessages` field. The V2 error response has the message under `error.details[0].errorMessages`, which the helper still checks.

## Compatibility note for the owner

V2 config command errors no longer carry a top-level `errorMessages` field. They carry the messages under `error.details[].errorMessages`, which is the standard JAX-RS error shape. Base's V2 responses had both. Any client that reads the top-level field will see a change.
