## What happens today

The new UI has no Index & Query header. A user cannot pick a collection there, and cannot see the request handlers of the chosen collection. The ticket asks for both dropdowns, with their loading and selection state.

## What this change does

Adds the header and the state it needs. The request form, the response view and the request itself are not in this change.

- [`IndexQueryHeader`](https://github.com/nick-boss-tech/solr/blob/cf35ab0329c41cdef11429906d1e669d38b9f3a9/ui/shared/src/commonMain/kotlin/org/apache/solr/ui/views/indexquery/IndexQueryHeader.kt): a collection dropdown and a request handler dropdown. The closed handler field shows the selected endpoint with its class on the same line, the class in monospace. Each menu entry shows the endpoint and its class. A long class name is cut with an ellipsis. The handler field is 384 px wide and the collection field 256 px, as in the design. Both dropdowns are disabled while loading and when there is nothing to pick. Messages cover no collections and a collection with no handlers.
- [`IndexQueryStateHolder`](https://github.com/nick-boss-tech/solr/blob/cf35ab0329c41cdef11429906d1e669d38b9f3a9/ui/shared/src/commonMain/kotlin/org/apache/solr/ui/components/indexquery/viewmodel/IndexQueryStateHolder.kt): loads the collections and the handlers of the selected collection. It holds the selected collection and handler, and clears the handler when the collection changes.
- [`HttpIndexQueryRepository`](https://github.com/nick-boss-tech/solr/blob/cf35ab0329c41cdef11429906d1e669d38b9f3a9/ui/shared/src/commonMain/kotlin/org/apache/solr/ui/components/indexquery/data/HttpIndexQueryRepository.kt): `GET api/collections` and `GET api/collections/{collection}/config/requestHandler`.
- `RequestHandlerOption` moves to the domain package, and four strings are added.

## Scope of this change

**Summary: the header comes with the state it needs to meet the ticket's criteria.**

The ticket's criteria say that the collections are listed, that the handlers load for the selected collection, and that the selection is part of the state. Its "Additional Information" excludes only the form of a request handler. Three options fit the ticket:

1. The header component only. The criteria for loading and state would stay open, because the header takes its lists and selection as parameters and nothing supplies them.
2. The header with its loading and selection state (this change). It meets the criteria for collections, handlers and state, and it leaves out request execution.
3. The whole screen, including running a request and showing its response. That is the content, which the ticket excludes and which Christos Malliaridis asked to keep in a separate pull request.

This change takes option 2.
