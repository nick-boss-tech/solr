# SOLR-17850: Implement solr.SearchHandler UI form (new UI)

Draft PR description. Not opened as a GitHub PR. Partial: this is the request form component only.

## What

Adds `SearchHandlerForm`, a composable in `ui/shared` for a request to solr.SearchHandler, and the `SearchRequestForm` input model.

- Each field shows its abbreviation with the written-out name: q (Query), fq (Filter Query), fl (Fields), sort, rows, start.
- Array fields (q, fq, fl) start with one input. "Add" adds an input. "Remove" appears only on additional inputs.
- The q field must keep at least one input. Execute is disabled while every q input is blank.
- Defaults: rows 10, start 0, one empty input for each array field.
- Execute runs in normal mode or in debug mode. The form does not run the request; the caller receives the input and the mode through `onExecute`.
- Clear all resets the input to the defaults.
- The form scrolls vertically, since it is taller than a small window.

## Not in this change

- Running the request against Solr. The caller's `onExecute` does this later.
- The request preview and the response preview. The ticket excludes them.
- Hosting the form on the Index / Query screen. That screen has no content yet (see the SOLR-17849 draft).
