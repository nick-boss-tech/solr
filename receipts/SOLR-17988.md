Inheritance in fresh `bash --noprofile --norc` shells:

- Unexported include assignment: the child JVM has no value (`solr.ui.enabled=null`).
- Exported assignment: inherited (`solr.ui.enabled=false`).
- Explicit `-Dsolr.ui.enabled=false` with an unexported assignment: `false`.
- Explicit `-Dsolr.cloud.wait.for.zk.seconds=60` alone: `60`.

Finding for the PR owner, not a contradiction of the prose: an exported deprecated alias overrides an explicit `-D` for the new name. `SOLR_WAIT_FOR_ZK=45` with `-Dsolr.cloud.wait.for.zk.seconds=60` gives `45` and a warning. `EnvUtils` applies the deprecated mapping with `setProperty` after the explicit-property check. The upgrade note says to prefer the new export or `-D` in `SOLR_OPTS`, but does not say what happens when both are present. No docs change was made in this gate. Adding a sentence needs a new head and a new gate.

## Start script and module decision

Source-consumer checks: `source-consumer-checks.txt`.

- Release `bin/solr` lines 319 to 325, identical to the PR tree's `solr/bin/solr` lines 319 to 325: `--module=new-ui` is skipped when `SOLR_UI_ENABLED` or `SOLR_UI_EXPERIMENTAL_ENABLED` is `false`.
- `LoadAdminUiServlet` line 44 reads `solr.ui.enabled`. No Java code reads `solr.ui.experimental.enabled`.
- The release `bin/solr` has no reference to `SOLR_WAIT_FOR_ZK` or `SOLR_ADMIN_UI_DISABLED` (0 matches), so the start script does not translate them, as the upgrade note says.

Launcher runs against the release on port 18983 (`probe/launcher2.sh`, output `probe/launcher2/`). The java command line was read from `/proc/<pid>/cmdline` of the Solr process started by `bin/solr start`:

| Case | `--module=new-ui` in java command | `-Dsolr.ui.enabled` in java command | Classic UI `/solr/` HTTP |
| --- | --- | --- | --- |
| default | present | none | 200 |
| `SOLR_UI_ENABLED=false` | absent | none | 404 |
| `SOLR_UI_EXPERIMENTAL_ENABLED=false` | absent | none | 200 |
| `SOLR_OPTS="-Dsolr.ui.enabled=false"` | present | `-Dsolr.ui.enabled=false` | 404 |

The two disabled-UI start logs print `New Solr UI not enabled`. The 404 is the status code only. The saved body is not the servlet's message. Release `bin/solr stop` waited 180 seconds on the first case, so later cases used TERM and then KILL after 30 seconds. This is an environment observation and does not affect the documentation claims. `probe/launcher/` is the first launcher run. Its java-argument columns are empty because the match pattern was wrong. It is superseded by `probe/launcher2/`.
