Probe: the same as the paging probe above (2 shards, 2 replicas, 40 documents, `sort=_docid_ asc`, `rows=7`, pages at 0 to 35), in fresh clusters. Seed `6975C0FFEE6975`. Logs: `/workspace/gates/logs/vm4/solr-5135-paging-probe/clusters/` and `/pin/`.

- Replica docids: in all six clusters, both replicas of each shard return the same `_docid_` for every document (AGREE mismatches 0). Replicas that disagree are not the cause.
- Cross-shard order: with `_docid_` as the leading sort key, the comparator orders documents from different shards by the shard address string (`ShardFieldSortedHitQueue.lessThan`, the final tiebreak `-docA.shard.compareTo(docB.shard)`). The key is the shard's replica list (host, port and core name for each replica), in the order the request built it. The list is shuffled for each request, so its first replica decides the order. The ports are assigned at each cluster start.
- Interleaved: when the shard-1 and shard-2 replica addresses interleave as strings, the group order changes with which replica answers. Default routing picks replicas at random per request, so pages overlap and skip.
