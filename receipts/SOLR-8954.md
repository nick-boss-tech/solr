## Classification: the branch change causes the failure

The branch collects every id whose router returns a null target slice and sends those ids to all shards (RealTimeGetComponent, head lines 1061-1069 and 1091-1097). That is the intended fix for the implicit router, whose `getTargetSlice` returns null on a get with no `_route_` because the id carries no shard information at all. For `compositeId` with a router field the same null means something else: `CompositeIdRouter.getTargetSlice` returns null deliberately for a get or delete-by-id with no route when a route field is defined (its own comment states this), because the document was routed by the route field's value and a bare-id lookup cannot be routed. The existing test pins that contract: a real-time get with no `_route_` returns 0 documents, and with `_route_` it returns the document. The branch's fan-out applies to every router, so it overrides that contract and the get now finds the document. The branch's own changelog scopes the change to the implicit router, so the compositeId effect is outside the change's stated scope.

This is not the test encoding behavior the ticket means to change: the ticket's premise is the implicit-router skip, proven by the branch's own added test failing on base production (above). It is also not a measurement error: both heads were verified by ls-remote at claim time, the base is the true merge-base, and the failure is the exact assertion a reading of the head predicted before the run was filed.
