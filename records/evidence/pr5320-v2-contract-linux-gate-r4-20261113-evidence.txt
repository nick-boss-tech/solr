== Null semantics review (round 3 requirement, recorded from the production diff and the head tests)
The branch adds an AnyOfValidator and a strictNull mode to JsonSchemaValidator: a schema containing anyOf, and each anyOf alternative, validates null instead of auto-accepting it. Inside anyOf: an enum matches null only when the enum list literally contains null (explicit nullable case, covered by testAnyOfEnumNull); a {type: null} alternative accepts null (covered by testAnyOfRejectsSilentFailureAndNullId); nested items inherit strictNull, so a null element inside an array alternative is rejected (same test). Errors are isolated between alternatives: each alternative validates against a scratch error list and only a generic no-match error is reported. Outside anyOf the legacy behavior is preserved: validate() returns true for null when the schema has neither anyOf nor (under strict) a type or enum, and a plain {type: string} schema still accepts null (asserted at the end of testAnyOfRejectsSilentFailureAndNullId).
