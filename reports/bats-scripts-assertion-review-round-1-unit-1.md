## Findings and deciding controls

### U1-C1: attempted files accepted as indexed (confirmed-defect, P1)

`test_basic_auth.bats:68-74` creates `COLL_NAME` but posts to `monitors`. Line 74 accepts `1 files indexed.` alone. The producer above counts the attempted file even if the POST failed; a later commit error is also ignored by this assertion. Thus the test can accept an unsuccessful authenticated post. This is an assertion defect, not a claim that production authorization is bypassed. Optional follow-up control: preserve the existing target mismatch and capture the real response plus query state; then reject only document updates while allowing commits. Require the assertion to fail. This review ran neither control.

### U1-C2: successful empty commit accepted as successful log indexing (confirmed-defect, P1)

`test_basic_auth.bats:78` accepts `Committed`. PostLogsTool's catch prints `Batch sending failed:` and continues to `client.commit()`; the latter can succeed with no documents added. The output token therefore establishes commit acceptance only. Follow-up control: make the batch update fail while allowing commit; require indexed-document evidence to reject this case. No control ran.

### U1-C3: failed ZK read accepted as deletion (confirmed-defect, P2)

Affected: `test_basic_auth.bats:62-63`; `test_delete_collection.bats:46,55,64,73,81`. Both helpers assign `local ...=$(solr zk ls ...)` without preserving/checking its exit. Empty stdout after a failure reaches `return 1`, which `refute` accepts exactly like absence. A failure reading `/collections` can coexist with a successful subsequent `/configs` read, so the neighboring positive config checks do not repair the collection-deletion assertion. Follow-up control: after a successful create, leave the object present and make only the relevant listing fail. The negative assertion must fail rather than declare deletion. No control ran.

### U1-C4: assertion-result exit confused with tool-error exit (confirmed-defect, P2)

`test_assert.bats:43,57` use `run ! ... --exitcode`. They accept any nonzero exit, including the distinct exception exit 100 documented and returned by AssertTool, instead of requiring the single intended mode assertion failure. The earlier mode diagnostic does not constrain a separate later invocation. Follow-up control: cause a transport/tool exception only for the --exitcode call and compare its status with the intended mode-failure count. No control ran.

### U1-S1: empty failed response accepted as uncompressed (suspected-defect, P2)

`test_compression.bats:35-36` runs silent curl and only excludes `Content-Encoding:`; it has no HTTP-success/header prerequisite for that capture. Deciding control: start normally, then refuse only this request (or stop the endpoint immediately before it) and run this individual test. Capture curl exit/output and require it to fail instead of passing the absence check. The later gzip test is a separate test and cannot validate this capture. No runtime result is claimed.
