## Findings and deciding controls

### U2-C1: attempted-file counts plus no ERROR accepted as successful posting (confirmed-defect, P1)

Same producer defect as U1-C1. Affected summary/error-absence assertions: test_post lines 62-63,73-74,84-85,95-96,105-106,114-115,123-124,146-147,159/162,209/211; test_extraction 115-116. A rejected document POST can return false and emit only WARNING while the file count increments. If commit succeeds, both the count and ERROR-refutation pass. Four basic-post variants (62-96) lack a query read-back. The optimize and verbose cases also accept the summary; the latter's responseHeader fragment does not require success status. The later numFound checks in the no-type, directory, and extraction tests do protect those entire tests against an empty-index result, although the summary assertions themselves remain non-discriminating.

Follow-up control: reject the document add with a real handler/schema error while allowing commit/optimize, preserve raw response, and require each unguarded test to fail. Do not claim a suite false pass for tests whose later query rejects the mutation. No control ran.

### U2-C2: Committed does not prove a batch was indexed (confirmed-defect, P1)

Same producer defect as U1-C2, at test_postlogs line 47. The line 46 progress text precedes the attempted send. A successful empty commit after the swallowed send exception satisfies both. The line 50 query is a separate suspected weakness below. Follow-up control: fail only batch updates while allowing commit, then require a fresh positive document count. No control ran.

### U2-C3: error-free text is not a healthy report (confirmed-defect, P1)

test_healthcheck lines 36/39 merely exclude lowercase `error`. HealthcheckTool can emit `degraded`, DOWN replicas, or uppercase `ERROR: Collection healthcheck_test not found!` without that token; neither call's exit is asserted. The same zero-for-degraded behavior affects unit 3's health polling. Follow-up control: construct a responsive collection with one DOWN replica, capture status/degraded output and zero exit, and require the health assertion to reject it. Also distinguish a missing-collection error from success. No control ran.

### U2-C4: export artifact assertion reuses earlier output (confirmed-defect, P2)

test_export line 38 already establishes `BATS_TEST_TMPDIR/output.json`. Line 48 exports again to that exact path; line 49 only checks existence, with no removal/checkpoint or exit assertion. A second invocation that fails before touching the file satisfies line 49 using the first export's artifact. Per-test temp isolation does not fix reuse within one test. Follow-up control: after the first export succeeds, fail only the second export before sink creation and show the existing file is unchanged. No control ran.

### U2-C5: negative-only output checks accept unrelated failures (confirmed-defect, P2)

test_export line 67 accepts the absence of `Export complete` as the non-cloud rejection, while any earlier connection/argument error also lacks it. test_post line 180 accepts absence of a success JSON body as suppressed verbosity, but an unsuccessful post also lacks the body. ToolBase's generic exception path supplies concrete wrong-pass output in both cases; the expected reason/success status is not required. Follow-up controls: (a) inject a connection error before mode validation; (b) fail only the non-verbose args request and retain its ERROR output. Both checks must reject the unrelated outcome. No control ran.

### U2-S1: a failed query can masquerade as nonzero documents (suspected-defect, P2)

test_postlogs line 50 excludes only the literal `"numFound":0`. An HTTP error/non-JSON body may also lack it. Deciding control: after the postlogs invocation, return an actual error for this select request only; preserve HTTP status, body, and curl exit, and check whether the test passes without a positive numFound value. This review does not claim a captured false pass. No control ran.
