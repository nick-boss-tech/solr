## Findings and deciding controls

### U3-C1: connection refusal accepted as certificate rejection (confirmed-defect, P1)

test_ssl lines 117,353,366,496 each accept `Server refused connection` alongside a certificate-specific diagnostic. HttpJettySolrClient produces that text for ConnectException before any TLS handshake is required. Thus an unreachable/stopped endpoint can satisfy checks claiming peer-name rejection, required client certificate rejection, client-hostname rejection, or missing-trust rejection. ClosedChannelException is also broad, but the ConnectException producer alone establishes the defect without inferring how every Jetty/JDK TLS failure is wrapped.

Follow-up control: for each assertion, establish the positive control as today, then refuse only the targeted request/port and capture the non-TLS connection diagnostic. The intended test must reject that diagnostic. No control ran, and no production TLS vulnerability is alleged.

### U3-C2: generic ERROR accepted as credential rejection (confirmed-defect, P2)

test_stream lines 113/115 require nonzero plus ERROR for the no-credentials case. A missing .expr file is opened before any authenticated connection and produces the same generic ERROR via ToolBase. The assertion would accept that unrelated error without testing credentials. Follow-up control: remove/deny access to only this generated expression file before the invocation and require an authentication-specific check to reject the resulting file error. No control ran.

### U3-C3: degraded collection satisfies healthy polling (confirmed-defect, P1)

test_rolling_upgrade lines 118/163 call wait_for on healthcheck's exit. That command returns zero after printing a degraded report, so wait_for finishes on an unhealthy state. The final live-node count only establishes three nodes, not healthy replicas. This is the same producer issue as U2-C3. Follow-up control: preserve three live nodes with a DOWN/non-ACTIVE replica, or an equivalent isolated degraded report, and require the polling condition to wait/fail instead of succeeding. No control ran.

### U3-S1: bare nonzero TLS checks lack a failure discriminator (suspected-defect, P2)

test_ssl lines 66,557,558,560,561,568,581,583 accept any nonzero exit. Positive checks before/after reduce ambiguity but do not bind the individual failed request to the intended certificate/trust transition. Deciding control: arrange an unrelated per-call transport/tool failure after the positive precondition, record exact exit/cause and whether the rest of the test completes. If the whole test rejects it elsewhere, record that as a non-reproduction rather than claiming a suite false pass. No control ran.

### U3-S2: a failed stop can satisfy no-force-kill (suspected-defect, P2)

test_start_solr line 40 only excludes `forcefully killing` from a run that captures stop. Deciding control: leave the two pre-asserted processes alive, fail this stop invocation before it reaches shutdown, and capture its output/exit plus live endpoint state. Check whether the test still accepts the absence token. The final teardown's later cleanup cannot prove the tested stop invocation succeeded. No control ran.
