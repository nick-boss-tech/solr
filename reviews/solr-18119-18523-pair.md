## SOLR-18119 (`3fa8af32707`)

The base crawl does check anchors: `dev-tools/scripts/checkJavadocLinks.py:252-257` (base `9becf6c6a15`) looks each anchor up in the target page's anchor set and prints `BROKEN ANCHOR` on a miss. ## SOLR-18523 (`c0a3972d667`)

### Must fix

1. **The changelog and the PR title overstate compile-time coverage.** The changelog title (`changelog/unreleased/SOLR-18523.yml:1`) says "Javadoc link validation now happens at compile time via DocLint". The PR title says "javadoc links are validated by DocLint at compile time". Compile-time DocLint runs `-Xdoclint:all/protected` on compiled sources (`gradle/java/javac.gradle:58-60`). The description's own negative control shows that overview references are not checked at compile time: they are checked only by the javadoc tool in CI (`gradle/documentation/render-javadoc.gradle:422`). Narrow both titles to public and protected elements in compiled sources.

2. **The cited evidence file still states the root-check error.** The "Lucene follow-ups" bullet cites `reviews/solr-18523-doclint.md` on branch `assignment-18523-doclint`. That is a branch name, not the head SHA, which the presentation rule requires. The file is this branch's earlier review, and its line 58 says "a local `check` no longer runs `documentation`". The description now corrects that: `checkSiteLinks` still builds the site when the ref guide is included. Line 84 of the same file expects a root `check --dry-run` to omit `documentation`, which the same edge contradicts. Either drop the citation or correct that file first.

3. **The trade list omits anchor validation.** "A choice to check" lists docroot-only page coverage as the coverage that is retired. The crawl also validated fragment anchors on every page it scanned (`dev-tools/scripts/checkJavadocLinks.py:252-257`, base). Add anchor coverage to the list, so that both descriptions agree on what the crawl checked. See SOLR-18119 finding 2.

### Should fix

4. **The overview gate depends on the render task re-running.** `RenderJavadocTask` takes its sources from `sourceSets.main.java` as `@InputFiles` (`gradle/documentation/render-javadoc.gradle:55`, `:227`). `overview.html` is passed as `-overview` (`:322`) but is not an input. The description's control confirms that an overview-only change does not re-run the task unless it is forced. In a fresh CI checkout the gate works: the local build cache is off on CI and the remote cache is disabled (`gradle/develocity.gradle:58-66`). A reused workspace can report the task UP-TO-DATE, and then an overview-only change passes the gate. Either declare `overview.html` as an input of the render task, or state the condition in the description and in the comment at `gradle/documentation/documentation.gradle:74-80`.

5. **The root-check claim omits its condition.** "A root `check` still reaches the documentation build through the ref guide: `check.dependsOn 'checkSiteLinks'`" holds only when `refguide.include` is true. That defaults to whether `.git` exists (`solr/solr-ref-guide/build.gradle:54-58`). A source tree without `.git` does not reach it. State the condition in the description and in the comment.

6. **Citations are not all head-SHA links.**
   - Unlinked file citations: `gradle/documentation/documentation.gradle` (in "What this change does"), `build.gradle` (the removed apply line), `changelog/unreleased/SOLR-18523.yml` (in the Changelog line, with no line anchor), and `SYSTEM_REQUIREMENTS.html`.
